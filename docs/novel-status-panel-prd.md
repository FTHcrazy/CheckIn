# 主角属性面板（Character Status Panel）PRD

> 版本 v0.1 · 2026-09-24 · 所属模块：WorkerWindow / NovelPage
> 原型：`designs/novel-status-panel/Character Status Panel.html`

---

## 1. 背景与问题

系统流 / 游戏流小说的作者需要在正文里**高频维护**主角的数值设定——属性（力量/敏捷/HP）、装备（武器/防具/饰品）、技能熟练度（剑术 Lv.7 / 火球术 320/500）等。当前产品的应对方式只有两条路：

1. **要素卡 fields 键值**：`NovelEntity.fields` 是 `Record<string, string>` 的扁平键值，写装备、熟练度这类"带结构、带引用"的信息会迅速退化成一堆 `装备_武器`、`剑术_熟练度` 的碎键，无法表达"装备槽 → 某件 item 要素"的引用关系；
2. **正文里自己记**：数值散落在章节正文里，写到后面自己都对不上。

同时，编辑器右侧 SupportPanel 需要手动展开、宽度侵占码字区，属性更新是"写作间隙顺手改一下"的高频轻操作，不适合固定在左右两栏。

**目标**：给作者一个**随叫随到、用完即走、完全自定义**的主角属性面板——编辑区悬浮按钮唤起、贴身无遮罩浮层承载（不阻挡正文）、分组与条目由模板驱动可自由增删改（不限"系统流"一种形态），未使用属性点等可分配资源有明确落点，装备/技能支持「永久 / 激活时」属性加成并实时汇总主角总属性，且与既有要素体系（character / item / level_system）打通。

## 2. 用户故事

- 作为系统流作者，我希望在码字间隙一键打开主角面板，**30 秒内**把"力量 74 → 87"改掉，以便继续写作不打断心流。
- 作为作者，我希望给主角"穿戴"一把已建卡的武器（item 要素），以便装备与要素卡、全书检索互通，改武器名时装备栏同步。
- 作为作者，我希望技能熟练度能绑定已有等级体系（如「武学品阶」），以便数值与世界观设定一致。
- 作为系统流作者，主角每次升级获得 5 点未分配属性，我希望面板里有地方维护这些"还没用掉的点数"，写作时随时对得上账。
- 作为无限流作者，我的主角面板没有"装备"概念，只有积分、技能卡、队伍关系——分组和条目我要能**完全自定义**，而不是被"属性/装备/技能"三个固定页签框死。
- 作为游戏数据流作者，我希望把「装备时 +12 力量」「学会即永久 +4 敏捷」这类加成直接挂在装备 / 技能条目上，以便主角总属性不用自己口算，写战斗戏不改错数。
- 作为作者，我希望面板有一栏**状态汇总**，实时展示主角在当前装备、激活技能下的总属性及来源明细，以便正文直接引用、随时对得上账。
- 作为作者，我希望修改即自动保存、无需点保存按钮，以便不怕丢数据。
- 作为作者，我手滑把力量从 74 改成 47 且已自动保存后，我希望在行内看到「上次 74」并能一键回退，以便改错不心疼。

## 3. 非目标（Non-goals）

| 不做 | 理由 |
|---|---|
| 从正文自动解析属性变化 | NLP 识别准确率不可控，误改比不改更糟；M1 只做手动维护 |
| 数值公式引擎（战力计算、百分比乘区、套装效果） | 与"写作辅助"定位冲突；R5 的加成汇总只做同源加减累加，不引入乘除与条件组合 |
| 属性历史版本 / 章节维度属性快照对比 | 有价值但非高频痛点，放 Later（可仿 novel_snapshots 思路） |
| 多角色批量管理 / 队伍面板 | M1 聚焦"主角"场景，面板支持切换角色即够用 |
| 属性数据导出 | 可复用既有导出链路，M1 不单做 |

## 4. 功能范围

### R1 悬浮入口（FAB）

- 编辑区（`nv-page__stage`）内**右下角悬浮圆形按钮**，浮于正文之上，不固定在左右侧栏、不占布局流；坐标避开底部 StatusBar（bottom 预留 48px）。
- 图标使用「面板/属性」语义图标，hover 显示 tooltip「主角属性面板」。
- 点击在按钮上方弹出**贴身浮层面板**（无遮罩，见 R2）；再点 FAB、Esc 或点击面板外任意处关闭。
- 位置记忆：拖拽换位后写入 config（key `novel_status_fab`），下次打开恢复；M1 可先固定右下角，拖拽作为增强项。
- 专注模式（F11）下随 StatusBar 一同隐藏。

### R2 属性面板浮层（贴身无遮罩，不阻挡正文）

- **不做居中大弹窗、不做遮罩**：属性更新是"写作间隙顺手改"的高频操作，遮罩 + 居中弹窗会打断码字心流。面板以 **376px 宽的紧凑浮层**锚定在 FAB 上方弹出（右对齐、带指向箭头），正文全程可见、可继续编辑——作者可以边对照正文数值边改。
- **头部**：角色头像 + 名称 + 当前境界 chip（读取既有「当前境界」绑定，只读展示，跳转要素卡可改）+ 自动保存状态 + 关闭按钮。
- **模板驱动、完全自定义（去"系统味"）**：面板不预置「属性 / 装备 / 技能」固定页签，改为**自定义分组**承载一切：
  - **分组自由**：分组名、顺序、数量全部由作者定义（系统流是「状态 / 装备·法宝 / 功法技艺」，修仙流是「境界 / 法宝 / 灵物」，无限流是「积分 / 技能卡 / 队伍」……）；分段控件横向滚动展示，尾部「管理」按钮进入分组/条目管理。
  - **条目类型只有三种**，覆盖一切设定形态：**数值**（当前值/上限，上限非空时展示进度条——属性、熟练度、积分、寿命全是它）、**文本**（自由描述——储物空间清单、外貌特征）、**标签**（自定义选项集——武器品质 普通/稀有/史诗，选项由作者定义，不内置"系统流"品质色）。
  - **未使用属性点等可分配资源**：本质就是一个数值条目（无上限），模板预设默认带上（名称「未分配属性点」+「可分配」徽标），步进器加减即可维护；来源规则写备注（如"每级 +5"）。同类的技能点、抽奖券、气运值都是自建条目。
  - **预设模板兜底**：新建面板时提供开箱骨架（系统流 / 修仙流 / 西幻流 / 空白白板），仅作初始示例，分组与条目全部可增删改——既避免空面板无从下手，也不把任何流派的结构强加给作者。
  - **关联要素**：任意条目可绑定一个 item 要素（装备、法宝、丹药……），绑定后显示要素名 chip、点击跳要素卡；item 被删自动降级为文本。
  - **条目激活态**：装备 / 技能类条目自带**激活开关**（装备=手持/穿戴中，技能=运功/激活中）——既是给作者的状态备忘，也是「激活时」加成是否生效的判据（见 R5）。
- **自动保存**：任何修改防抖 800ms 落库，复用 `SaveState` 状态机在头部展示「保存中… / 已保存」；关闭浮层前 flush 待写数据。
- **关闭时机**：点击面板外任意区域即收起（无遮罩浮层的标准交互）；收起不丢数据（已自动保存）。

### R3 数据与联动

- 属性表按 **作品 + 角色（character 要素）** 一对一存储；角色要素卡删除时主进程级联清理对应属性表。
- 条目绑定的 item 要素被删除时，条目自动降级为纯文本（保留要素名），并 toast 提示。
- 数值条目可选绑定已有等级体系的等级项（如技能品阶），复用 R25 的 level 数据，不新建体系；境界绑定复用既有 `novel_links`（`toType='level'`、relation「当前境界」）链路，面板只读展示 + 快捷跳转，不在面板内改绑定（避免两处写同一关系）。

### R4 上一次保存值与一键回退

- **动机**：自动保存太快（防抖 800ms），作者改错数值后编辑器 Ctrl+Z 无从感知；面板必须自带回退点。
- **口径**：每行数值字段（属性「当前值」、技能「熟练度当前值」）记录 `prevValue`，即**上一次落库时的值**——不是打开面板时的快照，所以连续多次修改并保存后，回退点始终是最近一次保存前的值。
- **计算时机**：渲染层在每次整包落库前计算——数值发生变化的行 `prevValue = 变更前的当前值`，未变化的行清空 `prevValue`；主进程只存取不感知。
- **UI**：有回退点的行，在数值旁展示弱色 chip「↩ 上次 74」；点击一键回退。**回退本身也是一次修改**：当前值与 `prevValue` 互换后照常走自动保存，因此作者可以在两个值之间来回切换，不会丢任何一侧。
- **范围**：M1 仅覆盖数值字段；备注、装备描述等文本字段不做（文本改错重打成本低）。
- **兼容**：`prevValue` 为可选字段，旧数据缺省即无回退点，无需迁移。

### R5 属性加成与状态汇总（游戏数据流核心）

- **加成挂在条目上**：任意条目（装备、法宝、功法、技能……）可附加若干条「属性加成」，每条加成 = { 目标数值条目, 数值, 模式 }；目标必须是**同一面板内的数值条目**——面板本身就是属性登记处，不引入外部属性注册表。数值支持负值（诅咒装备、走火入魔）。
- **两种加成模式**：
  - **永久**：获得即生效、始终计入汇总（「学会《疾风步》永久 +4 敏捷」）；
  - **激活时**：仅当条目处于激活态（装备中 / 运功中）才计入（「赤霄剑装备时 +12 力量，卸下失效」）；未激活条目的激活加成在汇总中灰显标「未生效」。
- **状态汇总栏**：浮层头部下方常驻一条**可折叠汇总栏**（派生值，实时计算，不落库）：
  - **收起态**：chip 平铺展示所有被加成指向的属性总值，如「力量 99 (+12) · 敏捷 72 (+10) · 灵力 340 (+20)」；窄面板下 chip 横向滚动。未被任何加成指向的属性不出现（不刷屏）。
  - **展开态**：逐属性展示「基础 87 → 总 99」与**来源明细**（如「+12 赤霄剑 · 激活时」「+3 火球术 · 激活时 · 未生效」），未生效来源灰显——作者一眼看清每个数从哪来。
  - **口径**：`总值 = 基础当前值 + Σ永久加成 + Σ激活中条目的激活加成`；多条同目标直接累加，无乘区、无套装逻辑（Non-goal）。
- **派生不落库**：汇总永远是 content JSON 的投影，由纯函数 `computeTotals()` 计算——单一数据源，杜绝「汇总与明细两处真值」；基础值步进、激活开关、加成增删任一变化都即时重算。
- **联动**：加成目标条目被删除时，指向它的加成自动移除并 toast 提示；属性改名汇总即时跟随（加成按条目 id 引用，展示时取名称）。

## 5. 数据模型

新增单表（对齐 `novel_*` 建表风格，M1 一次到位）：

```sql
CREATE TABLE IF NOT EXISTS novel_status_sheets (
  id TEXT PRIMARY KEY,
  work_id TEXT NOT NULL,
  entity_id TEXT NOT NULL,              -- 绑定的 character 要素
  content TEXT NOT NULL DEFAULT '{}',   -- JSON：{ groups: [...] } 模板驱动的自定义面板
  updated_at INTEGER NOT NULL,
  UNIQUE (work_id, entity_id)
);
CREATE INDEX IF NOT EXISTS idx_novel_status_work
  ON novel_status_sheets(work_id, entity_id);
```

`content` JSON 结构（渲染层 types 定义，主进程只存取不解析）：

```ts
interface StatusSheetContent {
  /** 自定义分组（顺序即导航顺序）；预设模板只是初始骨架 */
  groups: StatusGroup[];
}

interface StatusGroup {
  id: string;
  name: string;              // 如「状态」「装备·法宝」「功法技艺」
  entries: StatusEntry[];
}

interface StatusEntry {
  id: string;
  name: string;              // 如「未分配属性点」「赤霄剑」「火球术」
  kind: "number" | "text" | "choice";
  value: string;             // number: 当前值；text: 内容；choice: 选中项
  max?: string | null;       // 仅 number：上限（空 = 无上限；上限非空展示进度条）
  options?: string[];        // 仅 choice：自定义选项集（如 普通/稀有/史诗）
  itemId?: string | null;    // 关联 item 要素（装备/法宝/丹药…），联动要素卡与检索
  /** R5 激活态：装备=手持/穿戴中，技能=运功/激活中；缺省视为未激活（可选字段向后兼容） */
  active?: boolean;
  /** R5 属性加成：指向同面板其他数值条目（可选字段向后兼容） */
  bonuses?: Array<{
    attrId: string;                 // 目标数值条目 id（展示时取其名称）
    amount: number;                 // 支持负值（诅咒装备 / 走火入魔）
    mode: "permanent" | "while_active";
  }>;
  /** R4 回退点：上一次落库的值（仅 number，可选字段向后兼容） */
  prevValue?: string | null;
  note: string;
}
```

**选型说明**：属性数据单角色体积小（<10KB）、整存整取，JSON 单列足够；拆三张明细表是为"频繁小改"做行级写优化，M1 用整读整写 + 防抖即可，后续量大再拆。

## 7. 指标

- **北极星**：周活跃系统流作品中使用属性面板的作品占比（目标首月 ≥ 40% 的"含 character≥3 且正文含『属性/等级』关键词"作品）。
- **驱动**：面板日均打开次数、单次平均停留时长（目标 <60s，验证"用完即走"）、自动保存失败率（<0.1%）。
- **健康**：打开面板后 5 分钟内继续码字的比例（不伤害写作心流）。

## 8. 风险与开放问题

1. **浮层遮挡正文右缘**：无遮罩贴身浮层固定 376px 宽，正文版心（约 620px）居中，正常窗口宽度下不压正文；窄窗口时浮层可能与正文重叠——属可接受的临时遮盖（随时可收起），不做宽度自适应。Later 可提供"贴边小窗"模式。
2. **点外关闭的误触**：作者可能点到正文导致浮层收起；因修改即自动保存，无数据丢失风险；若埋点发现高频误关，再评估"锁定浮层"开关。
3. **自定义度与上手成本的平衡**：完全自定义意味着空面板风险——用预设模板 + 空状态引导兜底；条目类型克制在三种，避免滑向"表单引擎"（Non-goal）。
4. **数值口径**：属性「当前值/上限」与技能「熟练度」结构相同（都是 number 条目），统一为单一行组件按 `max` 决定是否渲染进度条。
5. **多角色**：浮层头部角色切换器已预留，若后续需求旺盛，属性历史、角色间对比在 v0.2 评估。
6. **加成的口径纪律**：汇总只做同源加减累加，一旦作者提出百分比、套装、条件生效，就滑向公式引擎——守住 Non-goal，把需求记入 Later 评估。
7. **汇总与正文的口径漂移**：面板算出的总属性作者会直接抄进正文，数值 afterward 手改正文不会回写面板——汇总栏提供「复制」能力（Later）降低誊抄成本，M1 靠展示清晰即可。
