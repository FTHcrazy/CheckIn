# CheckIn 记账页面 · 产品需求文档（PRD）

> 版本：v0.1（草案） ｜ 状态：待评审 ｜ 负责人：产品 ｜ 日期：2026-09-22
> 范围：在主窗口（BaseWindow）新增一个「记账」页面，补全个人效率闭环中的财务视角。

---

## 0. 优先级总纲（来自需求方）

| 优先级 | 主题 | 含义 | 对功能设计的要求 |
|--------|------|------|------------------|
| **P1** | 操作简单 | 最低成本完成一笔记录 | 一键记账、智能默认、键盘流、常驻入口 → 多为 Must(P0) |
| **P2** | 数据明晰 | 看完知道钱去哪了 | 总览看板、分组流水、清晰汇总 → 多为 Should(P1) |
| **P3** | 多维化 | 深度洞察消费结构 | 账户/标签/预算/多维分析 → 多为 Could(P2) / Future |

本文档所有功能均按「用户三优先级 × MoSCoW」双维度标注，确保 P1 不被 P3 稀释。

---

## 1. 问题陈述（Problem Statement）

CheckIn 当前覆盖待办 / 备忘 / 日程 / 代码 / 资讯，但缺少个人财务视角的闭环。用户日常产生大量零散收支（餐饮、交通、订阅、工资），现状是：

- **专业记账 App 过重**：建账本、选模板、填一堆字段，与"随手记"的心智相悖；
- **备忘录随手记难汇总**：在 Memo 里记了但事后无法按分类/周期聚合，等于没记；
- **财务感知弱**：月底"钱去哪了"的焦虑普遍，缺乏轻量工具形成习惯。

**代价**：用户日活场景里缺失高频行为（记账是每天都可能发生的事），既削弱主窗口打开率，也与 CheckIn「个人效率闭环」定位不匹配。

---

## 2. 目标（Goals）

- **用户目标**：3 步内完成一笔记账（金额 → 分类 → 确认），首笔到保存 < 15s；月度收支一眼看清。
- **业务目标**：以高频日常行为提升主窗口日活与留存，补全个人效率闭环。
- **可衡量**（上线 30 天目标）：
  - 活跃用户记账渗透率 ≥ 40%（活跃用户中至少记过 1 笔的占比）；
  - 人均周记账 ≥ 3 笔；
  - 记账页周回访 ≥ 2 次；
  - 记账流程错误率 < 1%。

---

## 3. 非目标（Non-Goals）

- ❌ **多人在家庭共享账本**（v1 仅单人本地）。
- ❌ **云端同步 / 多端实时同步**（数据本地 SQLite，与现有一致；云同步另立项）。
- ❌ **投资理财 / 资产行情**（基金、股票估值等；仅记录"已发生"的收支）。
- ❌ **发票 OCR / 银行账单自动导入**（v1 手动 + 模板；OCR 为后续）。
- ❌ **多币种实时换算**（v1 单币种，币种字段预留以支持后续）。
- ❌ **借贷 / 复杂复式记账**（v1 单式流水）。

---

## 4. 用户故事（User Stories）

按优先级排列（P1 在前）：

- **P1** 作为日常用户，我希望打开 App 就能一键记一笔，以便不打断手头事也把账记了。
- **P1** 作为赶时间的用户，我希望输入金额回车即保存，以便 3 秒内完成。
- **P1** 作为健忘用户，我希望常用分类自动置顶 + 默认上次分类，以便少点选。
- **P2** 作为月末用户，我希望看本月收支汇总和分类占比，以便知道钱去哪了。
- **P2** 作为复盘用户，我希望按日期分组的流水可搜索 / 筛选，以便核对某笔。
- **P3** 作为想控费的用户，我希望给分类设月度预算并超支提醒，以便克制开支。
- **P3** 作为多卡用户，我希望管理多个账户 / 钱包余额和转账，以便掌握总净资产。
- **P3** 作为分析型用户，我希望按分类 / 账户 / 标签 / 时间多维切换统计，以便深度洞察。

### 5.2 关键功能验收要点（P0）

**F-01 快速记账**
- Given 用户在记账页或快捷入口，When 输入金额并选分类后回车，Then 生成一笔记录（时间默认当前时刻），列表顶部即时出现；
- 金额支持两位小数；负数 / 0 / 空 拦截并提示；
- 类型默认"支出"，可一键切"收入"。

**F-06 分类体系**
- 预设类：餐饮 / 交通 / 购物 / 居住 / 娱乐 / 医疗 / 教育 / 工资 / 理财 / 其他，每类图标 + 主题色；
- 自定义类持久化（增 / 改 / 删），删除时其历史记录归并"其他"或提示重指派。

**F-07 账目时间线**
- 按记账日期倒序分组（今天 / 昨天 / 日期）；
- 行内点编辑弹小窗改分类 / 金额 / 备注；删除二次确认 + 5s 撤销；
- 空状态展示"记第一笔"引导与快捷入口。

**F-09 周期总览看板**
- 本月收入 / 支出 / 结余三数字（红涨绿跌遵循国内习惯：支出红、结余绿视主题而定，采用 --app-* 语义色）；
- 近 30 天日趋势折线；切换"本月 / 本季 / 本年"。

**F-10 分类占比**
- 环图按分类聚合当月支出，hover 显示金额 + 占比；超 7 类折叠为"其他"。

## 6. 信息架构与交互（IA）

**入口登记（与现有架构对齐）**
- `HomeSidebar` 的 `NAV_ITEMS` 新增 `{ path: "/ledger", label: "记账", icon: <AccountBookOutlined /> }`；
- `App.tsx` 新增 `const LedgerPage = lazy(() => import("./pages/LedgerPage/LedgerPage"))` 与 `<Route path="/ledger" element={<LedgerPage />} />`（沿用 lazy + Suspense）。
- lite 构建（`__CHECKIN_LITE__`）无需隐藏该入口。

**页面布局（沿用圆角浮动 + 四主题）**
- 顶部：周期切换（本月 / 本季 / 本年 / 自选）+ 本月结余大数字；
- 中部：总览卡（收入 / 支出 / 结余 + 日趋势）+ 分类占比；
- 下部：时间线流水（可筛选）；
- 常驻底部"＋ 记一笔"悬浮按钮，全局快捷键唤起轻量输入条（不离开当前页）。

**快捷记一笔**：轻量输入条（金额键盘优先），覆盖层形式，3 步闭环。

## 7. 数据模型（草案，落地参考）

复用现有 per-user SQLite（`userDb`），由 `electron/handlers/ledger-handlers.ts` + `db.ts` 负责建表与 SQL（SQL 不进渲染进程）：

- `ledger_transactions`(id, type['expense'|'income'|'transfer'], amount REAL, category_id, account_id, to_account_id, note, happened_at, created_at, tag_ids JSON)
- `ledger_categories`(id, name, icon, color, kind['expense'|'income'|'both'], is_preset, sort)
- `ledger_accounts`(id, name, type, initial_balance, color)
- `ledger_tags`(id, name, color)
- `ledger_budgets`(id, category_id, month, amount)

> 表结构为草案，实现时以 handlers/db 为准；建表采用迁移式（兼容旧库）。

## 8. 工程落地路径（与现有架构对齐）

1. **渲染页**：新建 `src/windows/BaseWindow/pages/LedgerPage/`，组件以文件夹形式、`index.scss` 就近，沿用 `Page` 容器与 `WindowHeader`；遵循"列表行 memo + 稳定回调""动画仅 transform/opacity"等规范。
2. **路由登记**：`App.tsx` 增加 lazy 路由；`HomeSidebar` 追加导航项（图标 `AccountBookOutlined`）。
3. **主进程**：新建 `electron/handlers/ledger-handlers.ts` 导出 `registerLedgerHandlers()`，在 `main.ts`（与 `registerTodoHandlers` 同位置）注册。
4. **数据层**：`db.ts` 在 `userDb` 建上述表（迁移式建表）。
5. **服务层**：`shared/services/ledger.ts` 封装语义化 API（`addTransaction` / `getSummary` / `listTransactions` / `setBudget` …），页面 hooks（`useLedgerData` / `useLedgerEditorState`）调用，不直接碰 `window.electronAPI.db`。
6. **主题 / 规范**：全部用 `var(--app-*)` 四主题；图表用轻量方案（避免 lottie，jsdom 禁）；加 vitest 单测，交付 test / typecheck / lint 三件套。
7. **数据迁移**：导入 / 导出复用 migration 体系（zip + manifest），在迁移页追加 ledger 范围。
8. **隐私合规**：财务数据本地存储、不联网（与 memo 一致），遵循个人信息保护法最小化原则。

## 9. 成功指标（Success Metrics）

- **领先指标**：记账渗透率 30 天 ≥ 40%；首笔完成时长 p50 < 15s；人均周记账 ≥ 3 笔；记账页周回访 ≥ 2 次；记账流程错误率 < 1%。
- **滞后指标**：主窗口 30 日留存（记账用户 vs 非记账，假设 +5pp）；财务相关 NPS 正向；导出成功率 ≥ 99%。
- **测量**：本地埋点（`ledger_add` / `ledger_view` / `ledger_export`），按用户本地聚合，不联网上报。
