| 项 | 内容 |

## 0. 原始需求复述

重做**全局设定中心独立窗口**的 UI 布局与交互逻辑，在不影响本书设定中心的前提下解决四个痛点：
分类多了找不到、引用关系看不见、编辑操作太绕、空态与引导弱。
改动范围严格限制在 `src/windows/GlobalSettingWindow/` 目录内，`src/shared/components/SettingCenter/`
的本体文件保持不动；不套 Modal 外壳；不新增 IPC 通道（除非单独评审）；直接改代码，本 PRD
以文字 + ASCII 线框图描述新布局。

---

## 1. 产品目标

**一句话**：让作者在全局设定中心里「秒找到分类、一眼看见影响面、就近改完」，同时不丢「跨书共享 · 改动即时同步」这条核心语义。

### 当前体验问题清单（四条痛点）

| # | 痛点 | 现在是什么样 | 用户因此卡在哪 |
|---|---|---|---|
| **P1** | **分类多了找不到** | 左栏固定 220px：一行「等级序列」标题 + 一句说明 + 分类行（色点 / 名称 / `N 级`），**没有搜索、没有筛选、没有排序切换**，行数多时靠 `.nv-sc__list` 内部滚动 | 分类上到 20+ 后只能凭记忆滚动定位；左栏底部输入框只管「新建」，不能用来找；找错了要在左右两栏之间来回切 |
| **P2** | **引用关系看不见** | 只有右栏 `CategoryCard` 头部一枚 `is-ref` 徽标「N 部书引用」（`formatReferenceCountLabel`，0 引用显示「暂无引用」）。**左栏完全没有引用信息**；只有点「删除」触发 `refCount > 0` 时，才会弹一次确认说「被 N 部书引用，删除后这些书会就地固化」 | 改动**之前**不知道影响面：「改这一条会同步到几本书」没有常驻可见性；「暂无引用」与「被 8 部书引用」在视觉上同权重，作者无法据此决定「改 / 另建一条」；也看不出被**哪几本**书引用 |
| **P3** | **编辑操作太绕** | 新建走左栏底部输入框；改名 / 改说明要点右栏卡片「编辑」进表单再「保存」；删除要点卡片「删除」+ `Popconfirm`；等级行操作全在行尾「⋯」里。左栏底部那行 tip 明确写着「重命名与删除在右侧卡片的『编辑 / 删除』按钮」（FR-05 只订正了文案，没改体验）。**无右键菜单、无批量选择、无键盘快捷键** | 改一个分类名要点 3 次（选中 → 编辑 → 保存）；批量维护等级只能靠「批量生成」弹窗按行 / 按模式灌，**没有勾选多条等级做删除 / 移动**；分类行本身没有上下文入口 |
| **P4** | **空态与引导弱** | 右栏 `Empty` + 一句「先新建一个设定分类」+ 一个「套用内置预设」按钮（`EMPTY_CTA_COPY.settingEmpty`）；左栏空时 `Empty`「还没有设定分类」。窗口级另有装载中的「正在打开全局设定中心…」与装载失败的 `Alert` + 重试 | 没说清「全局库是什么 / 跨书共享意味着什么 / 建完怎么被书引用」；预设入口是一个泛化按钮，看不出库里有 9 套内置预设可选；新手不知道下一步该干什么 |

## 2. 用户故事

1. **（分类多了找不到）** 作为维护了 30 个全局分类的作者，我想在左栏直接输入关键词过滤分类，以便 3 秒内定位到「法宝品阶」，而不是滚半天。
2. **（查看影响面）** 作为准备把「练气九层」改名的人，我想选中分类时立刻看到「被 5 部书引用 · 改名会同步到这 5 部」，以便判断是改这一条还是另建一条。
3. **（就地编辑）** 作为整理设定的人，我想双击分类名就地改名、回车即存，以便不用再走「选中 → 编辑 → 保存」三步。
4. **（批量维护等级）** 作为重排「丹药稀有度」阶梯的人，我想勾选多条等级一次性删除，以便不用一条条点「⋯ → 删除该等级」。
5. **（空库起步）** 作为第一次打开全局设定中心的新手，我想在空态看到「这是什么、建完谁能用、下一步做什么」，并能一键套用内置预设，以便 1 分钟内建出第一条等级序列。
6. **（键盘流）** 作为键盘党，我想 `Ctrl/⌘+F` 聚焦搜索、`↑/↓` 切换分类、`F2` 改名、`Delete` 删除，以便全程不摸鼠标。

## 3. 需求池

优先级：**P0 = 本次必须交付**；P1 = 应当交付（本次如排期紧张可延到下个小版本）；P2 = 锦上添花。

### P0（Must have）

| ID | 需求 | 验收标准（可测） |
|---|---|---|
| **R1** | **左栏搜索**（分类名 + 分类说明） | ① 输入「法」→ 左栏只显示名称或 `note` 含「法」的分类，行数 = 命中数；② 命中 0 时左栏显示空态「没找到「法」相关的分类」+「清空搜索」按钮；③ `Esc` 或点清空按钮 → 恢复全量且输入框置空；④ 搜索框带 `aria-label="搜索设定分类"` 与 `allowClear`；⑤ **搜索不触发任何 IPC、不改 `sortOrder`**（断言：搜索期间 `globalCategoryOrder` 调用次数为 0）；⑥ 过滤纯前端，输入到重渲染 ≤ 200ms |
| **R2** | **左栏筛选**（全部 / 境界体系 / 自定义 / 已被引用 / 暂无引用） | ① 切「境界体系」→ 只列 `kind === 'realm'`；切「已被引用」→ 只列 `refCount > 0`；切「暂无引用」→ 只列 `!(refCount > 0)`；② 与 R1 搜索**取交集**同时生效；③ 筛选状态仅存窗口私有 view 态，**不落库、不持久化**；④ 当前筛选下 0 命中时给出与搜索不同的空态文案 |
| **R3** | **左栏行显示引用徽标** | ① 每个分类行行尾显示引用徽标，`refCount > 0` 显示「N 部书引用」，`0` 显示弱化的「暂无引用」；② 文案由 `shared/novel/setting-reference.ts` 的 `formatReferenceCountLabel` **唯一**产出（不另拼字符串）；③ 左栏徽标与右栏 `is-ref` 徽标在同一分类上数值一致 |
| **R4** | **影响面条（右栏顶部常驻）** | ① 选中分类后，右栏顶部横幅常驻显示影响面：`N = 0` → 「暂无作品引用 · 改动只影响全局库」；`N > 0` → 「被 N 部书引用 · 改动会即时同步到这 N 部书」；② `N > 0` 时横幅底色 `var(--app-accent-blue-weak)`、文字 `var(--app-accent-blue)`；`N = 0` 时用 `var(--app-surface-alt)` + `var(--app-text-secondary)`；③ 横幅上删除入口与右键菜单删除**共用 `useGlobalSetting.onDeleteCategory` 同一个回调**（保证二次确认口径唯一）；④ 影响面条在分类切换 / 广播重载后数值同步刷新 |
| **R5** | **分类就地编辑**（双击改名） | ① 双击左栏分类名 → 名称就地变 antd `Input`（`size="small"`，原值全选）；② `Enter` 提交 → 调 `globalCategoryUpdate`（经 `onPatchCategory`）；`Esc` 取消还原；③ 空串 / 纯空白**不提交**（保持原值退出编辑）；④ 失焦且非空 → 提交；失焦且为空 → 取消；⑤ 提交后左栏与右栏同步（走既有「写后重载 + `global-setting-changed` 广播」，不做本地乐观更新） |
| **R6** | **分类右键菜单** | ① 右键分类行弹出 `Dropdown` 菜单：重命名 / 设为境界体系（或转为普通分类，按 `kind` 互斥显示）/ 删除；② 右键后自动选中该分类；③ 「删除」在 `refCount > 0` 时走既有二次确认文案（「删除后这些书会把它就地固化为各自的本书副本（保留内容、不再同步）」）；④ 菜单全部走既有 IPC，**不新增通道**；⑤ 菜单项在键盘可达（antd `Dropdown` 自带语义，不手写浮层） |
| **R7** | **空态引导重做** | ① 库为空时右栏显示引导卡：一句说明（「这里的设定可被任意作品引用 · 改动会同步到仍引用它的书」）+ 两个动作：「套用内置预设」→ 打开既有 `TemplateLibraryModal`；「新建空白分类」→ 聚焦左栏新建输入框；② 点「套用内置预设」后模板库弹窗可见，且能列出 `SETTING_PRESETS` 全部 9 套内置预设；③ 左栏空态同步为「还没有设定分类」+ 一句「用上面的搜索框找已有分类，或在下面新建」；④ **装载失败态不得退化成空态**（保留 `Alert` + 重试，断言：错误态下不出现「还没有设定分类」） |
| **R8** | **窄窗不塌**（minWidth 920） | ① `≥1080px`：左栏 240px；② `960–1079px`：左栏 200px，等级序列隐藏「别名」列；③ `≤959px`（含 minWidth 920）：左栏 160px，等级序列隐藏「别名」「说明」列（说明仍可从行「⋯ → 编辑名称 / 别名 / 说明」进入）；④ 三档下**均不出现横向滚动条**（断言 `scrollWidth <= clientWidth`）；⑤ 影响面条文案单行省略（`text-overflow: ellipsis`）+ `Tooltip` 挂全文 |

### 4.3 关键交互流程

| 流程 | 步骤与判定 |
|---|---|
| **搜索** | 输入 → 纯前端 `useMemo` 过滤（分类名 `includes` + 说明 `includes`，忽略大小写与首尾空白）→ 左栏即时刷新 + 顶部显示「N 条」。**不触发 IPC、不改 `sortOrder`**。`Esc` / `allowClear` → 复原。搜索期间若左栏为空，空态给「清空搜索」按钮而不是「还没有设定分类」 |
| **筛选** | 筛选器与搜索**取交集**；切到「已被引用 / 暂无引用」时命中计数同步变化；筛选态只存在窗口私有 view hook 里，窗口关闭即销（不持久化、不写库） |
| **就地编辑（R5）** | 双击分类名 → 行内 `Input`（原值全选）→ `Enter` 提交 / `Esc` 取消 / 失焦（非空提交、空则取消）→ 提交走 `onPatchCategory` → 写后重载（`global-setting-changed` 广播回灌）→ 左栏 + 右栏 + 影响面条同步 |
| **新建** | 入口二选一：左栏底部输入框（保留现有范式），或工具头「＋ 新建分类」（点击即聚焦左栏输入框）。`Enter` / 点「新建」提交 → `onCreateCategory`。**空串时「新建」按钮置 `disabled`**（沿用现状）。重名不拦（主进程允许，由作者判断） |
| **删除确认** | 分类：影响面条的「删除」与右键菜单「删除」**共用 `useGlobalSetting.onDeleteCategory`**（内部已实现：`globalCategoryDelete(id)` 先探引用，`refCount > 0` 才弹 antd 实例确认框，确认后 `globalCategoryDelete(id, true)` 固化删除）。**左栏就地删除也要走同一个回调**，不允许另写一套确认文案。等级：单行立即执行（与现状一致）；批量删除（P1）统一走一次二次确认 |
| **批量（P1 R10）** | 勾 `Checkbox` → 顶出「已选 N 项」工具条 →「删除所选」→ 确认 → 串行 `onDeleteLevel` → **全部结束后只 `reload()` 一次** |
| **键盘（P1 R9）** | 全局监听挂在窗口根；命中「焦点不在 `input` / `textarea` / `[contenteditable]` / 行内编辑态」才响应。`Ctrl/⌘+F` 聚焦搜索 → 此时 `↑/↓` 在**过滤结果内**移动选中（不是全量）→ `Enter` 选中并聚焦右栏；`F2` 进入改名；`Delete` 触发删除；`Esc` 先退编辑态、再清搜索 |
| **空态引导** | 空库 → 右栏引导卡（说明 + 「套用内置预设」/「新建空白分类」）。「套用内置预设」→ 打开既有 `TemplateLibraryModal`（`onApplyPreset` 已有真实实现）→ 选一套 → `onApplyPreset` 建分类 + 灌等级 → 重载后自动选中新建的分类 |
| **装载中 / 失败** | **保持现状**：`loading` → 「正在打开全局设定中心…」；`loadError` → `Alert` + 「重试」。新布局**不得覆盖**这两态（R7 ④ 断言） |
| **跨窗口刷新** | 沿用现状：订阅 `global-setting-changed` → 写后重载。新布局只增订阅者（影响面条数值同步刷新），不新增广播 |
