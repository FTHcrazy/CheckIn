# 小白作家首次使用体验评审（Novel 窗口）

- **评审日期**：2026-10-09
- **评审角色**：**「小白作家」小林** —— 22 岁，第一次写网文，之前只在手机备忘录和 Word 里写过几千字随笔。不懂技术，不知道"要素""行囊""伏笔"这些词，也没耐心看说明书。
- **评审对象**：CheckIn 小说窗口（NovelWindow）**当前真实实现**，非 PRD 承诺。依据为 `docs/` 三份文档 + `CHANGELOG.md` + `src/windows/NovelWindow/**` 实际代码。
- **方法**：**启发式走查（heuristic walkthrough）**，按「下载 → 首次打开 → 写下第一个字 → 想建个人物 → 想调设置 → 想回头改」的真实路径逐屏走一遍，每条不满都标注**代码 / 文案证据**与**小白原话**。
- **诚实声明**：本报告是**基于代码与文档的角色化走查**，不是真实用户测试结果。所有"不满"都是从**已实现的界面文案、交互入口、默认状态**推演出来的，未编造任何用户访谈数据。文末 §6 列出本次**未能验证**的项。

> **一句话结论**：这个软件的**内核（码字、防丢稿、性能）已经很像专业工具**，但它把「专业」理解成了「功能多、术语准」，而小白要的是「第一眼就知道点哪、不害怕、不丢字」。当前**首次使用的前 15 分钟体验是断的**——没有引导、术语成墙、默认给了一本陌生人的 6 万字小说。

## 2. 不满清单（按主题分组，★ = 严重度）

### 2.1 冷启动：把「模板书」当成用户数据递到面前 ★★★★★

- **现象**：全新用户第一次打开，书架里已经躺着一本**6 万字的陌生人小说**《山海拾遗（模板示例）》，含完整要素库、伏笔、等级体系、甚至一整套填满的「行囊」（`docs/novel-editor-prd.md` §6.5.1 与 `electron/novel-template.ts`）。统计条把它的字数算进「累计字数」，Hero 卡「继续写作」把它当"上次在写的书"。
- **小白原话**：「**我第一件事是找哪里能删掉它。**」
- **为什么是问题**：模板书是为了压测与演示而生的（PRD 明说 6 万字用于压测虚拟滚动），但**它对用户是噪音，不是帮助**。它污染了"我的书架"这个心智模型 —— 书架应该是"我的东西"，第一次打开却有一个不属于我的东西，还占着"继续写作"的最佳位置。用户必须先做一次**清理动作**才能开始创作，这是负体验。
- **建议**：
  1. 首次使用改为**空书架 + 一句欢迎语 + 一个大的「写下第一本书」**；（删除 / 重置模板的动作留给开发调试）
  2. 若一定要留样例，做成**书架底部一张可关闭的"示例作品"提示卡**（点开才载入，不写进统计、不进"继续写作"）；
  3. 「重置为模板书籍（**调试**）」这个入口现在**对普通用户可见**（作品管理菜单 `WorkManageMenu/index.tsx:130`）—— 把"调试"两个字递给小白，只会让她更不敢碰。

### 2.2 顶栏：6 个图标，0 个看得懂的文字 ★★★★☆

- **现象**：顶栏右侧依次是 章节栏 / 支撑面板 / 打字机 / **行囊** / 历史快照 / 设置（`NovelTopBar/index.tsx:160-217`），**全部是纯图标 + Tooltip**。其中「行囊」用的是**购物袋图标**（`ShoppingOutlined`）。
- **小白原话**：「购物袋？我以为能买东西。点开一看是天书。」
- **为什么是问题**：小白不会去 hover 每个图标试。**图标语义要么是行业通用（齿轮=设置、返回箭头=返回），要么必须配文字**。「行囊」「打字机」属于产品自造概念，用图标表达 100% 会失效。Tooltip 是补救，不是入口。
- **建议**：核心入口改「图标 + 文字」胶囊（书架 / 大纲 / 人物 / 灵感 / 设置）；「行囊」这种自造词至少换成**「主角面板」**这类自解释的说法。

### 2.3 术语墙：整个界面在说一门用户不会的语言 ★★★★★

- **现象**：界面上高频出现**要素、行囊、伏笔、境界、载体、被动 / 持续 / 释放、加成词条、盘点记录、码字、目标、连续码字**。
- **证据**：右栏 Tab 名 `要素`（`SupportPanel/index.tsx:108`）；行囊空态文案「属性是汇总的**骨架** —— 先加…再让装备和技能**往上挂加成**」（`AttributesModule/index.tsx:93`）、「点「+ 被动」写**常驻加成**，点「+ 释放」写主动技能**参数**」（`ModifierList/index.tsx:196`）。
- **小白原话**：「"要素"到底是啥？人物？设定？我觉得就是"资料"。」
- **为什么是问题**：小白需要的是**用她的词**（人物、地点、大纲、灵感），而不是系统建模的词。术语墙会让用户直接判定"这软件不是给我这种人的"，然后放弃。**这不是文案小事，是用户分层问题**。
- **建议**：见 §4 术语翻译表，界面层全面换成用户语言；专业术语（被动/持续/释放）只在**行囊这一层**保留，并在首次进入时给一句话解释。

### 2.4 建人物卡的核心动作，是一个小白不可能发现的隐藏交互 ★★★★★

- **现象**：这个软件最得意的能力是「正文人名 ↔ 资料卡联动」。但**建卡的正路是：在正文里选中一个人名 → 右键 → 「标记为角色」**（PRD R20 ③，`EntityContextMenu`）。而这条提示**只在右栏切到「要素」Tab 时，出现在面板最底一行小字**里（`SupportPanel/index.tsx:348-354`）。右栏默认收起。
- **小白原话**：「右键？我写作从来不用右键。而且我根本没看到有这行提示。」
- **为什么是问题**：**核心能力的入口藏在"默认不可见 + 非常规手势"后面**，等于没有。小白建第一个角色卡这一步就走不通，整套"设定库随写作生长"的价值归零。
- **建议**：① 第一次进入编辑器时，用一个**一次性气泡**指引"选中人名 → 点这里建卡"；② 右栏「资料」Tab 顶部给**显眼的「＋新建人物」按钮**，不依赖右键；③ 选中文字后浮出一个**工具条**（比右键菜单更容易被发现）。

### 2.5 「行囊」——一个对小白完全无意义、却最容易误入的巨型功能 ★★★★☆

- **现象**：顶栏点开即是一个**9 模块的专业面板**：总属性汇总 / 人物属性 / 装备栏 / 物品栏 / 技能栏 / 境界 / 货币 / 状态 / 备注，外加模块管理、量纲设置、部位设置、盘点记录、来源明细（`CharacterPack/index.tsx` 全量）。
- **小白原话**：「这是在玩 RPG 吗？我就想写个都市言情。」
- **为什么是问题**：行囊的 PRD（`character-pack-prd.md`）明确面向**系统流 / 网游流 / 无敌流 / 种田流**作者 —— 这是**细分品类**，不是小白。但它以**一级入口**的形态对**所有用户**开放，且默认播种了一个"主角"骨架，点进去就是一堆空模块（`pack-handlers.ts:660` 首次建行囊角色）。**小白误入后只会得到"这软件好复杂"的结论。**
- **建议**：① 行囊**默认不在顶栏**，改为「资料」页里一个"主角数值面板（进阶）"入口，或按作品开关；② 首次打开行囊给一页**极简说明**（"这是给系统流 / 网游流作者记主角数值用的，用不上可以关掉"）；③ 空白模块默认**折叠**，只显示一句人话说明。

### 2.6 没有「导入」——老稿搬不进来 ★★★★★

- **现象**：PRD §1 把「导入导出」列为**主流编辑器标配能力**（"缺一个就不专业"），但实际只落地了**导出 TXT**（整本 / 当前卷 / 当前章），**没有任何导入通道**（`preload.ts` 的 novel 通道清单里无 import；`docs/novel-editor-prd.md` §6.5.3 未实现清单里也没有这一条 —— 属于**需求缺口**，连补录都没有）。
- **小白原话**：「我在 Word 里写了 8 章啊，难道要我一段段复制？」
- **为什么是问题**：**迁移成本 = 用户流失点**。任何想从别处搬过来的用户（这是绝大多数人的第一步），都会在这里卡住。而且冲突处理、编码识别这些"难的部分"越晚做越难。
- **建议**：MVP 至少支持 **TXT / Markdown 导入 → 按"第X章"标题自动切章**；给一个"导入为草稿"的安全语义（不覆盖现有作品）。

### 2.7 「保存」找不到，小白会一直焦虑 ★★★☆☆

- **现象**：编辑器**没有可见的"保存"按钮**，全靠 800ms 防抖自动保存；顶栏只有一个小状态点 + 文字，初始态是**「待输入」**（`novel-config.ts:233`）。
- **小白原话**：「我就写了两句，它写"待输入"……是我没保存吗？Ctrl+S 是保存吗？我按了没反应。」
- **为什么是问题**：**"待输入"这个初始态会让小白误以为需要手动保存**。虽然自动保存是更高级的体验，但小白**不知道**，于是反复焦虑、反复找保存按钮。失败态文案「保存失败，待重试」虽然比旧版诚实，但直接暴露技术语义，小白只会更慌。
- **建议**：① 初始态改成更安心的空/「✓ 已自动保存」；② 首次保存成功后弹**一次性轻提示**「已自动保存，不用点保存」（不弹模态）；③ 失败态改成「**刚才那次没存上，正在重试**」这种安抚式文案。

### 2.8 「工具」里一半是不能用的功能 ★★★☆☆

- **现象**：右栏「工具」Tab 是二级面板：起名器可用，但**人物关系网络（R27）、架空地图（R28）是灰色"规划中"占位卡**（`ToolLauncher/index.tsx:50-60`），面板头写着「1 项可用 · 2 项规划中」。
- **小白原话**：「看到"规划中"我就知道这软件还没做完。」
- **为什么是问题**：把 roadmap 暴露给终端用户 = 主动告诉用户"你没花钱买到全部"。小白会据此降低对产品的信任。
- **建议**：未上线功能**直接不上线**（从清单里摘掉），或做成「敬请期待」但**不占主位**（例如只在更新日志里提）。

### 2.9 灵感速记有两个入口，小白不知道该在哪记 ★★★☆☆

- **现象**：书架右栏有**全局灵感库**（含未归属灵感 `workId=''`），编辑器右栏也有**灵感速记**（归属当前作品）（PRD R32 ⑤）。
- **小白原话**：「我在书架记的灵感，怎么进编辑器找不到了？」（因为归属规则不同）
- **为什么是问题**：**同一个东西两个家、规则还不一样**，用户心智模型会崩。这不是高级功能，是**概念泄漏**（把内部数据模型"未归属灵感"暴露成了用户概念）。
- **建议**：统一为"灵感 = 一条便签"，书架看全部、编辑器看当前书，同一份数据、同一套操作；不做"归属/未归属"这种用户不可见的区分。

## 3. 结构化归因：为什么会出现这些不满

把上面 20 条不满归到 4 个根因，方便决策：

| 根因 | 表现 | 涉及条目 |
|---|---|---|
| **R1 · 把"演示态"当"首启态"** | 模板书、行囊骨架、规划中占位 —— 都是开发为了验证能力而造的，却留给了真实用户 | 2.1 / 2.5 / 2.8 |
| **R2 · 用建模语言当界面语言** | 要素 / 载体 / 性质 / 未归属灵感 / 盘点 —— 系统名词直接上屏 | 2.3 / 2.9 / 2.10-b/h |
| **R3 · 核心能力藏在非常规交互后面** | 右键建卡、纯图标入口、快捷键无提示 | 2.2 / 2.4 / 2.10-d |
| **R4 · 缺少"第一次"的设计** | 无引导、无空态教学、保存心智没建立、迁移无路 | 2.6 / 2.7 / 2.10-c/e/f |

> 一句话：**这是一个"功能完成度很高、首次使用完成度很低"的产品。**

## 5. 优先级建议

### 第一批：**零成本快赢**（改文案 / 改默认值，1~2 天，收益最大）

1. **首启不播种模板书**，改空书架 + 欢迎语（2.1）—— 一条判据 + 一段文案
