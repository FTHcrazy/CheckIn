## 二、背景与目标

### 2.1 背景

小说窗口（NovelWindow）功能密度高：书架、卷章树、设定中心、标注层、右键菜单、五个支撑面板、独立行囊窗口。经源码级走查，零基础作者首次使用存在四个高摩擦点：

| # | 摩擦点 | 证据 |
|---|---|---|
| P-01 | **右键菜单有隐形前置条件**：选区为空时右键直接 return，弹的是系统原生菜单，作者以为「功能坏了」 | `EditorPane/index.tsx` L418-427 |
| P-02 | **设定中心不是「世界观/人物/大纲」的常识心智**：实际是「设定分类 × 等级序列」，境界体系只是 `kind='realm'` 的一条分类，新手找不到「人物设定在哪」 | `SettingCenter/index.tsx` L229-238 |
| P-03 | **新建即默认名**：卷默认「未命名卷」展示为「第一卷」、章默认「未命名」，且空名保存静默丢弃；新建作品空名点「创建并开写」也是静默无反应 | `useNovelData.ts` L520-573、`ChapterTreeItem` L88-99 |
| P-04 | **行囊十模块信息过载**：新书默认只开 3 块，其余七块收在「模块管理」里，新手不知道还有什么、也不知道「境界」依赖设定中心先建梯 | `pack-config.ts` L24-37、`RealmModule` L93-97 |

另有既知体验债：设定中心左栏提示「右键或「⋯」可重命名 / 删除分类」为过期文案（代码中无 `onContextMenu`），实际路径在卡片①的「编辑 / 删除」按钮——本方案一并修正。

### 2.2 目标

| 编号 | 目标 | 衡量口径 |
|---|---|---|
| G-01 | 零基础作者不看外部资料完成首次创作闭环（建书 → 建章 → 建设定 → 写正文 → 记状态） | 引导完成率（走完 Tour ≥4 步）≥ 60%（估算，上线 4 周复盘） |
| G-02 | 高摩擦操作（右键菜单、设定中心、行囊）的自助发现率提升 | `ctx_menu_open` / `setting_center_open` / `pack_open` 新用户触发率对比上线前 |
| G-03 | 引导打扰可控 | 每用户每会话 Tour 弹出 ≤ 1 次；弱提示同时在场 ≤ 1 个 |
| G-04 | 引导消失后功能仍可自助找到 | 帮助文档覆盖全部 Tour 讲过的动作，且可按关键词检索 |

### 2.3 非目标（本期不做）

- 不做交互式可点击的模拟教学（sandbox 演练模式）。
- 不改任何既有功能交互与数据表结构；引导状态仅新增 1 个 config 键。
- 不做多语言（帮助文档仅中文）。
- 不做行囊内建梯（延续 `pack-dashboard-prd.md` L-02 结论，维持跳转设定中心）。

## 三、名词与术语

| 术语 | 含义 |
|---|---|
| L1 强引导 | antd `<Tour>` 漫游式引导：遮罩 + 高亮目标 + 步骤卡片，逐步讲解 |
| L2 弱提示 | 不遮罩不拦截的轻提示：Tooltip 单次气泡、Badge 角标、空态引导卡（CTA） |

## 四、需求范围

**包含**：Tour 5 步编排与文案（第 1-4 步强制引导：无关闭叉、无 Esc，唯一出口是「下一步」；第 5 步可关闭）；弱提示点位表（Tooltip × 6、Badge × 1、空态卡 × 4）；帮助中心（入口、重看引导、文档结构）；引导状态机与存储；过期文案修正（设定中心左栏提示）；埋点。

**不包含**：模拟教学、多语言、数据表结构变更、行囊内建梯、任何既有交互改动。

## 五、方案对比与选型说明

| 维度 | 方案 A：全量 Tour（12+ 步一次讲完） | 方案 B：三层引导（5 步 Tour + 弱提示 + 帮助中心）【推荐】 | 方案 C：纯文档（只写帮助页） |
|---|---|---|---|
| 思路 | 一次把全部功能走完 | Tour 只讲首次闭环 5 步，长尾交给弱提示与帮助中心 | 不做产品内引导 |
| 实现成本 | 低 | 中 | 极低 |
| 用户体验 | 差：步骤多、记忆负担重，跳过率高 | 好：核心路径强引导，长尾按需触达 | 差：P-01 类「隐形前置条件」靠文档救不回来 |
| 风险 | 高（步骤多导致整体放弃） | 低-中（默认态变化需埋点验证） | 高（G-01 无法达成） |
| 达成 G-01~G-04 | 仅 G-01 一半 | 全达 | 均不达 |

**推荐方案 B**。理由：① 首次创作闭环是唯一必须强引导的路径，其余功能在「用到时给提示」体验最优；② 复用 antd 现成组件（Tour / Tooltip / Badge），无新依赖；③ 帮助中心承接「引导是一次性的，帮助是长期的」。

## 六、用户角色与使用场景

### 6.1 角色

- **零基础作者（主力）**：第一次用本应用写小说，对「设定中心 / 行囊 / 标注层」零认知。特征：怕点错、见弹窗就想关、遇到没反应的按钮会认为坏了。
- **回流作者**：用过旧版本，跳过引导，但需要帮助文档查快捷键与新功能。
- 画像说明：基于功能形态构建的角色假设，待用户确认。

### 6.2 场景

**主流程（首次创作）**：安装后打开小说窗口 → Tour 第 1 步高亮「新建作品」→ 建书 → 第 2 步建卷章 → 第 3 步进设定中心套预设 → 第 4 步开行囊，**强制引导到此结束** → 第 5 步讲正文右键建卡（普通可关闭步骤）。全程 Tour 驱动，无外部文档。（2026-10-14 按用户反馈两度调整：行囊提前到第 4 步；第 1-4 步强制——无关闭叉、不响应 Esc，只能点「下一步」；第 5 步保留叉与 Esc，看过前四步已具备基本认知，随时可撤。）

**分支流程（跳过者自助）**：作者走完或关掉第 5 步后 → 帮助入口 Badge 仍亮 → 某天点开帮助中心 → 看「快速上手五步」图文 → 顺链补齐。

**异常流程**：Tour 第 2 步目标（左栏「新章节」按钮）因书架还没作品而不可见 → 自动跳过该步不中断；作者正在打字 → 不触发任何引导。

## 七、引导体系设计（核心）

### 7.1 三层结构与优先级

```
L1 强引导（Tour，一次性）── 首次创作闭环 5 步（第 1-4 步强制：只能下一步）
L2 弱提示（Tooltip / Badge / 空态卡）── 长尾功能按需触达
L3 常驻入口（帮助中心 F1）── 长期兜底 + 重看引导
```

裁决序：**写作不被打断 > 强引导 > 弱提示**。同一时刻最多 1 个 L1 在场 + 1 个 L2 在场；空态引导卡属于界面本体，不受此限。L1 与关闭守卫（`CloseGuardModal`）互斥：守卫在场时 Tour 关闭或延迟，守卫结束后不再恢复（该次会话不再弹，避免连击弹窗）。

### 7.2 Tour 步骤编排（文案为最终稿，目标元素均已按源码核对）

| 步 | 目标元素 | 触发前置 | 卡片标题 | 卡片描述（原文） |
|---|---|---|---|---|
| 1 | 书架顶栏「新建作品」按钮（`ShelfTopBar`） | `guideState=not_started` 且书架页可见 | 新建你的第一本书 | 点这里给书起个名字，起好就能开写。书名随时能改，第一本不用纠结。 |
| 2 | 左栏底部「新章节 / 新卷」按钮（`ChapterTree` `nv-tree__foot`） | 已存在至少一部作品；否则跳过 | 建一卷、一章，开始写 | 点一下就建好，默认叫「未命名」，双击名字就能改。不用先想好结构，随时能拖动调整顺序。 |
| 3 | 顶栏设定中心图标（`NovelTopBar`，Ctrl+Shift+S） | 同上 | 先把全书的总设定立起来 | 境界、等级、品阶这类全书通用的体系都在这里。第一次可以从「模板库」一键套用（如「修仙 · 经典九层」），灌完随便改。 |
| 4 | 顶栏行囊图标（Ctrl+Shift+B） | 已有作品 | 行囊：主角的状态面板 | 境界、属性、装备、物品、技能都在这里记。写正文时随时 Ctrl+Shift+B 呼出；关窗前有未保存改动会先问你一次。 |
| 5 | 编辑器正文区（空态用「写下第一章」按钮；有正文用状态条「标注」开关） | 已有激活章节 | 选中文字，右键有惊喜 | 选中一段文字再右键：记进行囊、一键建成角色 / 地点 / 势力 / 物品资料卡，或绑定到已有卡片。注意：没选中文字时右键是系统菜单。 |

编排规则：步骤间不做强制顺序锁（允许作者自己操作跳到下一步对应状态，Tour 自动对齐）。

**强制引导（2026-10-14 用户反馈，1.44.0 落地）**：第 1-4 步的步骤卡片**不渲染右上角关闭叉、不响应 Esc**，唯一出口是卡片上的「下一步」——零基础作者见叉就点，第 3 步的设定中心与第 4 步的行囊会被整段跳过。**第 4 步行囊讲完即「强制引导结束」**；第 5 步（右键建卡）恢复为普通可关闭步骤（有叉、Esc 可跳过并写 `skipped`）：它讲的是一个要先选中文字的交互，硬按着头看效果差，作者看过前四步已具备基本认知。

### 7.3 弱提示点位表

**Tooltip（单次出现，6 秒或点击后淡出）**

| # | 触发时机 | 挂载目标 | 文案 |
|---|---|---|---|
| T-02 | 首次打开设定中心 | 「模板库」按钮 | 第一次用？模板库里有现成的体系，一键套用 |
| T-03 | 首次在正文产生 ≥2 字选区 | 选区下方（坐标由 `coordsAtPos` 算出） | 选中了，右键试试 —— 右键可以把选中的名字建成资料卡（角色 / 地点 / 势力 / 物品），或记进行囊 |
| T-04 | 首次打开行囊 | 头部「模块管理」图标 | 默认只开了 3 块，其他模块在这里按需开启 |
| T-05 | 首次进入大纲空态 | 「＋ 一句话梗概」 | 给这章写一句话梗概，后面好回忆 |
| T-06 | 标注层首次高亮出词 | 高亮词悬浮卡 | 点高亮词可打开资料卡；底部状态条可关闭标注 |
| T-07 | 首次拖动章节触发序号确认 | 确认弹框标题旁 | 这个确认是防误触排序的，可在「排版与偏好」里关掉 |

> T-01（编辑器空态「写下第一章」）已于 1.44.0 下线：空态按钮本身就是强 CTA，再挂一个气泡属重复提示，且强制引导第 2 步已覆盖「从哪开始写」。移除明细见 §14.1 D-05。

**空态引导卡（补 CTA，均已核实现状）**

| # | 位置 | 现状 | 本期补齐 |
|---|---|---|---|
| E-01 | 编辑器无章节空态 | 已有「写下第一章」按钮 | 不改 |

### 7.4 引导状态机与存储

```
not_started ──触发（首次进入 NovelWindow）──▶ in_progress(1/5)
in_progress ──走完 5 步──▶ done
in_progress ──第 5 步点关闭 / Esc──▶ skipped
in_progress ──点「下次再说」──▶ deferred ──下次启动──▶ in_progress
done/skipped ──帮助中心「重看新手引导」──▶ 重置为 not_started（手动触发不写自动弹）
```

- 存储：`novel_config` 新增全局键 `novel_guide_state_v1`（不绑定 workId，安装实例级一次），记录 `{ state, currentStep, updatedAt, stepsViewed[] }`。
- 弱提示的「单次出现」标记并入同键 `tooltipSeen: string[]`，不新增表。
- `deferred` 仅推迟到下次启动，同一会话内不再弹。

### 7.5 帮助中心（L3）

- 入口：窗口标题栏「？」图标 + 快捷键 F1；行囊窗口同样常驻。单实例唤起。
- 首屏：①「重看新手引导」按钮（重置 guideState 后立即播放 Tour）② 快速上手五步流程图（与配套 HTML 文档同源内容）③ 搜索框（按关键词检索功能索引）。
- 文档内容即 `docs/novel-onboarding-guide.html`：快速上手流程图 + 分步骤功能索引 + FAQ 三段互链。

## 八、功能需求

> 状态词：必须（shall）/ 应该（should）/ 可以（may）。

### FR-01 Tour 漫游引导

**描述**：首次进入小说窗口必须按 §7.2 编排播放 5 步 Tour（antd `<Tour>`，`type="primary"` 视觉随主题）。

**规则**：R1 步骤目标不存在或不可见时跳过该步继续下一步；R2 遮罩期间禁止穿透点击目标外的区域；R3 第 1-4 步为强制步——无「跳过 / 关闭叉 / Esc」出口，唯一推进方式是「下一步」；第 5 步可关闭（叉 / Esc 均写 `skipped`）；R4 作者在两步之间完成了后续操作（如已建章），Tour 自动跳到对应步。

**验收**：
- Given 全新安装，When 首次进入小说窗口，Then Tour 从第 1 步开始，高亮「新建作品」按钮，遮罩不拦截该按钮点击。
- Given 作者在第 2 步前已手动建章，When Tour 继续播放，Then 直接从第 3 步开始。

### FR-02 弱提示

**描述**：Tooltip 按 §7.3 点位表在对应首次时机出现一次；Badge 按 B-01 规则显隐。

**规则**：R1 同一时刻全窗口至多 1 个 Tooltip 在场；R2 Tooltip 不拦截点击；R3 出现即记入 `tooltipSeen`，重装前不重复。

**验收**：Given T-03 已看过，When 作者再次选中文字，Then 不再出现气泡。

### FR-03 帮助中心

**描述**：标题栏「？」与 F1 必须打开帮助中心（单实例），首屏含「重看新手引导」与帮助文档。

**验收**：Given 引导已跳过，When 点「？」，Then 打开帮助中心且首屏可见「重看新手引导」；点击后 Tour 立即从第 1 步重放。

### FR-04 引导状态持久化

**描述**：guideState 与 tooltipSeen 必须持久化到 `novel_config` 键 `novel_guide_state_v1`。

**验收**：Given 走到第 3 步后退出应用，When 重启进入，Then 从第 3 步续播（`deferred` 除外）。

### FR-05 过期文案修正（搭车项）

**描述**：设定中心左栏提示「右键或「⋯」可重命名 / 删除分类」应该（should）改为「重命名与删除在右侧「分类信息」卡片」，与实际交互一致。

### FR-06 打字保护

**描述**：作者处于编辑器输入焦点且 3 秒内有键入时，禁止触发任何 L1/L2 引导。

## 十、数据与埋点需求

| 事件 | 触发时机 | 关键字段 |
|---|---|---|
| `guide_start` | Tour 第 1 步展示 | source（auto / replay） |
| `guide_step_view` | 每步展示 | step（1-5）、duration |
| `guide_skip` | 第 5 步关闭 / Esc / 「下次再说」 | step、viewedSteps |
| `guide_complete` | 走完 5 步 | totalDuration |
| `guide_replay` | 帮助中心重看 | — |
| `tooltip_show` / `tooltip_dismiss` | 弱提示出现 / 消失 | id（T-02~T-07）、dwellMs |

## 十四、实施落地说明（2026-10-14 · CHANGELOG 1.43.0 / 1.44.0）

### 14.1 与本文档的实现偏差（均为实现约束下的等价或更优解）

| # | 文档原述 | 实际实现 | 原因 |
|---|---|---|---|
| D-01 | 单个 Tour 播完 5 步 | **拆成两个 Tour 实例**（书架页播第 1 步、编辑器页播第 2-5 步），靠 store 的 `playingStep` 串联 | 两页是 `display:none` 切换的兄弟容器，隐藏容器内的元素取不到有效 rect，单实例无法跨容器高亮 |
| D-02 | 目标不可见 → 跳过该步；全部不可见 → 置 `deferred` | 目标不可见 → **暂停（`pause()`，不改 state）**，条件到位后由 `start()` 续播；只有作者主动延后才写 `deferred` | 直接跳步会在「还没建章」时一路跳到最后并置终态，作者再也看不到后续步骤；暂停可在进入编辑器后自然续播 |
| D-03 | 弱提示 7 个点位全量接入 | 本期接入 **T-01 / T-02 / T-03 / T-04**；T-05、T-06、T-07 见 14.2 | 见 14.2 |
| D-04 | T-03 用 `<GuideTooltip>` 包裹某个元素 | **新增 `SelectionGuide`**：自带零尺寸定位锚点，坐标由 `view.coordsAtPos` 算出 | `GuideTooltip` 只能把气泡挂在被包裹的真实元素上；选区是运行时坐标，CodeMirror 不给元素。出现调度（延时 / 超时 / 一动就撤）抽成 `use-guide-bubble`，两个组件共用同一套规则 |
| D-05 | 弱提示 T-01（编辑器空态「写下第一章」气泡）接入 | **T-01 下线**，点位表只保留 T-02~T-07 | 空态按钮本身就是强 CTA，再挂一个气泡属重复提示；且 Tour 第 2 步已覆盖「从哪开始写」（1.44.0 用户反馈：去掉编辑器空态的提示） |
| D-06 | R3 「跳过」终止全程；§9 可访问性「Esc 跳过」 | **强制引导只覆盖第 1-4 步**（`closable={false}` + `keyboard={false}`，无关闭叉、不响应 Esc，唯一出口是「下一步」）；第 5 步恢复可关闭（叉 / Esc 写 `skipped`） | 零基础作者见叉就点，第 3 步的设定中心与第 4 步的行囊会被整段跳过（1.44.0 用户反馈）。第 4 步行囊讲完即「强制引导结束」；第 5 步讲的是要先选中文字的交互，看过前四步后已具备基本认知，给个叉随时能撤 |
| D-07 | 目标不可见 → `pause()` 等条件到位续播（D-02） | 探测改**三关口**（布局盒 / 视口交集 / 祖先链 `visibility`·`opacity`）+ rAF 重试 600ms 预算 + 实例收 `visible` 收摊；store `start()` 允许**跨视图改拍** | 修「Tour 偶现不显示」三因：①一失败即 pause 且无续播；②折叠侧栏 `width:0;opacity:0` 盒子仍在，老可见性判断把卡片定位到看不见处；③`start()` 遇 playingStep 非空一律 return，两实例各握对方的步会互等死锁、引导永不再现 |
| D-08 | （文档未述）antd Tour 单步实例的关闭语义 | **`onClose` 只在可关闭步骤上接 `skip`**（强制步传 `undefined`） | 单步实例下 antd 的「下一步 / 完成」恒走 finish 路由（`current === total - 1` 恒真），rc-tour 的 `onFinish` 先调 `handleClose()` 触发 `onClose`。早期实现所有步都接 `onClose={skip}`，每点一次「下一步」就先把 `playingStep` 清掉，`goNext` 随后读到 null 空转——表现为「点下一步，下一张卡片再也不出现」且状态被误写 `skipped`。1.44.0 修复，守卫测试钉住 `onClose={forced ? undefined : skip}` 形态 |
