# CheckIn 小说编辑器 —— 产品规划（PRD v0.4）

> 状态：草案待评审（v0.4 数据模型升级版）｜ 作者：产品通 ｜ 日期：2026-09-18
> 一句话定位：**一款专业、主流形态的本地小说编辑器，码字体验是第一优先级——任何功能若影响输入流畅度，一票否决。**
>
> **变更记录**：
> - v0.1 定位"写作伴侣"，手稿编辑器列为非目标；
> - v0.2 按产品决策升级为**专业小说编辑器**，原四大辅助模块（灵感/设定/大纲/检索）重排为 P1 支撑面板，编辑器核心上位 P0，载体仍为 WorkerWindow 窗口改造；
> - v0.3 增补 **R20 角色标记与悬浮资料卡**（正文人名 ↔ 设定卡联动：词库高亮 + hover 出卡），新增配套 Non-goal（不做 NLP 人名识别）。
> - v0.4 按产品决策升级数据模型：设定卡升级为**通用要素实体**（人名/地名/等级/自定义类型 + JSON 扩展字段），新增**多态关联表**支撑要素互相关联，新增**等级体系**与**用户自定义等级转换关系**。数据层 M1 一次到位，UI 分期落地（R23–R27）。

## 1. 市场基准与定位（为什么这样切）

主流竞品格局（2026-09 调研）：

| 阵营 | 代表 | 主打 | 短板 |
|------|------|------|------|
| 平台官方工具 | 作家助手(起点)、番茄作家助手、七猫助手 | 免费、AI 内嵌、一键发布、收益数据 | 被单一平台绑定，数据在平台侧 |
| 独立码字工具 | 小黑屋（强制码字/敏感词）、墨者（多端同步/历史版本）、大神码字（买断/默认不上云）、橙瓜（素材库全家桶） | 存稿安全、专注码字、隐私 | 会员费/广告、云依赖或功能臃肿 |

**主流编辑器的标配能力**（缺一个就不"专业"）：章节/分卷树、防丢稿（自动保存+历史版本）、实时字数统计与目标、专注模式、素材库（人物/大纲/灵感）、敏感词检测、导入导出。

**我们的切入点**：作者对"数据主权"是真实诉求（大神码字把"默认不上云"当核心卖点）。CheckIn 本地 SQLite 单机架构天然契合 → **做一款本地优先、轻量秒开、防丢稿做到极致的纯码字编辑器**。差异化亮点之一：**设定库与正文实时打通**（R20 人名高亮 + 悬浮资料卡）——竞品的设定库大多是"写完切过去查"的孤岛，我们让它长在正文里。

## 2. 码字体验设计规范（本 PRD 的核心章节 = 工程验收标准）

| 维度 | 硬指标 / 设计约定 |
|------|-------------------|
| 输入延迟 | 按键到上屏 P95 < 50ms；**中文 IME 组合输入（拼音候选期间）零掉帧、零丢字**——第一优先验收项 |
| 保存策略 | 输入停顿 800ms 防抖落库 + 失焦/关窗/每 30s 强制 flush；全程无"保存中"阻塞感 |
| 防丢稿三保险 | ① 防抖自动保存；② 增量快照（每 5 分钟或每 500 字，每章保留最近 20 版，可预览回滚）；③ 启动时崩溃恢复检查（检测未落库快照→提示还原） |
| 零打断原则 | 永不弹模态对话框（含关闭确认）；目标达成为轻提示；**移除现有 Esc 关窗行为**（编辑场景 Esc 属高频误触） |
| 中文排版默认值 | 正文区宽度 ~42em 居中、行高 1.9、段间距 0.6em、首行缩进两格（可关）、亮/暗/护眼底色三主题（复用现有 ThemeProvider） |
| 统计常驻 | 底部状态条：本章字数 / 今日新增 / 码字速度(字/分) / 今日目标进度条；字数口径与主流平台一致（含标点字符数，可切换纯汉字） |
| 续写无感 | 记忆上次作品/章节/光标偏移/滚动位置，打开即回到原位续写 |
| 核心快捷键 | Ctrl+S 手动保存、Ctrl+P 章节快速跳转（模糊搜索）、Ctrl+Enter 新章节、F11 专注模式（完整清单 P1） |
| **正文标注层**（v0.3） | 角色名（含别名）基于**设定卡词库白名单**高亮；仅可视区增量匹配、防抖 300ms；IME 组合期间挂起；标注层为统一基建（M2 承载人名高亮，P2 复用于敏感词标黄），单次输入的开销预算 < 2ms |
| **悬浮资料卡**（v0.3） | 悬停高亮人名 200ms 后浮现**无焦点 popover**（移开 100ms 消失，防扫过闪烁）；键盘输入/滚动时立即关闭；永不抢焦点、不阻断输入、不劫持滚轮 |

## 3. 目标与非目标

### 目标

| # | 目标 | 衡量方式 |
|---|------|---------|
| G1 | 码字核心循环零摩擦：打开→定位到上次位置→继续写 ≤ 3 秒 | 启动+恢复计时抽测 |
| G2 | 丢稿事件 = 0，任意崩溃可回滚 | 防丢稿演练清单（杀进程/断电模拟）全过 |
| G3 | 章节管理达到主流专业形态（章节树/状态/排序/分卷） | 功能对照竞品标配清单 |
| G4 | 创作素材闭环服务于码字：卡壳时 3 秒内调出设定/大纲/灵感 | 右栏面板唤起即用 |
| G5 | 设定库随写作"自动生长"：正文中的人名可秒级标记、随时悬浮速查 | R20 联动链路验收 |

### 非目标（守住码字体验与单机定位）

| 非目标 | 原因 |
|--------|------|
| 富文本正文（粗体/图片/表格/批注） | 主流平台发布即纯文本；砍掉它 = 砍掉编辑器内核最大复杂度与性能风险。正文即纯文本段落流 |
| **NLP 中文人名自动识别**（v0.3 新增） | 通用分词/实体识别对中文人名误判率不可控，误判即污染正文标注、打断心流——违背零打断原则。人名来源只有两条可靠路径：设定卡词库（白名单匹配）+ 用户手动标记 |
| 云同步 / 多端 / 协作 | 单机产品，数据主权即卖点，过早 |
| AI 生成/润色/续写 | 2026 已是行业标配，但需 LLM 服务与密钥管理 → **独立立项**，不混入编辑器迭代 |
| 强制码字锁机（小黑屋式） | 负体验风险高，先观察真实需求（P3 评估） |
| 平台发布对接 | 平台 API 不开放、规则各异，远期再说 |

## 4. 用户故事

- 作为**网文作者**，我希望打开编辑器直接回到上次写的章节和光标位置，以便无缝续写。
- 作为**网文作者**，我希望断电/崩溃后一字不丢，并能回滚到任一历史快照，以便安心码字。
- 作为**网文作者**，我希望实时看到本章字数、今日新增和目标进度，以便保持日更节奏。
- 作为**网文作者**，我希望左侧章节树可新建/排序/标记状态（草稿/完稿），以便管理几十章的大部头。
- 作为**网文作者**，我希望写卡壳时右侧划出人物卡/大纲/灵感便签，以便不离开正文解决设定问题。
- 作为**网文作者**，我希望正文里写过的角色名自动高亮，鼠标移上去浮现 TA 的资料卡，以便写作中途秒查人设不出戏。
- 作为**网文作者**，我希望选中正文里的新名字一键"标记为角色"（无卡则秒建、有卡则关联为别名），以便设定库随写作自动长出来。
- 作为**网文作者**，我希望一键自动排版（段首缩进、全角标点统一），以便贴平台前不用手工清理。
- 作为**网文作者**，我希望按 Ctrl+P 模糊搜索章节名直接跳转，以便在百章大书里不迷路。

## 5. 产品结构

```text
WorkerWindow（改造为编辑器窗口：默认 1200×760，min 800×560，记忆尺寸/位置）
├─ 左栏（可收起）：作品切换 + 卷/章节树（状态标记、排序）
├─ 中央：码字区 —— 纯文本、打字机/沉浸模式、底部常驻统计条
│          └─ 正文标注层：角色名高亮 → hover 悬浮资料卡
└─ 右栏（可收起）：支撑面板 Tab = 大纲 ｜ 设定卡 ｜ 灵感速记 ｜ 全库检索
```

三栏皆可收起 → 纯码字区一行 UI 都不多。默认打开状态：左栏展开、右栏收起。

## 7. 工程落点（对照 AGENTS.md，窗口级改造清单）

**窗口级（electron/main.ts + WorkerWindow）：**
- `createWorkerWindow()` 默认尺寸 720×520 → **1200×760**（min 420×320 → 800×560），并持久化上次 bounds
- **移除 App.tsx 中 Esc 直接关窗逻辑**（替换为编辑器内语义：退出专注模式/无操作）
- 即关即销语义**保留**——对编辑器反而是优点：无状态腐化，数据安全完全由持久化层兜底
- 标题/图标更新为编辑器身份

**数据层（userDb 新表，SQL 只进 db.ts / handlers）：**

```text
novel_works(作品) / novel_volumes(卷, P1) / novel_chapters(title, content, word_count, status, sort)
novel_snapshots(chapter_id, content, created_at)   -- 每章环形保留 20 版
novel_notes(灵感速记) / usage_log(埋点)

-- ── 要素模型（v0.4：原 novel_cards 升级，类型可扩展 + 互相关联 + 等级体系）──
novel_entities(id, work_id, type, name, aliases, summary, content,
               fields, sort, created_at, updated_at)
    type: character/location/faction/item/level_system/custom…（用户可自建类型）
    fields: 自定义键值扩展字段，JSON 列承载（SQLite JSON1 可查询）——预留扩展性，避免 EAV 过度设计
novel_links(id, from_type, from_id, to_type, to_id, relation, note)
    -- 多态关联：任意要素两两互相关联（人名↔地名、角色↔势力、角色↔等级…）
    -- relation 预置常用值（师徒/亲属/敌对/所属/出身地/当前境界）+ 用户自定义文本
novel_level_systems(id, work_id, name, note)         -- 等级体系（如"修真境界"）
novel_levels(id, system_id, name, rank, note)        -- 等级项，rank 即顺序（练气→筑基→金丹…）
novel_level_conversions(id, from_level_id, to_level_id, relation, note)
    -- 用户自定义等级转换关系：等同/对应/晋升为/自定义文本
    -- 表结构 M1 一次到位，编辑 UI 按 R26 分期（M3）
```

- 新建 `electron/handlers/novel-handlers.ts`（语义化 IPC：`novel-chapter-save` 等）；保存 + 快照写入同事务
- 字数在保存时计算并落列；**词库（要素名称+别名）随要素保存时同步刷新到渲染层内存**，供标注层匹配
- 新依赖建议：CodeMirror 6（纯文本模式）——虚拟滚动、性能与 IME 支持成熟，可深度定制打字机/护眼主题；备选受控 textarea（最简但打字机模式/标注层难做）；**排除** Monaco/ProseMirror。注意 pnpm 11 新依赖有发布冷却期（minimumReleaseAge）

**R20 技术要点**：CodeMirror 6 增量 decoration（仅可视区 + 防抖）承载人名高亮；`hoverTooltip` 扩展实现资料卡（无焦点、composition/输入期间强制关闭）；与敏感词（R15）共用同一标注管线。**这套能力反过来印证了内核选 CodeMirror 6 的必要性。**

**边界合规**：编辑器组件留在 `WorkerWindow/` 私有目录（文件夹化组件、index.scss）；仅单使用方不上移 shared；窗口隔离不 import BaseWindow。纯增量，不触碰 Todo/Memo/Daily 链路。

## 10. 风险与开放问题

**风险**

| 风险 | 等级 | 对策 |
|------|------|------|
| IME 兼容缺陷直接摧毁码字体验 | 高 | M1 第一周即做内核选型 time-box 验证（2 天），拼音实测不过则换 textarea 方案 |
| 富文本需求诱惑导致范围蔓延 | 高 | Non-goal 写死；正文永远纯文本段落流 |
| 标注层（高亮/hover 卡）拖慢输入 | 中 | 白名单匹配 + 可视区增量 + 防抖三重节流；"劣化 ≤2ms"硬验收；提供全局开关一键关闭标注 |
| 快照策略不当（过频卡顿/过疏丢稿） | 中 | 增量快照节流（5min/500 字双阈值）+ M1 演练校准 |
| Esc/误触关窗心理不适 | 中 | 已移除 Esc 关窗；关窗永不丢数据是硬验收 |

**开放问题**

1. **编辑器内核**：CodeMirror 6（推荐）vs 受控 textarea —— 工程侧 2 天验证后拍板（阻塞 R2/R20，不阻塞其他开发）
2. **载体确认**：仍按"改造 WorkerWindow"执行（本 PRD 前提）；若未来想保留通用临时窗，独立 NovelWindow 拆分成本低
3. **今日字数口径**：按净增（删字扣回，推荐）还是按保存动作累计
4. **快照保留 20 版/章**是否足够（存储估算：单章 1 万字 × 20 版 × 100 章 ≈ 20MB，无压力）
5. **同名角色处理**（v0.3）：同名不同人时 v1 按唯一卡匹配 + 资料卡内提示"存在同名卡"；是否需要"指定某卡仅在某章生效"等消歧机制 → M3 按真实反馈定
6. **要素字段模板**（v0.4）：v1 用"自定义键值字段"兜底扩展性；若 M2 数据显示用户高频重复添加同类字段，再升级为"按类型的字段模板管理器"（避免过早设计）
7. **等级转换的方向语义**（v0.4）：`novel_level_conversions` 的 relation 目前是无约束文本（等同/晋升为/自定义）；若需要"晋升链"自动推导（A→B→C 传递），届时升级为有向图校验 → M3 按需

### 附：一页纸决策摘要

- **是什么**：本地优先、秒开、防丢稿做到极致的专业小说编辑器（WorkerWindow 改造承载）。
- **凭什么是我们**：数据主权（本地 SQLite）+ 与 CheckIn 生态融合（写作时段/日更目标）+ 零会员零广告 + **要素库长在正文里且万物可关联**（人名高亮/悬浮资料卡/要素互相关联/等级体系与自定义转换）。
- **不做什么**：富文本、NLP 人名识别、云同步、AI（独立立项）、强制锁机、平台对接。
- **成败判据**：输入 P95 <50ms（标注层劣化 ≤2ms）、丢稿=0、打开即续写 ≤3s、周有效码字 ≥4 天。
