## 二、背景与目标

### 2.1 背景

行囊（CharacterPack）已从 NovelPage 内嵌面板升级为独立窗口（PackWindow），当前形态是**十模块编辑器矩阵**：总属性汇总 / 人物属性 / 属性映射 / 装备栏 / 物品栏 / 技能栏 / 境界 / 货币 / 状态效果 / 备注速记，每个模块都是一套完整的编辑界面（增删改、配置、弹窗管理）。

这个形态服务的是「配一套主角设定」的场景；但当作者的使用目的变成**「写正文时快速确认 / 微调主角当前状态」**时，问题暴露出来：

1. **初始界面一次性平铺**：宽档双栏并排九个模块、中档单栏纵向流十个模块全部展开。作者打开行囊第一眼看到的是一整屏编辑控件，而不是「主角现在是谁、什么境界、属性如何」。
2. **读写没有分层**：「看数」和「改配置」是同一套界面。查一个总览值，旁边就是属性定义编辑器、进制配置、映射规则——认知负担被与当前任务无关的控件撑满。
3. **境界选择路径长**：境界模块虽有阶梯点选，但「选到某一阶的某一小层」只能靠 `±1 层` 递推；等级多、小层多时点选成本高。而没有等级体系时，界面只给一句文字提示，作者必须自己切换到「设定 → 等级体系」页面从零建梯。

### 2.2 目标

| 编号 | 目标 | 衡量口径 |
|---|---|---|
| G-01 | 行囊初始界面从「编辑器平铺」转为「主角信息看板」 | 首屏（不滚动）呈现：主角身份、当前境界、核心属性总览、生效状态、关键设定摘要五区；编辑器模块默认收起为摘要行 |
| G-02 | 信息按创作节奏渐进展开 | 任意模块从「看到摘要」到「进入编辑」≤ 1 次点击；常用模块可钉选常驻 |
| G-03 | 等级体系在行囊内直接完成选择 | 选定「阶 + 小层」≤ 2 次点击完成，全程不离开行囊窗口；写入仍走 REQ-048 唯一契约 |
| G-04 | 不损失任何现有编辑能力 | 十个模块的编辑、管理、导出、保存链路零删减（本方案只改入口与默认态） |

### 2.3 非目标（本期不做）

- 不在行囊内创建 / 编辑等级体系本身（等级体系是作品级设定，创建与结构调整仍归设定中心 SettingCenter，见 §13 遗留问题 L-02）。
- 不做新的数据表、不改表结构（本方案在 `compat` 语义下完全成立，不依赖 §6.7 重构授权）。
- 不改动草稿 / 保存 / 关闭守卫 / 跨窗口同步等既有链路。
- 不做视觉改版（主题 token、组件库造型不动，仅调整信息结构与默认态）。

## 四、需求范围

**包含**：行囊初始看板（L0）信息结构与分区；模块默认态与渐进展开规则；钉选偏好；境界「阶 + 小层」行囊内直选；空态分层引导；无等级体系时的一键跳转设定中心（跨窗口）；档位策略调整；埋点。

**不包含**：等级体系创建 / 编辑入口进行囊；新数据表；既有保存 / 守卫 / 同步链路改造；视觉主题改版；移动端形态（行囊仅桌面窗口）。

## 五、现状盘点与方案对比

### 5.1 可复用资产（现状盘点）

| 资产 | 位置 | 本方案中的用法 |
|---|---|---|
| 三档宽度断点 + 自动折叠 | `pack-config.ts`（`packWidthTier` / `isCorePackModule`）、`pack-layout.ts`（`isAutoCollapsed`） | 默认折叠策略从「窄档自动折叠」扩展为「全档默认摘要行」 |
| 模块摘要纯函数 | `pack-layout.ts`（`moduleSummary`） | 摘要行文案直接复用，零新增口径 |
| 分区映射 | `pack-layout.ts`（`PACK_ZONE_OF` / `splitByZone`） | L1 展开后的分区编排不变 |
| 境界读写契约 | `pack-realm.ts`（`getRealm` / `setRealm` / `RealmWritePlan`）、`usePackPanel.ts`（`writeRealm`） | 直选写入唯一入口，`toast` 回带 `plan.position` |
| 阶梯纯函数 | `pack-utils.ts`（`clampRealm` / `carryRealm` / `formatRealm`） | 直选后夹取 / 进位规则不变 |
| 界面偏好落库 | `types.ts`（`PackUiPrefs`，config 键 `novel_pack_ui`，即改即存） | 新增 `pinned` 偏好字段 |
| 跨窗口双通道事件 | `pack-config.ts`（`notify*` + `readEventDetail`）、`shared/novel/dual-channel.ts` | 跳转设定中心的新频道沿用同一范式 |
| 本章变动角标 | `usePackPanel`（`changedReadAt` / `markAllChangesRead`） | 并入看板「最近改动」区 |
| 来源明细抽屉 | `components/SourceDetailDrawer`、`RecordDrawer` | 看板属性行点击追明细，入口不变 |
| 关闭守卫三通道 | `services/pack-close-guard.ts`、`CloseGuardModal` | 不改动 |

### 5.2 候选方案对比

| 维度 | 方案 A：只调默认折叠 | 方案 B：看板首页 + 渐进披露（推荐） | 方案 C：拆「看板 / 编辑」两个窗口 |
|---|---|---|---|
| 思路 | 宽 / 中档也默认折叠次要模块，核心三块展开 | 新增 L0 看板首页（身份 / 境界 / 属性 / 状态 / 设定摘要五区），十个模块降为 L1，按需展开 | 行囊拆成只读看板窗 + 编辑窗 |
| 实现成本 | 低（改 `isAutoCollapsed` 默认值） | 中（新增看板区组件 + 偏好字段 + 境界直选，复用全部既有资产） | 高（窗口生命周期 / 上下文投递 / 守卫全部重做） |
| 用户体验 | 中：仍是编辑器首页，只是收起了 | 好：一屏看懂主角，编辑显式进入 | 好但割裂：两窗同步成本高 |
| 风险 | 低 | 低-中（默认态变化影响老习惯，靠 pin + 引导缓解） | 高（跨窗同步、关闭守卫、草稿归属全部要重新设计） |
| 对 G-01~G-04 的达成 | 只达 G-02 一半 | 全达 | 全达但成本失控 |

**推荐方案 B**。理由：① 复用现有折叠 / 摘要 / 契约 / 事件四类资产，不新建数据表、不动保存链路；② 「看板首页 + L1 模块」正是渐进式披露的标准结构，初始界面只放「当前状态」，编辑能力一次点击可达；③ 方案 C 把简单问题复杂化，两个窗口的同步与守卫是已付过代价的领域（P3-1 删桥的教训），不值得再走一遍。

## 六、用户角色与使用场景

### 6.1 角色

- **作者（主力）**：连载中小说创作者。边写正文边开关囊：「主角这章筑基了，把境界改一下」「确认下当前气血多少」「这场战斗后加个虚弱 debuff」。特征是**高频、短时、目的明确**。
- 画像说明：以上为基于行囊现有功能形态构建的角色假设，待用户确认。

### 6.2 场景

**主流程（写作中对记）**：写至「陆长安运转功法，气息攀升」→ 打开行囊 → 首屏看到「陆长安 · 炼气 7 层」→ 点境界卡小层「8」→ toast「境界已更新：炼气 8/9 层（保存后生效）」→ 关闭行囊继续写。全程 ≤ 3 次点击，不滚动找模块。

**分支流程（配设定）**：开新书 → 行囊首屏引导「还没有属性」→ 一键套用「玄幻」属性模板 → 看板出现核心属性 → 需要调换算规则时点「属性映射」摘要行进编辑器。

**异常流程**：无等级体系 → 境界卡显示「未设置」+ 「去设定中心创建」按钮（一键唤起 NovelWindow 并定位到等级分类）；行囊窗口未绑定主角实体 → 境界卡明示「仅在行囊内使用」，直选仍可用（写 `realmAt`）。

## 七、信息架构与分层设计（核心）

### 7.1 三层渐进式披露模型

```
L0 看板首页（默认，一屏）
├─ A 主角身份卡：头像位 / 名字（可改）/ 主角绑定态 / 保存三态
├─ B 境界卡：当前境界 + 直选（阶 + 小层）+ 微调 + 双读数对照
├─ C 核心属性总览：base → final + 增量段（默认 top 区，可展开全部）
├─ D 生效状态：持续 / 被动 buff 摘要 + 快捷开关
└─ E 关键设定摘要：装备 / 技能 / 物品 / 货币 / 映射 / 备注 摘要行（各一行）
L1 模块编辑器（按需进入，一次点击）
├─ 现有十个模块，能力零删减
└─ 分区编排（gear / stats）与模块管理保持现状
L2 系统管理（低频）
   ├─ 模块管理 / 单位制管理 / 槽位管理 / 分组管理 / 记录抽屉 / 导出
   └─ 入口收敛在头部「更多」，不看板首页占位
```

分层原则：**先读后写、先状态后配置、默认收起、显式展开**。

### 7.2 L0 看板首页线框思路

```
┌────────────────────────────────────────────────────┐
│ 头部横带（现状保留）                                  │
│ 陆长安 · 炼气 7/9 层   负重 128/200  容量 18/30格   │
│ 已保存 · 3 分钟前        [保存][更多▾]               │
├────────────────────────────────────────────────────┤
│ B 境界卡                                  [阶设置⚙] │
│   炼气 7 层                                        │
│   [炼气][筑基][金丹][元婴][化神]…   ← 阶梯尺（直选）│
│   小层 [1][2][3][4][5][6][7][8][9]  ← 层号条（直选）│
│   [−1 层] [+1 层]   实体面板：炼气 7 层 · 同源      │
├────────────────────────────────────────────────────┤
│ C 核心属性总览                        [展开全部 ▾]  │
│   气血   100 → 180   +60 被动 · +20 映射    3 条来源│
│   攻击    32 →  51   +15 被动 · ×1.10 持续  2 条来源│
│   …（默认展示前 N 条，其余进 L1）                    │
├────────────────────────────────────────────────────┤
│ D 生效状态                                          │
│   ● 中毒（持续） 气血 −5/回合      [开关]           │
│   ● 阵法增益（被动） 防御 +10%                     │
├────────────────────────────────────────────────────┤
│ E 关键设定（摘要行，点击进 L1 编辑器）      [模块管理]│
│   装备栏    6 部位 · 4 已穿戴                    ▸ │
│   技能栏    12 项 · 5 启用                        ▸ │
│   物品栏    23 种 · 共 87 件                      ▸ │
│   属性映射  3 条换算                              ▸ │
│   货币      已配置                                ▸ │
│   备注速记  128 字                                ▸ │
└────────────────────────────────────────────────────┘
```

分区规则：

- **A/B/C/D 为看板常驻区**（读 + 轻量写），任何档位不收起；
- **E 为摘要行区**，一行一模块，文案取 `moduleSummary`（已有纯函数，不新增口径）；
- 点 E 的摘要行 → 该模块就地展开为完整编辑器（L1，保留分区编排）；再点收起回摘要行；
- 「展开全部」一键把所有模块展开（等价旧版全展开态），照顾配设定场景。

### 7.3 渐进呈现规则（状态机）

| 模块状态 | 进入条件 | 退出条件 |
|---|---|---|
| 摘要行（默认） | 初始加载；作者未表态 | 点击行内任意处 |
| 展开（L1 编辑器） | 点击摘要行 / 看板入口 | 点击收起；或作者钉选后不再变化 |
| 钉选常驻 | 作者在模块管理 / 行内点「钉」 | 取消钉选 |

规则要点：

1. **默认态改革**：`isAutoCollapsed` 的策略从「仅窄档自动折叠」改为「全档默认摘要行」，核心三块（汇总 / 属性 / 境界）并入看板常驻区而非独立折叠块。作者手动展开过的模块记入 `prefs.collapsed`，规则 2（显式偏好接管）不变。
2. **钉选**：`PackUiPrefs` 新增 `pinned: PackModuleKey[]`（即改即存，走 `novel_pack_ui`）。被钉模块在看板首页常驻展开——把「作者每天都看的技能栏」从两层点击变零层。
3. **空态分层引导**：每区空状态给「下一步动作」而非仅说明文字——无属性 → 「套用模板 / 去建属性」；无境界体系 → 「去设定中心创建」；无绑定 → 「设为主角」入口。引导按钮直达对应动作（§7.4）。
4. **档位策略**：宽档看板 + 右侧可并排展开的 L1；中 / 窄档看板单栏 + L1 纵向流；窄档下头部读数整块不传的既有规则不变。

### 7.4 等级体系行囊内直选（专项）

**现状**：阶梯 chips 可点选跳阶（`pick(index)`）；小层只能 `±1 层` 递推（`step(±1)`，`carry: true`）；无等级体系时仅文字提示去设定中心。

**目标交互**（全部在行囊窗口内完成，不跳页）：

| 操作 | 交互 | 写入路径 |
|---|---|---|
| 选阶 | 点阶梯尺 chip，或从「阶下拉」框选（等级 > 8 个时下拉为主路、尺为辅助） | `writeRealm({index, sub:1}, "pack")` → `setRealm` → 夹取到该阶第 1 层 |
| 选小层 | 点层号条 `1..N`（N = 该阶小层数，> 12 时改下拉） | `writeRealm({index, sub}, "pack")` → `clampRealm` |
| 微调 | `−1 层 / +1 层` 保留（跨阶自动进位 / 退位） | `writeRealm(pos, "pack", {carry:true, delta:±1})` |
| 结果反馈 | toast 文案取 `plan.position`（唯一真相），不二次计算 | 既有逻辑不变 |

硬约束（继承 REQ-048，方案内逐条保留）：

- 所有读取走 `getRealm` / `getPanelRealm`，写入走 `writeRealm` → `setRealm`，禁止组件直连 `realmAt` / `novel_links`；
- 未绑定主角实体时直选同样生效（写 `realmAt`，仅行囊内使用），界面明示该语义；
- 阶设置弹窗（小层数 / 战力当量）保持「改的是体系、与实体面板同表」的说明，不混入「选当前境界」的语义。

**无等级体系时**：境界卡显示「未设置」+ 主按钮「去设定中心创建」。点击后经跨窗口广播唤起 NovelWindow（focus + 打开 SettingCenter 并定位到境界分类，复用页面内既有的 `openSettingCenterForRealm` 入口形态），创建完成后阶梯尺自动可用（行囊 `meta.levelSystems` 随装载 / 同步刷新）。频道新增 `novel-open-setting-center`，沿用 `subscribeDualChannel` + `readEventDetail` 双通道范式，负载带 `workId` 与目标分类 id。

> 说明：用户要求「已定义的等级体系在行囊内直接框选或选择」——本方案以直选满足该要求；**创建**体系属作品级设定管理，保留在设定中心（一键跳转已把路径成本降到接近零），是否进一步支持行囊内建梯列入遗留问题 L-02。

## 八、功能需求

> 状态词：必须（shall）/ 应该（should）/ 可以（may）。每条附 Given/When/Then 验收标准。

### FR-01 看板首页（L0）

**描述**：行囊初始界面必须呈现五区——主角身份卡（A）、境界卡（B）、核心属性总览（C）、生效状态（D）、关键设定摘要行（E）。初始状态不得展开任何编辑器模块。

**规则**：
- R1 A 区复用现有头部横带信息（名字 / 境界 / 绑定态 / 保存三态），不新增读数口径
  （负重 / 容量已于 1.39.0 下线，头部不再有中间读数区）；
- R2 C 区默认展示前 N 条属性（N 随档位：宽 8 / 中 6 / 窄 4），其余经「展开全部」或进入 L1 查看；
- R3 D 区只列生效中（`active`）的持续 / 被动效果，过期与组停用不计入（与汇总管线口径一致）；
- R4 E 区顺序尊重作者在模块管理里的排序。

**验收**：
- Given 一本有完整数据的书，When 打开行囊，Then 不滚动可见 A/B/C/D 四区与至少 4 行 E 摘要，且界面无任何输入框 / 配置控件处于焦点态。
- Given 十个模块全部启用，When 初始加载，Then 无模块处于展开编辑器态。

### FR-02 渐进展开与收起

**描述**：E 区摘要行点击后该模块就地展开为完整编辑器（L1），再次点击收起回摘要行；「展开全部」可一次展开所有模块。

**验收**：
- Given 模块处于摘要行，When 点击，Then ≤ 1 次点击内出现该模块完整编辑器，且其既有功能（增删改 / 导出 / 管理入口）全部可用。
- Given 模块处于展开态，When 点击收起，Then 回到摘要行且未保存编辑不丢失（草稿链路不变）。

### FR-03 钉选常驻

**描述**：作者可以（may）把任意模块钉选为看板常驻展开；取消钉选后回到默认摘要行。钉选写 `PackUiPrefs.pinned`，即改即存，不计未保存改动。

**验收**：
- Given 模块被钉选，When 重开行囊 / 切换章节后返回，Then 该模块仍为展开态。
- Given 未钉选模块，When 手动展开后关闭行囊再打开，Then 回到摘要行（显式折叠偏好仅记录作者主动收起）。

### FR-04 境界直选（阶）

**描述**：境界卡必须提供阶梯尺点选与阶下拉框选两条路径选定主角当前阶；写入必须走 `writeRealm(position, "pack")`。

**规则**：
- R1 阶梯尺维持「一条尺子」读法（不换行、横向滚动），当前阶高亮、已过阶置灰；
- R2 阶数量 > 8 时下拉框选为主路径（避免长尺滚动成本）；
- R3 点选即写：toast 文案取 `plan.position` 格式化结果。

**验收**：
- Given 已绑定主角且阶梯有 9 阶，When 点「金丹」chip，Then toast「境界已更新：金丹 1/3 层（保存后生效）」，保存后实体面板角色卡同步（既有广播链路）。
- Given 未绑定主角，When 点选任意阶，Then 写入 `realmAt` 且界面明示「仅在行囊内使用」。

### FR-05 境界直选（小层）

**描述**：境界卡必须提供层号条（1..N）直接选定小层；N > 12 时改为下拉。`±1 层` 微调保留。

**规则**：
- R1 层号条只出现当前阶的小层数 N 个；
- R2 选层写入走 `writeRealm({index, sub}, "pack")`，夹取规则用 `clampRealm`，组件不自算边界；
- R3 已到顶阶满层 / 首阶首层时微调按钮置灰并说明原因（现有规则保留）。

**验收**：
- Given 当前「炼气 3/9 层」，When 点层号「7」，Then 境界显示「炼气 7/9 层」且保存后实体面板一致。
- Given 当前阶 N=1（无小层），When 查看境界卡，Then 不渲染层号条（不出现单选项 [1]）。

### FR-06 空态分层引导

**描述**：看板各区空状态必须提供下一步动作入口，而非纯文字说明。

| 空态 | 引导动作 |
|---|---|
| 无属性 | 「套用模板」（通用 / 玄幻 / 网游，既有 `ATTR_TEMPLATES`）+「去建属性」 |
| 无等级体系 | 「去设定中心创建」（跨窗口唤起，§7.4） |
| 未绑定主角 | 「设为主角」（走 `bindEntity`，即时落库 + 广播，既有链路） |
| 无生效状态 | 一句话说明 + 「+ 持续 / + 被动」入口（既有 StatusModule 动作） |

**验收**：
- Given 新书无任何设定，When 打开行囊，Then 五个区各显示对应引导且每个引导按钮可一次点击到达目标动作。
- Given NovelWindow 未运行，When 点「去设定中心创建」，Then 由主进程拉起 NovelWindow 并定位（不得静默失败，失败要有 toast）。

### FR-07 核心属性总览区

**描述**：C 区展示 base → final 与增量段（被动 / 持续 / 映射 / 百分比 / 乘算），点击行进来源明细（既有 `SourceDetailDrawer`）。估算模式入口保留在汇总模块头部。

**验收**：
- Given 某属性有 3 条来源，When 点击该行，Then 打开来源明细抽屉且列出全部 3 条。
- Given 属性超过默认展示数，When 点「展开全部」，Then C 区展示全部属性。

### FR-08 最近改动并入看板

**描述**：头部「本章变动」能力（should）以看板入口形式保留：有未读变动时在 A 区显示角标与「全部已读」，不再占据中部读数带。

**验收**：
- Given 24 小时内有改动，When 打开行囊，Then A 区显示未读计数；点「全部已读」后计数清零且 24 小时过期规则不变。

### FR-09 档位与默认态策略

**描述**：默认折叠策略必须从「仅窄档自动折叠」调整为「全档默认摘要行」；核心三块并入看板常驻区。`pack-layout.ts` 以纯函数承载新规则并更新守卫测试。

**验收**：
- Given 宽档（≥900px）打开行囊，When 初始加载，Then 看板 + 摘要行呈现，无模块默认展开（钉选除外）。
- Given 窄档（<600px），When 初始加载，Then 同宽档默认态 + 头部读数整块不传（既有规则）。

### FR-10 偏好与迁移

**描述**：`PackUiPrefs` 新增 `pinned: PackModuleKey[]`（默认空数组）。旧偏好文件无该字段时按空数组处理，不弹迁移、不丢既有偏好（`collapsed` / `inventoryView` 等原样保留）。

**验收**：
- Given 旧版本偏好（无 `pinned`），When 升级后首次打开，Then 行为与空 `pinned` 一致，无报错、无偏好丢失。

## 九、非功能需求

| 项 | 要求 |
|---|---|
| 性能 | 看板首屏只渲染摘要与派生量，不得挂载十个编辑器；属性行默认 ≤ 8 条，其余懒展开；打开到可交互 ≤ 现有水平（不劣化） |
| 兼容 | 无表结构变更；旧草稿 / 旧偏好完整可读（`compat` 语义成立，不依赖 §6.7 `refactor` 授权） |

| 可访问性 | 阶梯 chip / 层号条键盘可达（Tab / 方向键），当前阶 `aria-current`；层号条按钮带可读名称（如「炼气第 7 层」） |
| 工程规范 | 新规则进 `pack-layout.ts` 纯函数 + 守卫测试同步；组件文件夹 + `index.scss` 就近；禁止组件直连境界字段（REQ-048 契约保留并补反向断言） |

## 十一、异常与边界处理清单

| 场景 | 处理 |
|---|---|
| 等级体系被外部（设定中心）删除，行囊开着 | `meta.levelSystems` 同步刷新后境界卡回落「未设置」+ 引导；不得崩、不得留幽灵阶 |
| 直选后保存失败 | 既有保存失败态（`saveFailed` + 重试 + 草稿导出逃生口）不变；toast 已明示「保存后生效」 |
| 阶的小层数被阶设置改小（如 9 → 3，当前在 7 层） | `clampRealm` 夹取到 3；UI 不得显示越界层号 |
| 跨窗口跳转时 NovelWindow 拉起失败 | toast 明示失败 + 保留行囊内引导按钮可重试 |
| 多窗口开着不同作品 | 所有事件负载带 `workId` 过滤（既有范式）；跳转频道同样带 `workId` |
| 极窄窗口（<380px） | 看板单栏；层号条超长改下拉；不出现横向溢出 |
| 模块被全部关闭 | 保留既有空态提示（齿轮重开），看板常驻区不受影响 |

## 十三、风险与遗留问题

### 风险登记册

| 编号 | 风险描述 | 类别 | 概率 | 影响 | 等级 | 应对措施 |
|---|---|---|---|---|---|---|
| RK-01 | 默认态变化影响老作者习惯（「我的模块怎么全收起」） | 体验 | 3 | 2 | 6 低 | 「展开全部」一键回旧态；首启一次引导气泡；pin 引导 |
| RK-02 | 境界直选与 R25 实体面板双写分叉 | 技术 | 2 | 4 | 8 中 | 写入只走 REQ-048 唯一契约 + `plan.position` 回写；双读数对照保留；守卫测试补反向断言 |

| RK-05 | 层号条 / 阶梯 chip 在等级极多（50+）时的渲染与滚动 | 技术 | 2 | 2 | 4 低 | 阈值切换下拉（阶 > 8、小层 > 12）；纯函数定阈值便于测试 |

### 遗留问题

| 编号 | 问题 | 建议 |
|---|---|---|
| L-01 | 「框选」是否含批量操作（如一次把多章境界记录批量调整）？ | 当前按单次直选设计；如需批量，记录抽屉（RecordDrawer）是更合适的载体，独立评估 |

| L-03 | 看板密度（紧凑 / 宽松）是否需要作者可调？ | M3 候选，埋点复盘后定 |
