## 1. 执行摘要

**简述：** 为 CheckIn 小说编辑器新增「地图编辑器」——一个让网文作者用**现成的 PNG 地形素材**快速拼出架空世界示意图的轻量工具，解决"脑中有地理格局、笔下写不清晰"的问题。

**内容：** 一个可视化画布编辑器，支持：底图铺设 → 地形素材拖拽摆放 → 地点标记 → 地点间连线 → 缩放平移浏览 → 导出图片。核心不追求美术表现力，追求**低门槛出图**与**随时可改**。

**原因：** 网文作者（尤其玄幻 / 仙侠 / 历史 / 权谋 / 种田流）在开书期必须想清楚"势力怎么分布、主角往哪走、两地多远"，这是**设定期最高频的思维负担之一**。当前作者的做法是：① 在脑子里记（会记错、前后矛盾）；② 手画在纸上（不可改、不可搜、丢了就没了）；③ 用专业绘图软件（学习成本高、杀鸡用牛刀）。地图编辑器把这件事压到"拖几下就成图"的粒度。

**面向谁：** 用 CheckIn 写小说、需要设定地理格局的网文作者。

**为什么现在做：** 地图是小说设定层缺失的最后一块拼图。人物有关系网络、物品有行囊、等级有体系，唯独"空间"没有落点——而这恰是长篇最容易出硬伤（前后地理矛盾）的地方。

## 2. 产品定位与边界

### 2.1 一句话定位

> **架空世界示意图编辑器** —— 用现成素材拼出一张"自己看得懂"的设定图，不追求画得好看，只追求**想得清楚、写得一致**。

### 2.2 用户画像

| 维度 | 描述 |
|---|---|
| 身份 | 网文作者（玄幻 / 仙侠 / 历史 / 权谋 / 种田 / 无限流） |
| 典型场景 | 开书设定期搭世界观；写作中随时回看地理；向读者/编辑说明势力分布 |
| 技术背景 | 无美术基础、无绘图软件经验 |
| 核心诉求 | 快速、低门槛、可随时改 |
| 非诉求 | 精美插画、印刷级精度、真实地理准确性 |

### 2.3 核心价值主张

| 作者当前的痛 | 本产品如何解决 |
|---|---|
| 地理格局全靠脑记，写着写着矛盾 | 可视化落点，一眼看清相对位置 |
| 纸上手画，改一处要重画整张 | 元素可拖拽、可撤销，改一处不动其他 |
| 用 PS/AI 画，学习成本太高 | 素材拖拽 + 现成地形贴图，零绘图技能 |
| 设定散落在正文/备忘录/Excel | 收进 `novel_maps`，与作品绑定 |

### 2.4 明确的非目标（Non-goal）

**以下内容明确不做，且不属于本产品的演进方向：**

| 非目标 | 理由 |
|---|---|
| 真实地理地图 / 测绘数据 | 与架空世界定位不符，且涉及地图数据合规 |
| 在线瓦片地图（高德/天地图等） | 同上，且引入网络依赖 |
| 印刷级美术输出 | 定位是设定示意图，不是插画工具 |
| 自由矢量绘图（钢笔/贝塞尔曲线工具） | 会滑向"绘图软件"，见 §9 风险 |
| 3D 地形 / 等高线 / 光照渲染 | 超出"想清楚地理"的需求 |
| 地理投影坐标系 | 架空世界无真实经纬度，不需要 |

**用户故事**
> 作为作者，我希望选一张现成的地形图当画布底，而不必从空白开始画。

**功能定义**

| 项 | 说明 |
|---|---|
| 选图 | 从内置底图库中选择（首期提供若干张预设底图） |

- 底图始终位于最底层，不可被拖拽到素材上方

**验收标准**
- [ ] 可从底图库选图，选中后立即渲染
- [ ] 替换底图时，已有素材位置不发生偏移
- [ ] 底图缺失时不报错，降级为纯色底 + 提示

**待定项**

### 4.3 R-MAP-03 地形素材拖拽摆放

**用户故事**
> 作为作者，我希望从素材库里把"山""树""城池"拖到地图上，像摆棋子一样拼出地形。

**功能定义**

| 项 | 说明 |
|---|---|
| 素材源 | 内置 PNG 地形素材（山 / 水 / 树 / 城 / 关隘 / 特殊地形） |
| 添加方式 | ① 从素材区点击 → 落到画布中心；② 拖拽 → 落到鼠标位置 |

**验收标准**
- [ ] 素材可添加、可拖动，位置实时跟手无延迟

### 4.4 R-MAP-04 素材缩放 / 旋转 / 删除

**用户故事**
> 作为作者，我希望调整素材大小与角度，让地形更自然。

| 操作 | 交互 |
|---|---|

- [ ] 缩放有最小尺寸限制，防止素材缩不见
- [ ] 旋转时以素材中心为轴，无位置漂移
- [ ] 删除后可撤销恢复

### 4.7 R-MAP-07 画布缩放与平移

**用户故事**
> 作为作者，我希望从"看全大陆"平滑缩到"看清一座城"，不用来回切换工具。

**功能定义**

| 操作 | 交互 |
|---|---|
| 缩放 | 滚轮 / 触控板双指；**以光标位置为锚点** |
| 平移 | 按住空格拖动 / 中键拖动；触控板双指 |
| 范围 | 缩放有上下限（如 10% ~ 800%） |
| 适配 | 提供"适应窗口"与"100%"快捷按钮 |

**关键体验要求**
- 缩放需**连续平滑**（无级），对用户不表现为跳级
- 缩放到远处时自动简化细节，保证帧率（详见 §5.3）
- 缩放锚点必须在光标处，否则体验割裂

**验收标准**
- [ ] 缩放跟手，无肉眼可见卡顿
- [ ] 缩放锚点锁定光标位置（光标下的内容不跑）
- [ ] 平移不出现空白露底（视口外有预取边距）
- [ ] 达到缩放上下限时给出明确反馈（停止而非乱跳）

### 4.8 R-MAP-08 撤销 / 重做

**用户故事**
> 作为作者，我希望误操作能一键回退，像在编辑器里改文字一样。

| 项 | 说明 |
|---|---|

| 首期不做 | 视口（缩放平移）变化**不进**撤销栈 |

**验收标准**
- [ ] 各类编辑操作均可撤销 / 重做
- [ ] 撤销后再做新操作，重做栈正确清空
- [ ] 撤销栈在会话内保持，切图后按图独立

## 5. 关键交互与体验定义

### 5.1 整体布局

```
┌──────────────────────────────────────────────────┐
│  顶栏：地图名称 │ 撤销/重做 │ 适应窗口 │ 导出      │
├────────┬──────────────────────────────┬──────────┤
│ 素材区 │                              │ 属性区   │
│ (素材  │        画  布  区            │ (选中元素│
│  分类) │                              │  的属性) │
│        │                              │          │
└────────┴──────────────────────────────┴──────────┘
```

- 三栏结构：左素材区 / 中画布 / 右属性区
- 左右栏可收起，最大化画布空间
- 所有控件遵循 `AGENTS.md` §6.1.2：**必须使用 Ant Design，禁止原生表单控件**

### 5.2 视口与坐标

- **单一事实源**：`viewport = { x, y, scale }` 统一驱动所有图层
- **缩放锚点**：始终以光标位置为锚点，保持光标下的世界坐标不变
- **世界原点**：设在地图中心，避免深层缩放时的浮点精度抖动
- **坐标换算**：屏幕坐标 ↔ 世界坐标的换算必须是纯函数，必须覆盖单元测试

### 5.2.1 分层渲染的职责边界（关键约束）

地图由**底图层（WebGL）**与**交互层（SVG）**两层合成。为保证两层视觉一致，职责必须严格划分：

| 层 | 负责绘制 | 禁止绘制 |
|---|---|---|
| **底图层** | 底图、地形素材（PNG） | — |
| **交互层（SVG）** | 文字标签、选中框与控制点、连线与连线标注 | **禁止**重复绘制城池/山脉/河流等素材图标 |

**三条硬约束：**

1. **单一变换源**：两层的变换参数必须由同一份 viewport 推出，禁止各自推导
2. **同帧提交**：两层更新必须在同一帧内完成，禁止"先动底图再动 SVG"
3. **文字反向补偿**：标签位置随地图变换，但**字号恒定**（不随缩放变大变小）

> 完整技术方案见 `docs/novel-map-architecture-research.md` §12；坐标换算参考实现见 `docs/novel-map-coord-system.ts`。

### 5.3 缩放时的细节分级（LOD）

对用户表现为**连续无级缩放**，内部按缩放级别调整渲染细节：

| 缩放级别 | 显示内容 |
|---|---|
| 远（看全图） | 底图 + 主要标记（大城市） |
| 中 | 底图 + 全部标记 + 连线 |
| 近（看局部） | 全部内容 + 小标签 + 细节素材 |

- 切换阈值需带**迟滞**（阈值两侧留缓冲），避免临界处反复闪烁
- 小标签在远缩放时隐藏或聚合，防止糊成一片

### 5.4 性能体验底线

| 场景 | 要求 |
|---|---|
| 打开地图 | 1 秒内可交互 |
| 拖拽素材 | 跟手，无延迟感 |
| 缩放平移 | 流畅无卡顿 |
| 2000+ 元素 | 仍可正常编辑（性能指标见 §6） |

## 6. 性能需求

### 6.1 性能指标（验收基线）

| 指标 | 目标值 |
|---|---|
| 首屏可交互（含底图） | < 1s |
| 2000+ 元素全量就绪 | < 3s |
| 拖拽 / 平移帧率 | ≥ 55fps |
| 缩放帧率 | ≥ 55fps |
| 单次交互响应（选中 / 拖动） | < 16ms |
| 峰值内存（含纹理资源） | < 500MB |

### 6.2 性能约束下的设计要求

1. **元素规模**：必须支持 2000+ 元素（底图素材 + 标记 + 连线合计）同时存在且流畅编辑
2. **只渲染可见部分**：视口外的元素不参与渲染（视口裁剪）
3. **资源预切分**：底图与素材需在构建期预处理（图集打包 / 瓦片切分），运行时不承担解码压力
4. **按需加载**：大体积资源分块加载，不一次性载入全部

> 具体技术方案见 `docs/novel-map-architecture-research.md`。

## 7. 数据模型

### 7.1 数据表

```sql
novel_maps(
  id          INTEGER PRIMARY KEY,
  work_id     INTEGER NOT NULL,      -- 归属作品
  name        TEXT    NOT NULL,      -- 地图名称
  content     TEXT,                  -- JSON 画布文档
  created_at  TEXT,
  updated_at  TEXT
)
```

**`content` JSON 结构：**

```jsonc
{
  "version": 1,                      // 文档版本号，便于后续迁移
  "baseImage": {                     // 底图（R-MAP-02）
    "src": "builtin:world-01",
    "x": 0, "y": 0, "scale": 1
  },
  "terrains": [                      // 地形素材（R-MAP-03/04）
    {
      "id": "t1",
      "sprite": "mountain-03",       // 素材标识
      "x": 120, "y": 340,
      "scale": 1.2, "rotation": 0,
      "z": 1                         // 层级
    }
  ],
  "markers": [                       // 地点标记（R-MAP-05）
    {
      "id": "m1",
      "type": "city",                // city|pass|village|sect|custom
      "name": "青云城",
      "x": 500, "y": 220,
      "entityId": null               // 迭代：绑定要素 id（R-MAP-12）
    }
  ],
  "edges": [                         // 连线（R-MAP-06）
    {
      "id": "e1",
      "from": "m1", "to": "m2",
      "label": "三千里"
    }
  ],
  "viewport": { "x": 0, "y": 0, "scale": 1 }
}
```

### 7.2 数据原则

| 原则 | 说明 |
|---|---|
| 单文档 JSON | 整张地图存一条记录，避免大量小表关联 |
| 版本号 | `content.version` 用于后续结构升级与迁移 |
| 大资源外置 | 底图与素材图片**不入库**，只存标识/路径 |
| 增量保存 | 编辑期间防抖保存，避免频繁写库 |
| 崩溃可恢复 | 复用编辑器既有快照与恢复机制 |

### 7.3 工程约定（对齐既有规范）

- 写操作需返回是否实际写入（供乐观更新补偿）
- 加载与保存需防并发竞态（快速切图场景）
- 删除作品时，需先删地图再删关联要素，避免悬挂引用

## 8. 分期路线

### 8.1 分期总览

| 阶段 | 内容 | 目标 |
|---|---|---|
| **v1 · 最小可用** | R-MAP-01 ~ 09 | 跑通"选底图 → 拖素材 → 加标记 → 连线 → 导出"闭环 |
| **v2 · 效率增强** | R-MAP-10 ~ 12 | 图层管理、素材库面板、要素绑定 |
| **v3 · 设定融合** | R-MAP-13 ~ 15 | 导出设定文档、多图管理、搜索定位 |

### 8.2 v1 实施步骤建议

1. **资源准备**：确定底图与素材规格，完成资源预处理管线
2. **数据层**：`novel_maps` 表 + 加载/保存 IPC
3. **画布内核**：视口 + 缩放平移 + 渲染管线
4. **编辑能力**：素材添加/拖动/缩放/旋转；标记与连线
5. **交互完善**：撤销重做、选中态、快捷键
6. **导出**：PNG 导出与本地落盘
7. **性能验证**：以 2000+ 元素压测，达成 §6.1 指标

> 每步独立可交付、可验收，避免一次性大规模提交。

## 9. 风险与应对

| 风险 | 等级 | 应对 |
|---|---|---|
| **范围蔓延为"绘图软件"**——地形笔刷、自由曲线、特效等不断加码，导致工期失控且偏离"示意图"定位 | **高** | 严守 §2.4 非目标；新增绘图类功能必须有使用数据支撑并单独立项 |
| PNG 素材规格与架构不匹配（尺寸/格式/数量超预期） | **中高** | 需求侧尽早锁定资源规格清单（见 §10） |
| 性能不达标（2000+ 元素卡顿） | **中** | 先做资源预切分与视口裁剪；架构方案已预留优化路径 |
| 双渲染层（底图 + 交互层）同步不一致 | **中** | 单一 viewport 事实源驱动，坐标换算纯函数化 + 单测覆盖 |
| 用户不满足于"示意图"，要求精美插图 | **中** | 定位上明确取舍；如确有强需求，评估接入 AI 生成图作为底图的可能 |
| 地图数据丢失 | **中** | 复用增量快照与崩溃恢复机制 |

## 11. 术语表

| 术语 | 含义 |
|---|---|
| 底图 | 铺在画布最底层的整张地形图 |
| 素材 / 地形素材 | 可拖拽摆放的 PNG 小图（山、树、城池等） |
| 标记 | 带名称的地点点位（城池、关隘等） |
| 连线 | 两个标记之间的路线，可带文字标注 |
| 视口 (viewport) | 当前可见的画布区域，由 x/y/scale 定义 |
| LOD | 细节分级，随缩放级别调整渲染精细度 |
| 无级缩放 | 用户感知上的连续平滑缩放（内部可分级） |
