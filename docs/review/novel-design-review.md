# Novel（小说）模块 · 设计师视角审查报告

> 审查范围：CheckIn 桌面端的 novel 子域（`src/windows/NovelWindow/**` 及 `src/shared/components/{CharacterPack, SettingCenter, WindowHeader, ThemeSwitcher}/**`、`src/shared/theme/**`）。
> 审查基线：`6cdcde2 fix: 敏感词识别bugfix` 所在的工作树。
> 结论结构：每项统一「现状 → 问题 → 影响 → 建议 → 优先级」。文末附短期可落地改进项汇总。

---

## 0. 范围校正（务必先读）

本报告在正式下笔前对审查对象做了一次事实校正，避免"对着不存在的模块空谈"：

- 这里的 **novel 域是一个「小说写作 / 码字」工具**，不是阅读 App。它没有书城、没有书籍分类货架、没有独立"阅读器"、没有订阅付费、没有评论区。
- 实际存在且可审查的界面形态是：**书架主页（BookshelfPage）** 与 **编辑器（NovelPage）** 两大视图（`App.tsx` 用 `display` 切换、编辑器懒挂载后常驻），外加三个独立窗口 **行囊（PackWindow）/ 全局设定中心（GlobalSettingWindow）/ 关系网络（RelationWindow）**。
- 因此本报告谈"阅读器交互"时，对应的是编辑器里 **CodeMirror 6 正文区（EditorPane）的"阅读/码字"体验**，而非翻页式阅读器；谈"翻页/目录跳转"对应的是**章节树 + 章节跳转（ChapterJumpPalette）+ 续写位置恢复**。

## 1. 界面一致性（配色 / 间距 / 排版）

### 1.1 主题体系完整但"护眼/阅读底色"是缺位的
- **现状**：`src/shared/theme/themes.ts` 定义了 4 套主题（柔雾紫蓝 aurora / 奶油暖橘 cream / 薄荷清新 mint / 月夜暗色 midnight），通过 `--app-*` 令牌贯穿三窗口；正文底色 `EditorPane` 写死 `backgroundColor: "var(--app-surface)"`，编辑设置抽屉（`SettingsDrawer`）里**没有**独立的"阅读底色 / 护眼模式"开关，注释明确写着"阅读底色不在这里提供——跟随主窗口主题"。
- **问题**：码字/长读场景的底色只能靠"换整套主题"来变，而主题色相是**带颜色的**（蓝紫 / 暖橘 / 薄荷），不是"纸张感"的护眼底色。所谓"护眼"只有 midnight 的暗色这一条路，缺了"米黄/豆沙绿护眼纸面"这类介于亮暗之间的中间态。
- **影响**：作者想"白天用护眼纸面、晚上用暗色"做不到，只能二选一；护眼诉求与"我喜欢某套主题的品牌色"冲突，被迫牺牲一个。
- **建议**：把"阅读底色"从主题中解耦，做成正文区的独立维度：`纸面底色（跟随主题 / 米黄 / 豆沙绿 / 纯白）+ 暗色` 的独立开关（可放 `EditorSettings` 持久化），与 `fontSize/lineHeight` 并列在排版抽屉。
- **优先级**：P1

### 1.2 字号与排版参数已覆盖，但"字体"层是空的
- **现状**：`SettingsDrawer` 提供字号（14–24px）、行距（1.4–2.4）、段间距（0–1.6em）、首行缩进开关、今日目标、字数口径、章节/卷序号后缀等；`novel-config.ts` 的 `DEFAULT_SETTINGS` 给出中文排版默认值（17px / 1.9 / 0.6 / 缩进开）。正文用 `var(--nv-paper-font, inherit)`。
- **问题**：没有**正文字体**选择（宋体 / 黑体 / 衬线），`--nv-paper-font` 默认 `inherit` 落在系统 UI 字体上；长文阅读/码字场景下衬线字体对中文正文的识别度与"纸感"更好，当前统一走无衬线。
- **影响**：排版"够用但没到写作工具该有的手感"，字体这一核心排版维度缺失，是写作者的高频诉求。
- **建议**：在排版抽屉补一档"正文字体"（系统宋体 / 黑体 / 无衬线三类即可，需在 `get_available_fonts` 里确认可用字重），落到 `--nv-paper-font`。
- **优先级**：P1

### 1.3 行内间距单位混用（px / em / 无单位）
- **现状**：字号用 `px`，行距 `lineHeight` 用**无单位数字**（1.9），段间距用 `em`，缩进用 `2em`。三者在 `SettingsDrawer` 里并列展示，单位不统一。
- **问题**：行距无单位、段间距有单位，且 UI 文案里 `{settings.lineHeight.toFixed(1)}` 不带单位、段间距带 `em`，同一面板两种标注习惯，视觉与心智模型不一致。
- **影响**：用户难以判断"1.9"与"0.6em"哪个大，调参靠猜；文案层面也不统一。
- **建议**：展示层统一带单位（行距也标"×"或"倍"），或内部统一为 em 并同步文案。
- **优先级**：P2

### 1.4 antd 组件与自研面板的色板已对齐，但存在"两套齿轮"的心智负担
- **现状**：顶栏同时有「小说设定」（`bookSettingSvg` 书图标，`data-tour-target="topbar-setting"`）与「排版与偏好」（`ControlOutlined` 滑杆），注释明确说明"与标题栏的设置（全局：外观/账号）区分，图标用滑杆而非齿轮，避免同屏两颗齿轮"。
- **问题**：三处"设置"（窗口标题栏全局设置 / 顶栏小说设定 / 顶栏排版偏好）对新手仍有辨识成本；`SettingsWindow` 与 `SettingsDrawer`、`SettingCenter` 的命名在代码与界面里各自为政。
- **影响**：功能入口分散，首次使用者容易点错位置；帮助引导（红点 / Tour）承担了本该由信息架构解决的负担。
- **建议**：短期不动，但建议在全局设置里做一次"设置项归位"评审，把「排版偏好」明确为"本书排版"，与"小说设定（世界观/等级体系）"语义对齐。
- **优先级**：P2

## 2. 阅读器 / 码字区交互

### 2.1 无独立"阅读模式"，正文永远处于"可编辑"状态
- **现状**：`EditorPane` 是 CodeMirror 6 纯文本编辑器，整个正文区始终是"打字态"（光标、撤销栈、标注层、敏感词层、右键建卡菜单全都常驻）。有"专注模式（F11）"（`focusMode` 只收起左右栏与顶栏/状态条），但**不是**只读阅读态。
- **问题**：作者想"从头通读一遍自己的稿子"时，会不断触发光标闪烁、误触改字、hover 出悬浮资料卡；没有"只读预览 / 阅读模式"，通读体验被打断。
- **影响**：这是写作工具与"自审"之间的核心体验缺口——写完想读一遍是最高频的动作，却只能在编辑态里别扭地完成。
- **建议**：加一个"阅读/预览"开关（可并入专注模式或独立）：只读化正文（禁改）、关闭光标与右键建卡、可选隐藏标注高亮，Esc 退出。与"护眼底色"（见 1.1）天然组合。
- **优先级**：P0

### 2.2 "翻页"不存在，靠章节树/跳转/滚动，但缺"章节内目录/标题锚点"
- **现状**：章节导航有章节树（`ChapterTree`，左栏卷-章层级）+ 章节跳转面板（`ChapterJumpPalette`）+ 大纲面板（`OutlinePanel`，右栏）。无"上一章/下一章"的正文内翻页按钮，也无章节内的小标题锚点。
- **问题**：长章（CodeMirror 虚拟滚动天然支持三万字章节）内部没有结构锚点，通读时只能滚动；"上一章/下一章"要回到左栏点，割裂了连续阅读流。
- **影响**：连续阅读/校对效率低；章内结构（小标题、分节）无法定位。
- **建议**：① 正文区底部/侧边加"上一章 / 下一章"快捷切换（读完整章一键续）；② 若章内支持 Markdown 标题或分节，在大纲面板同步展示可点击锚点。
- **优先级**：P1

### 2.3 续写位置恢复做得细，但"目录跳转后位置"不跨章节记忆
- **现状**：位置记忆（R6）实现完善——`EditorPane` 记 `cursor + scrollTop`，切章滚顶、启动恢复上次位置，`RestorePosition` 一次性消费；滚动复位用 rAF 规避旧高度夹取，注释详尽。
- **问题**：位置记忆是"整本书一个续写点"（书架 Hero 的 `hero.chapterId`），**不是"每章各自记进度"**。跳去看另一章再回来，回到的是章顶而非上次读到的位置。
- **影响**：校对/对照阅读时频繁跳章，每次都要重新找位置；"断点续读"只对"上次最后写的那一章"有效。
- **建议**：位置记忆按章节粒度存（`chapterId → {cursor, scrollTop}`），切章即存、回来即恢复；与现有 R6 恢复机制复用同一套。
- **优先级**：P1

### 2.4 敏感词高亮 / 标注层与阅读体验的张力
- **现状**：要素标注层（人名/地点/势力/道具高亮 + 悬浮卡）与敏感词高亮层常驻正文，可整体关（状态条"标注 开/关"），但两者是**同一颗总开关**下强耦合的视觉噪声来源。
- **问题**：通读时满屏高亮 + hover 弹卡 + 敏感词红标，视觉负担重；关闭总开关会连"人名识别"这个写作时真正有用的能力一起关掉。
- **影响**：标注层是写作辅助利器，但在"读稿"场景反而成为干扰，且无法只关"敏感词"这一层。
- **建议**：让要素标注层与敏感词层**独立开关**（当前敏感词层其实有自己的 `sensitiveOn`，但 UI 上没给独立入口，仅靠敏感词面板 mode 控制），并在阅读模式下默认弱化两者。
- **优先级**：P2

## 3. 加载态 / 空状态 / 异常反馈

### 3.1 书架三态已严格区分，值得肯定
- **现状**：`BookshelfPage` 明确区分 `loading && !bundle`（"正在载入书架…"）、`!bundle && loadError`（`role="alert"` + 重试按钮）、空书架欢迎态（新建/导入入口）。注释明说"失败绝不能落进空态，否则用户以为数据丢了"。
- **问题**：编辑器侧（`NovelPage` / `useNovelData`）没有对等的"装载失败"态——`data.loading` 有，但失败反馈主要靠 toast 与状态条"保存失败，待重试"，缺一个覆盖主内容区的失败 + 重试界面。
- **影响**：编辑器数据加载失败时，用户可能面对空白正文区而不知是"没章节"还是"加载崩了"。
- **建议**：给编辑器补一个与书架同构的 `loadError` 失败态（`role="alert"` + 重试），与空态（`no-work` / `no-chapter`，已有）并列三态。
- **优先级**：P1

### 3.2 保存态反馈细腻，但"失败"的可恢复感不足
- **现状**：顶栏保存态 `SAVE_STATE_TEXT` 五态（待输入/输入中/保存中/已保存/保存失败待重试），30s 兜底 + 关窗 flush + `needsFlushSave` 判 pending/failed，工程上非常稳。
- **问题**：失败时只有顶栏一小格文字变红，没有可点击的"立即重试"入口，也没有失败原因（磁盘满 / 权限）提示。
- **影响**：用户看到"保存失败"却不知下一步，只能干等 30s 兜底。
- **建议**：保存失败态做成可点击（点击即 `flushSave()`），并区分"重试中 / 仍需人工处理（如磁盘满）"两类提示。
- **优先级**：P2

### 3.3 导入有阶段性反馈，导出/删除缺统一"进行中"视觉
- **现状**：导入书籍（TXT/DOCX）有 `importing` + `importPhase` 分阶段反馈（顶栏按钮 loading），做得细致。但导出（作品/卷/章/设定 JSON/MD）与删除操作多为"点击后 fire-and-forget"，靠 toast 或确认弹窗兜底，无进行中态。
- **影响**：大书导出耗时可能较长，无反馈会让用户以为没点中。
- **建议**：导出走与导入一致的"进行中"态（按钮 loading 或进度），删除保留确认弹窗即可。
- **优先级**：P2

## 4. 可访问性（a11y）

### 4.1 语义与 ARIA 基础良好，但覆盖不完整
- **现状**：顶栏图标按钮普遍有 `aria-label`、`aria-pressed`、`aria-busy`；进度条有 `role="progressbar"` + `aria-valuenow/min/max`；空态/错误用 `role="alert"`；视图切换用 `aria-hidden`。这些是好底子。
- **问题**：① 关键交互依赖**颜色**传达（保存态红/绿点、要素类型用颜色区分、敏感词角标转警示色），没有文字/形状冗余，色觉障碍用户无法区分；② 部分纯图标按钮（如关闭 `✕`、若干 `SvgIcon`）的 `aria-label` 是否齐全需逐一核对；③ 悬浮资料卡（HoverEntityCard）与右键菜单（EntityContextMenu）无键盘可达路径，纯键盘用户无法使用。
- **影响**：键盘与屏幕阅读器用户在这几个高频交互上被挡住。
- **建议**：① 为颜色语义补文字/图标冗余（保存态已有文字，主要是要素类型色、敏感词角标）；② 全量核对图标按钮 `aria-label`；③ 悬浮卡/右键菜单补键盘等价入口（如选中词后 `Enter` 打开详情）。
- **优先级**：P1

### 4.2 焦点管理在浮层/抽屉间有遗漏
- **现状**：设定中心、类型管理用 antd Modal（自带焦点圈定）；快照/排版用无遮罩抽屉（`SettingsDrawer` / `SnapshotDrawer`），靠文档级 `mousedown` 分流关闭。
- **问题**：无遮罩抽屉打开时焦点不圈定、不自动移入、关闭后焦点不回源按钮，键盘 Tab 会"穿透"到被抽屉盖住的下层元素。
- **影响**：键盘用户在抽屉打开后导航混乱。
- **建议**：抽屉打开时 `focus` 到抽屉内首个可聚焦元素、关闭时回焦到触发按钮；补 `aria-modal`/焦点陷阱（若保持无遮罩，至少做焦点管理）。
- **优先级**：P2

## 5. 移动端 / 小屏适配

### 5.1 已做"小屏自适应收起左栏"，但本质仍是桌面工具
- **现状**：`useNovelViewState` 有 `minStageWidth: 560` 的小屏自适应——三栏放不下时自动收起左栏并 toast 提示（"窗口较窄，已收起章节树"），右栏永不自动收。这是**窗口尺寸**级适配，不是移动端适配。
- **问题**：产品是 Electron 桌面应用，**没有移动端目标**；因此本报告的"移动端适配"结论是：**当前无移动端，属明确的产品边界而非缺陷**。若未来要出移动端，正文区（CodeMirror）与三栏布局、右键菜单（触屏无右键）、hover 悬浮卡（触屏无 hover）都需要重新设计。
- **影响**：无（当前形态下）；但需在 PRD 层面明确"是否要移动端"。
- **建议**：列为待产品确认问题（见产品报告），不在本报告展开。
- **优先级**：P3（待确认）

### 5.2 字号范围对高 DPI / 长时使用偏窄
- **现状**：字号上限 24px，行距上限 2.4。
- **问题**：高分辨率屏（如 4K）下 24px 仍偏小，长时写作用户常需要更大字号。
- **建议**：字号上限放宽到 32px+，或提供"缩放步进"。
- **优先级**：P2

## 6. 其它视觉细节（抽查结论）

- **正文字号/行距/段间距热更新**：`stylingCompartment` + `buildTheme` 独立 compartment，改字号不重建编辑器，体验流畅（好）。
- **章节树 / 右栏宽度持久化**：右栏宽度防抖 300ms 落库、卸载兜底，做得细（好）。
- **顶栏按钮"点了没反应"的防护**：`packOpening` / `globalSettingOpening` 的"正在打开…"态 + 8s 兜底，体现了对反馈时延的重视（好，可复用到其它慢操作）。
