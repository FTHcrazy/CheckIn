## 0 盘点口径

**范围**：NovelWindow 本体三个视图（书架 / 编辑器 / 回收站）+ 由它唤起的 3 个独立窗口
（行囊 / 人物关系网络 / 全局设定中心）。`MapWindow` 属独立数据域（`map.db`），仅有入口，
不在本文展开。

**计数单位**：一个「用户可独立触发、并产生可见结果」的能力点 = 1 项。
同一动作的批量版不另计（如「批量恢复」并入「恢复」）；纯展示文案不计数。

**状态定义**：
| 标记 | 含义 |
|---|---|
| 可用 | 无前置条件，主路径通 |
| 条件可用 | 依赖 AI 配置 / 版本（lite 无 novel 域 / AI 总开关） |
| 局部可用 | 主路径通，但反馈或兜底不全（本文 §4 逐条标注） |
| 占位 | 入口存在但明确「未上线」 |

**总量**：NovelWindow 本体 **99 项** + 关联独立窗口 **3 项** = **102 项**；
另有 11 条全局快捷键（`src/shared/shortcuts`）。

## 1 分域数量与场景覆盖

| 域 | 项数 | 覆盖的主要场景 |
|---|---|---|
| 作品与书架 | 17 | 开新书、搬库（导入）、多书管理与检索、回访续写 |
| 章节与卷 | 11 | 结构搭建、顺序调整、定位跳转、章节级 AI 入口 |
| 正文编辑与排版 | 23 | 码字、校对（查找替换/快照）、通读（阅读模式）、排版偏好 |
| 资料库（要素 8 + 设定 8） | 16 | 人物/地点/势力/物品建模、境界阶梯维护、跨书复用 |
| 写作辅助 | 7 | 结构规划（大纲/伏笔）、随手记、查资料、起名、合规自查、一致性校对 |
| AI 创作 | 12 | 生成（起名/续写/变换/润色/阶梯）、理解（摘要/抽取/关系推断）、治理（授权/开关/记录/用量） |
| 数据安全 | 6 | 误删反悔、换机迁移、事故恢复 |
| 引导与帮助 | 4 | 首跑上手、长期查功能、弱提示 |
| 设置与外观 | 3 | 全局偏好、本书排版、主题 |
| 关联独立窗口 | 3 | 主角状态盘点、关系可视化、跨书设定共享 |

**场景判断**：从「写第一章」到「写完导出」的全链路是闭合的——建书 → 建卷章 → 码字 →
建卡 → 设定 → 大纲/伏笔 → 自查 → 快照 → 导出/备份，每一环都有入口，没有断头路。
薄弱点不在「有没有」，而在「找不找得到、看不看得懂」（见 §4）。

## 3 对两份旧 review 的核销

只列旧结论中**已被推翻或已闭环**的项，避免后续读者按旧报告重复提需求。

| 旧结论（基线 `6cdcde2`） | 现状 | 证据 |
|---|---|---|
| 无阅读模式，正文永远可编辑 | **已闭环**：阅读模式 + 章首尾续滚翻章 | `SettingsDrawer`「阅读模式」开关；`EditorPane` `buildReadMode` + `onLoadPrev/NextChapter` |
| 护眼底色无法脱离主题 | **已闭环**：护眼纸质感独立开关 | `DEFAULT_SETTINGS.paperTexture` |
| 缺正文字体选择 | **已闭环**：FontPicker + 字体下载 | `usePaperFonts`、`--nv-paper-font` |
| 无备份、删除不可逆（P0） | **已闭环**：全量备份/恢复 + 回收站 30 天 | `DataSafetyModal`、`RecycleBinPage`、`novel-safety-handlers.ts` |
| 章节树疑似未虚拟化 | **已闭环**：已虚拟化 | `ChapterTree` 使用 Virtuoso |
| 敏感词层与标注层强耦合 | **部分闭环**：敏感词有独立 mode 与面板，但状态条上它是「计数入口」不是「层开关」 | `useSensitiveStore.config.mode`、`StatusBar` |
| 每章独立位置记忆 | **仍开放**：单点记忆 | `useNovelData.lastPosition` 单键 |
| 编辑器缺装载失败态 | **仍开放**：仅 2.4s toast | `useNovelPage.ts:214` 只 `showToast`；书架侧有常驻 `role="alert"` + 重试 |
| 保存失败不可点击重试 | **仍开放**：仅文字变红 | `NovelTopBar` 保存态只渲染文本 |
| 抽屉焦点管理缺失 | **仍开放**：无遮罩抽屉不做焦点圈定 | `SettingsDrawer` / `SnapshotDrawer` 均靠文档级 `mousedown` |
| EPub/排版 DOCX 导出、跨书检索、产品埋点 | **仍未落地**，属能力缺口而非界面调优 | 本文 §5 不纳入 |

字段说明：**价值**＝对核心用户（长篇连载作者）的实际影响；**成本**＝改动面
（XS ≤ 单文件文案/样式；S ≤ 单组件；M ≤ 跨组件/需改状态模型；L 需改数据层）。

### O-01 三处「设置」语义未归位

| 项 | 内容 |
|---|---|
| 现状 | 同屏三个设置入口：窗口标题栏「设置」（全局：外观/账号）、顶栏书图标「小说设定」（设定中心）、顶栏滑杆「排版与偏好」。代码注释自承「避免同屏两颗齿轮」。 |
| 维度 | 信息组织 / 心智模型 |
| 问题 | 三者命名不同源（设置 / 小说设定 / 排版与偏好），用户无法从名字判断该进哪个；「小说设定」与「设定中心」在帮助文档里是两个词，界面与文档各说一套。 |
| 可改进 | ①「小说设定」文案统一为「设定中心」（与帮助文档、快捷键说明一致）；②顶栏三颗按「本书内容 / 本书外观 / 应用设置」语义分组并加分组线；③设置窗口里给「本书排版」一个跳转。 |
| 影响范围 | 所有进入编辑器的用户，首屏即遇到 |
| 预期收益 | 消除一类必然发生的误点；把 6 步引导里「靠引导补 IA」的负担还回结构本身 |
| 价值 / 成本 | 中 / S |
| 优先级 | P1 |

### O-02 顶栏 6 颗无文字图标、异质功能平铺

| 项 | 内容 |
|---|---|

| 维度 | 视觉设计 / 认知负担 |

| 可改进 | 保留 3 颗高频（章节栏、支撑面板、排版），行囊/快照/设定收入「更多」溢出菜单或并入作品管理菜单；低频入口以文字形态出现在菜单里。 |
| 影响范围 | 编辑器全场景 |
| 预期收益 | 首屏可扫读；为后续入口增长留位 |
| 价值 / 成本 | 中 / M |
| 优先级 | P2 |

### O-03 右栏「工具」Tab 造成三层深度

| 项 | 内容 |
|---|---|
| 现状 | 五 Tab（大纲/要素/灵感/检索/工具）→「工具」进启动器 → 6 张卡 → 再进二级面板，头部靠左箭头返回。工具是低频能力，却占 1/5 Tab 位与两级导航。 |

| 可改进 | 把工具收成面板头的一颗图标（抽屉或浮层），五 Tab 变四 Tab；二级面板保留滑入动画，标题显示「工具 / 敏感词检测」面包屑而非只换标题。 |
| 影响范围 | 右栏全部使用路径 |
| 预期收益 | 主 Tab 只留高频，减少一次「进去再出来」的往返 |
| 价值 / 成本 | 中 / M |
| 优先级 | P2 |

### O-04 章节树与大纲面板双份卷章列表

| 项 | 内容 |
|---|---|
| 现状 | 左栏 `ChapterTree`：搜索、状态点、拖拽、AI 摘要入口；右栏 `OutlinePanel`：同一批卷章 + 一句话梗概 + 伏笔。两处都能点章节跳转。 |

| 问题 | 「我要找第 12 章」时应看哪边没有答案；两份列表在滚动位置、选中态上各记一份，容易不一致。 |
| 可改进 | 明确分工并在视觉上区分：左树＝导航（只标题 + 状态），右板＝结构编辑（只梗概 + 伏笔，标题降为次级信息）；两处点击行为统一为「跳转 + 同步展开」。 |
| 影响范围 | 所有建纲、校对场景 |
| 预期收益 | 减少一次「两边对不上」的困惑；右板回归「写梗概和伏笔」本职 |
| 价值 / 成本 | 中 / S |
| 优先级 | P1 |

### O-05 阅读模式入口过深、无快捷键

| 项 | 内容 |
|---|---|
| 现状 | 阅读模式是「排版与偏好」抽屉第二块里的一个 Switch；`SHORTCUTS` 里没有它。功能本身已完整（只读 + 隐藏光标 + 章首尾续滚翻章）。 |
| 维度 | 交互流程 |
| 问题 | 「写完通读一遍」是最高频的自审动作，却要走「开抽屉 → 找到开关 → 关抽屉」三步，且没有任何键位提示。 |
| 可改进 | 状态条或顶栏给一颗可见的「读」开关（与专注模式并列语义）；注册快捷键（如 F12 / Shift+F11），并在帮助中心「快捷键」分区补一行。 |
| 影响范围 | 全写作周期的通读/校对 |
| 预期收益 | 把已建成的能力从「知道才有」变成「顺手就用」，直接提升自审频率 |
| 价值 / 成本 | 高 / XS |
| 优先级 | P0 |

### O-06 AI 入口 7 处、4 种交互形态，无统一标识

| 项 | 内容 |
|---|---|
| 现状 | 续写＝正文右下悬浮按钮；润色/变换＝选中右键；摘要＝章行闪电；抽取＝工具二级面板；关系推断＝独立窗口顶栏；等级生成＝设定中心卡头；起名＝工具面板。共 7 个入口、4 种形态。 |
| 维度 | 视觉设计 / 心智模型 |
| 问题 | 作者无法形成「AI 在哪、能干什么」的整体印象；同一能力在不同位置长得完全不一样，也没有统一的「这是 AI」视觉信号（除总开关关闭时整块消失这一反向信号）。 |
| 可改进 | 统一 AI 视觉语言：同一颗图标（现有闪电）× 同一强调色 × 同一「需授权 / 可用 / 不可用」三态样式；帮助中心「AI 创作助手」分区已是唯一解释入口，界面上的 AI 元素回指该分区。 |
| 影响范围 | 8 个 AI 能力、全部入口 |
| 预期收益 | 认知成本从「记 7 个位置」变为「认 1 个标记」；也便于 AI 不可用时统一说明原因 |
| 价值 / 成本 | 中 / S |
| 优先级 | P1 |

### O-07 编辑器装载失败只有一次性 toast

| 项 | 内容 |
|---|---|
| 现状 | `useNovelData` 有 `loadError`，但 `useNovelPage.ts:214` 只把它 `showToast(…, "warning")`——2.4s 后消失；正文区仍显示空态。书架侧是另一个标准：常驻 `role="alert"` + 重试按钮。 |
| 维度 | 交互流程 / 心智模型 |
| 问题 | 加载失败 → toast 闪一下 → 空白正文 → 用户无法区分「这本书没章节」和「数据没读出来」，而后者会被误判成丢稿。 |
| 可改进 | 编辑器补一个与书架同构的失败态（覆盖正文区、`role="alert"`、带重试），与已有 `no-work` / `no-chapter` 空态并列成三态；toast 保留作为副反馈。 |
| 影响范围 | 数据装载异常时（低频、高后果） |
| 预期收益 | 把「以为丢稿」的恐慌转化为一次明确的重试动作 |
| 价值 / 成本 | 高 / S |
| 优先级 | P1 |

### O-08 保存失败不可点击重试、无原因

| 项 | 内容 |
|---|---|
| 现状 | 保存态五态（待输入/输入中/保存中/已保存/失败待重试）做得细，但顶栏只有一格文字变红，没有点击动作，也不说失败原因。 |
| 维度 | 交互流程 |
| 问题 | 用户看到「保存失败」却无处可点，只能等 30s 兜底；磁盘满这类需要人工处理的原因永远不会被说明。 |

| 影响范围 | 所有保存异常 |
| 预期收益 | 把被动等待变成主动恢复；数据焦虑降低 |
| 价值 / 成本 | 中 / S |
| 优先级 | P1 |

### O-09 状态条 7 项信息、32px 内密度过高

| 项 | 内容 |
|---|---|
| 现状 | 本章字数 / 今日新增 / 字每分钟 / 标注开关 / 敏感计数 / 目标进度 / 时钟，全部常驻。 |
| 维度 | 视觉设计 / 认知负担 |

| 影响范围 | 码字全程 |
| 预期收益 | 一屏内可读；信息密度与重要性重新对齐 |
| 价值 / 成本 | 中 / S |
| 优先级 | P2 |

## 6 明确不纳入本文的范围

以下属**能力缺口**而非界面调优，且未经产品确认，本文不展开、也不作为缺陷描述：

- 每章独立位置记忆（现为单点续写）——旧 review 已列，属功能补强。
- EPUB / 排版后 DOCX 导出、EPUB / Markdown 导入。

- `MapWindow` 的功能盘点（独立数据域，另有专项文档）。
- AI 能力扩展（新增意图、多轮对话等）。
