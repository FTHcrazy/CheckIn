# 地图：与逆向目标（易制地图 / makeamap）的交互与体验差距审查

> 状态：**审查稿**（含未闭环待办，清空后归档）
> 输入：`docs/prd/prd-map-render/`（7 篇）、WorkBuddy 资料库《makeamap_渲染逻辑分析.md》、
> 2026-09-28 / 10-30 项目内竞品调研记录、`docs/novel-map-prd.md`（v1，R-MAP-01~15）
> 基线：**2.18.0**，代码基线 `MapWindow/pages/MapEditorPage/`（map2 线）

---

## 0. 结论

**渲染已经对齐了九成，差的那一成不在渲染，在「内容」。**

- **渲染参数**（海陆二分 / 海岸三件套 / 区块降级 / 文字白描边 / 三档风格 / 烘焙 / 无级缩放 / 分块导出）与逆向目标基本同级，个别项（无级缩放 0.1~8、近处不糊）已经超过它。**这一块不要再改参数了。**
- **真正拉开差距的是三件事**：① 素材体系（逆向 ~60 个图集 / 我们 5 张 PNG）；② 生成器落到哪一层（逆向一次点击产出**可编辑的多类对象 + 自动命名**，我们只产出**一块陆地 + 一树编号区块**）；③ 交互范式（逆向是「放置态 → 选中态 + 右侧属性面板 + 图层树」，我们是「一排工具栏按钮」）。
- **一句话**：逆向目标的"好看"不是画出来的，是**摆出来的**；我们的"不好看"不是渲染不够，是**没东西可摆、也没法摆**。

因此本审查给出的优先级是：**生成器分层落对象 > 素材体系 > 属性面板与图层 > 继续调渲染参数（最低）**。

## 2. 逆向目标的交互模型还原

### 2.1 一次会话的任务流（B + C）

```
新建工程（选页面尺寸 A4）
  → 选底图（高德截图 / 纯色 / 图片层）
  → 「架空大陆自动生成器」一键出图          ← 核心体验，见 §2.4
  → 手动微调（放置态摆符号 / 选中态改属性）
  → 换风格（魔幻 / 仙侠 / 羊皮纸，整层色相变换）
  → 输出图片（分块拼接，最大到打印级）
  → 保存（服务端 map_id，下次打开接着改）
```

关键点：**"出一张图"和"改一张图"是两个阶段，且第一阶段就要出成品**。生成之后立刻是一张能看的地图，手动微调是"锦上添花"，不是"从空白开始搭"。

### 2.2 三栏信息架构与动作分工（B）

| 区域 | 内容 | 心智 |
|---|---|---|
| 顶栏 | 撤销 / 恢复 · 上移下移 · 上架展示 · 转为星球 · 发布 · **输出图片** · **保存** | 全局动作 + 出口，永远可达 |
| 左栏（四组） | 底图 / 画笔 / 要素 / **图层** / 页面尺寸 | "我用什么画" + "画在哪一层" |
| 右栏 | **属性面板**（选中对象的样式全量） | "这个对象长什么样" |
| 画布 | 单一 canvas + DOM 覆盖层（选择框 / 文字输入 / 坐标尺） | 画布只负责画 |

对照当前：**顶栏只有一排图标 + 两个生成按钮 + 导出**；**没有右栏属性面板**；**没有图层**。三栏里缺两栏。

### 2.3 两个状态机：放置态 / 选中态（B）

```
放置态：点工具 → 光标变 → 画布单击落一个对象 → 继续单击继续落 → Esc 退出
选中态：单击对象 → 出现节点控制点 + 右侧属性面板 → 改样式 / 拖节点 / 删
快捷键：Delete、Ctrl+D 删除 · Ctrl+C/V 连续粘贴 · 方向键或 WASD 微移 · 置顶置底
```

这是**绘图软件的通用心智**（与 PS / Figma / AI 同构），用户零学习成本。它的价值不在快捷键本身，而在于：**任何对象都能被"选中 → 看到它的全部属性 → 改"**。

当前只有"放置"的一半（点素材 → 画布落位 → Esc 退出 ✅），**没有"选中 → 属性面板"这一半**：选中素材后，工具栏只多出一个「地名」输入框，不能改尺寸、旋转、透明度、颜色、层级。

### 2.4 自动生成器：一次点击产出什么（A + B + C）

**素材命名本身就是证据**（A，§16）：

```
自动生成山脉00 … 自动生成山脉029        30 种
自动生成山脉_丘陵00-03 / _沙丘00-02 / _雪山00-05
自动生成城市00 … 自动生成城市09        10 种
自动生成森林0_1_0 / 0_2_0 / 0_3_0      3 档密度
自动生成村镇0 / 自动生成港口0
```

配合另外三条实测（A）：

1. **生成即分层落对象**：大陆 = 画笔位图（PAINT），山 / 城 / 林 / 村镇 / 港 = 点要素（POINT），河流 = 线要素（LINE）；
2. **生成即建文件夹树**：`自动生成山脉(z=199) / 城市(179) / 森林(81) / 村镇(9)…`，文字层 `城市(99999998) / 村镇(99999997) / 港口(99999996) / 国家(99999995)`；
3. **生成即带名字**：点要素 `name_val:"白石港"` + `name_link:"文字_文字_…"` —— 摆一座城，**城名是同一次生成的一部分**，不是事后手打。

实测样本的规模：`POINT ×436 / LINE ×137 / TEXT ×98`（B/A）。该样本可能含人工增补，但量级足以说明：**生成器产出的是一张"有山有水有城有名"的图，而不是一块空陆地。**

重掷也是核心动作：`MapInfo.land_create_num = 1` 记录"生成过几次"（A），说明**"再摇一次"被当成一等公民**，而不是藏在参数里的随机种子。

### 2.5 对象模型：类型即图层（A）

```
z 从下到上
BASEMAP → PaintCover(海洋修饰/浅海) → PAINT(陆地画笔) →
POLYGON(面) → LINE(线) → POINT(点) → TEXT(文字)
```

**同层只能放同类型对象**，图层是"类型容器"而不是任意分组（B）。这条决定了它的心智极其简单：用户不需要理解"分组"，只需要知道"我在改线还是改点"。

### 2.6 缩放与"看得清"的心智（A）

- 步长 0.1，常规上限 **2**，超大画布上限 1，下限 0.1；
- 上限 2 与"高清模式"触发阈值 2 完全吻合 —— **它把"再放大就糊"做成了一个已知边界**。

当前是 0.1~8 连续无级（`coords.ts`），近处不糊是**明确的超越点**，不要为了"像它"而退回两档。

## 3. 当前 map 的交互模型（实测）

### 3.1 现有动作面（A）

工具栏（`MapEditorPage/index.tsx`）：撤销 / 重做｜删除选中｜缩小 / 百分比 / 放大 / 适应窗口｜层级胶囊｜**生成陆地**（连带分区）+ seed 显示｜**生成区块**（随机层级树）+ 已生成 N 块｜加标注 / 素材地名 / 地名计数｜**导出 PNG**｜更多（风格 / 导出尺寸 / 地名字号 / 区块层级 / 陆地种子 / 显示分区 / 清除陆地 / 清除区块 / 清空画布）｜素材计数。

左栏：`SpritePanel` —— **山（2 种）+ 森林（2 种）+ 基底图，共 5 个 PNG、2 个分类**。

右栏：无。画布浮层：地名输入框、`RegionPanel`（圈定生成子图 / 绑定已有子图〔占位〕/ 移除子图 / 聚焦 / 回到全景）。

### 3.2 现有能力边界（A，逐条核实）

| 能力 | 现状 |
|---|---|
| 素材落位 | ✅ 点素材 → 画布单击落位 → Esc 退出 |
| 素材移动 | ✅ 拖动 |
| 素材缩放 / 旋转 / 透明度 / 改色 | ❌ 无（`baseWidth` 写死，只有 `el.scale` 字段被渲染使用，无 UI 入口） |
| 素材复制粘贴 / 微移 / 置顶置底 | ❌ 无 |
| 多选 / 框选 / 批量删除 | ❌ 无（删除只作用于单个 `selectedId`） |
| 地名 | ✅ 单击落位 + 输入；双击改名；清空即删除；有字号档 |
| 地名管理 | ❌ 无列表、不能拖动、不能批量改 |
| 区块 | ✅ 生成 / 清除 / 选中 / 子图圈定；画区、合并、层级 schema 仍是**方案稿**（`region-editing.md`） |
| 图层 / 显隐 / 锁定 / 排序 | ❌ 只有一个「显示分区」开关 |
| 线 / 面要素（河流、道路、区域填充） | ❌ 无（`nested-submap-road` 为方案稿） |
| 保存 / 打开 / 多图列表 | ❌ **完全没有**（无 IPC、无 `localStorage`、无表；`main.ts` 注释明确"无草稿状态跨窗口，关闭即销毁"） |
| 生成内容 | 仅 `land` + `regions`；`elements` 生成后为 `[]`（`useMapEditor.ts` 重置分支） |

### 3.3 现有生成能力的准确定义（A）

> **「生成陆地」= 一块陆地轮廓 + 一棵 Voronoi 区块树（1~4 级，默认 4 级）。**
> **没有山、没有林、没有河、没有城、没有名字。**

"生成一张随机地图"这个需求，在当前实现里**只完成了 20%**。

## 4. 差距 A：渲染效果（结论：已对齐，停止调参）

| 观感构成 | 逆向目标 | 当前 | 判定 |
|---|---|---|---|
| 海陆二分 | 海面纹理 + 有机陆地 | ✅ R-MAP-16（`land.ts` 四层叠加 + 域扭曲） | **对齐** |
| 海岸三件套 | 白描边 + 外发光 + 浅海带 | ✅ R-MAP-16 烘焙进 RenderTexture | **对齐** |
| 区块降级 | 国界细线、色块几乎不可见 | ✅ R-MAP-17（同色系淡彩 α0.10 / 1.2px） | **对齐** |

| 风格 | 3 档整层色相变换（魔幻/仙侠/羊皮纸） | ✅ R-MAP-19（3 档 ColorMatrixFilter） | **对齐** |
| 近处清晰度 | ❌ 放大 2 倍后插值模糊（HD 只重绘矢量） | ✅ 烘焙 + resolution 分级，近处锐利 | **超越** |
| 缩放粒度 | 0.1 步进、上限 2 | ✅ 0.1~8 连续无级 | **超越** |
| 纸张与投影 | A4 固定画幅 + 九宫格纸背景 + 投影 | ✅ 九宫格海面 + 纸投影 | **对齐** |
| **素材丰度** | **~60 图集：山脉 30 + 丘陵/沙丘/雪山 + 城市 10 + 森林 3 密度 + 村镇 + 港口** | **5 张 PNG：山 2 + 森林 2 + 基底** | **差一个量级** |
| **素材密度与层次** | 436 点要素铺满，大小错落 | 手摆，且不能缩放 → 摆不出"层峦叠嶂" | **结构性差距** |
| **符号与名字联动** | 点要素自带 `name_link`，摆城即带名 | 素材与地名是两套对象，手打 | **结构性差距** |
| **海洋修饰（浪花）** | `PaintCover id=9999` 海岸浪花层 | 未实现（只有外发光 + 浅海带） | 小差距 |
| **文字排版** | 竖排 / 沿线弯曲 / 字距 / 角度 / 阴影 | 只取子集（字号档 / 描边 / 无底框） | 中等差距（古地图观感） |
| 导出 | 分块拼接，到打印级 | ✅ 分块 + 1024/2048/4096 三档 | 对齐（尺寸档略窄） |

**结论**：把 §4 表格里"对齐/超越"的 9 行再投入，是**边际收益最低**的方向。后面 5 行（素材丰度、密度与层次、符号与名字联动、海洋修饰、文字排版）才是观感天花板。

## 5. 差距 B：初始随机地图体验（**最高优先级**）

### 5.1 点一次按钮，各自得到什么

| 维度 | 逆向目标 | 当前 map | 差距性质 |
|---|---|---|---|
| 陆地 | ✅ 有 | ✅ 有 | 对齐 |
| 分区 | ✅ 有（面要素，可编辑） | ✅ 有（区块树，可选中） | 对齐 |
| 山 / 丘陵 / 雪山 | ✅ 30+ 变体自动散布 | ❌ 无 | **缺** |
| 森林 | ✅ 3 档密度成片 | ❌ 无 | **缺** |
| 河流 | ✅ 线要素 | ❌ 无 | **缺** |
| 城市 / 村镇 / 港口 | ✅ 符号 + 名字 | ❌ 无 | **缺** |
| 国家 / 城市名 | ✅ 文字层自动生成 | ❌ 无（区块名是「郡 31」编号） | **缺** |
| 图层整理 | ✅ 自动建 5 个文件夹 | ❌ 无图层 | **缺** |
| 生成物可单独编辑 | ✅ 每类都是对象 | ❌ 只有区块是对象 | **缺** |
| 重掷 | ✅ `land_create_num` 一等公民 | ⚠️ 藏在「更多」的 seed，且只能整体重生成 | **半缺** |
| 风格 | ✅ 生成后一键换 | ✅ 3 档 | 对齐 |

**用户感知的差别**：逆向点一下 = "我的世界出来了"；当前点一下 = "给我一张空白海图，请自己画"。

### 5.2 七个体验断点（按伤害排序）

1. **丰度断点**：生成结果没有内容 → 用户必须先有美术能力才能得到一张图。
2. **可编辑性断点**：即使补了素材，如果它们是"烘死的图"，就没法改 —— 逆向的生成物全是对象（这点比"好看"更重要）。
3. **命名断点**：`郡 31` / `国家 12` 是编号，不是世界里的名字。生成结果"无人味"，用户第一步就得逐个改名（而现在连改名都没有）。
4. **重掷断点**：用户不满意时想的是"换一张"，不是"改种子数字"。且需要**局部重掷**（陆地满意、只换山；山满意、只换名字）。
5. **反馈断点**：生成完没有结果摘要（出了多少山/城/名），也没有就地「再摇一次」按钮 —— 用户要回到工具栏再点一次。
6. **密度断点**：素材不能缩放/旋转/改透明度 → 就算手动摆 400 个，也是同一尺寸的贴纸，摆不出层次。
7. **连续性断点**：生成完不能保存 → 关窗即失，"体验"变成"试用"。

### 5.3 修复方案：生成器分层落对象（R-MAP-21）

**核心原则：生成的是"对象"，不是"画面"。** 与逆向同构。

```
一次生成（纯函数 + seed，确定性）
├─ land        陆地多边形（现有 land.ts）
├─ regions     区块树（现有 generateHierarchy，可作为可选项）
├─ elements[]  ← 新增：山/丘陵/森林/村镇/港口实例
│                每条带 sourceId + seed + level + scale 抖动 + rotation 抖动
├─ labels[]    ← 新增：与 elements 一一绑定的地名（elementId 外键）
└─ polylines[] ← 新增（依赖折线能力）：河流 / 海岸线 / 主路
```

三条铁律：

1. **确定性**：同 seed + 同参数 → 逐实例坐标相同（可复现、可截图比对、可回归测试）。
2. **可编辑**：每个实例都是独立对象，能被选中 / 移动 / 缩放 / 删除 / 改样式；用户改过的打 `dirty`，重掷时默认保留（沿用 `nested-submap-elements` 的既有结论）。
3. **可重掷，且分粒度**：`全部 / 只陆地 / 只素材 / 只地名 / 只分区` 五档，就地按钮，不改 seed 也能摇。

**参数面板（一次给全，不塞「更多」）**：

| 参数 | 取值 | 默认 |
|---|---|---|
| 风格 | 魔幻 / 仙侠 / 羊皮纸 | 当前文档风格 |
| 丰度 | 稀疏 / 标准 / 繁密（决定山脉/森林/城镇的目标数量） | 标准 |
| 是否含分区 | 开 / 关 | 关（承接 R-REG-02「默认不划分」） |
| 是否含地名 | 开 / 关 | 开 |
| 陆地形态 | 大陆 / 群岛 / 环礁（`land.ts` 已有 features 参数，只需暴露档位） | 大陆 |

**结果摘要**：`已生成：陆地 1 块 · 山脉 86 · 森林 42 · 城镇 12 · 地名 31｜[换一张] [只换山] [只换名字]`。

### 5.4 素材体系（R-MAP-22，与 R-MAP-21 并行）

| 项 | 要求 | 验收 |
|---|---|---|
| 数量 | 每个主类 ≥ 6 变体，合计 ≥ 40 个符号（山脉/丘陵/沙丘/雪山/森林×3 密度/城市/村镇/港口/废墟/关隘…） | 面板可分类浏览 |
| 变体 | 同符号 3~6 变体，生成时按 seed 抽取，避免"复制粘贴感" | 一片森林里无两个完全相同 |
| 变换 | 尺寸 / 旋转 / 透明度 / 色相 四件套，属性面板可调 | 选中即可调，实时预览 |
| 来源 | **不得使用逆向目标的原始 PNG**（红线）；走 AI 生成 + 调色归一（项目已有 §5.5 工作流） | manifest 记 `ai-generated` + prompt |
| 与地名联动 | 点要素可"带名"创建；改名同步 | 摆一个城市即出现默认名，双击可改 |

## 6. 差距 C：交互范式

| 能力 | 逆向目标 | 当前 | 缺什么 |
|---|---|---|---|
| 放置态 | ✅ 点工具→连续落→Esc 停 | ✅ 同构 | — |
| **选中态** | ✅ 节点控制点 + 右侧属性面板 | ⚠️ 只有高亮 + 一个地名输入 | **属性面板（最高优先）** |
| **图层** | ✅ 六类容器 + 文件夹树 + 显隐/锁定/排序 | ❌ 无 | **图层面板** |
| 复制粘贴 | ✅ Ctrl+C/V 连续粘贴 | ❌ 无 | 连续粘贴（摆森林刚需） |
| 微移 | ✅ 方向键 / WASD | ❌ 无 | 精调 |
| 置顶置底 | ✅ 有 | ❌ 无 | 遮挡控制 |
| 多选 / 框选 | ✅ 框选 + 多边形套索 | ❌ 无 | 批量操作 |
| 节点编辑 | ✅ 线/面拖节点、点节点删点 | ❌ 无 | 河流/边界改形 |
| 快捷键一览 | 部分有 | 撤销/重做/删除/Esc | 补 C/V、方向键、Delete 分类 |
| 保存 | ✅ 顶栏保存 + 服务端 map_id | ❌ 无 | **见 `docs/spec/map-db-spec.md`** |

**心法**：逆向的三栏不是"布局偏好"，是**认知分工**——左栏回答"用什么画"，右栏回答"这个对象是什么样"，顶栏回答"整体做什么"。当前只有左栏（素材）+ 一排顶栏按钮，**"这个对象是什么样"没有答案**，所以用户只能"贴上去就再也改不了"。

> 架构全文见 `docs/prd/prd-map-render/map-asset-system-architecture.md`。

> **seed 不进主工具栏（只留「换一张」，复现靠摘要里的 seed 指示）**。
> 弹层参数：热门地图配方（十万大山 / 南疆沼泽 / 万里雪原）/ 丰度三档 /
> 成图-骨架 / 含地名 / 划分区块。五档重掷（换一张 / 只换陆地 / 只换素材 /
> 只换地名 / 只换分区）+ 结果摘要均已可用；生成产物全部是可编辑对象且
> 单 commit 可撤销。已知取舍：①「只换陆地」保留素材原位（可能落海，文案提示）；
> ② 河流折线依赖 B4 折线能力，本批不含；③ 布点允许层叠（手绘观感），
> 密度按碰撞自适应，丰度值是目标上限而非精确数。

**顺序理由**：先能保存（否则一切体验都是试用）→ 再能改（对象属性）→ 再能摆（素材）→ 最后能一键出图（生成器是前三者的编排，不是独立能力）。

> 注意：该顺序与"先做生成器"的直觉相反。原因是**生成器产出的是对象，对象没有属性面板就没法改，没有持久化就没法留**；先做生成器会得到一个"看起来很惊艳但一碰就碎"的演示。

## 10. 待拍板

1. **素材来源**：AI 生成（项目既定 §5.5 工作流）还是先内置一版手绘/程序化？前者观感统一但需要出图与调色归一的时间，后者快但容易"像贴纸"。
2. **生成器默认档**：默认"骨架"（只陆地，不改现有习惯）还是默认"成图"（一键出完整图）？我建议**新建地图时默认成图，之后可切骨架**。
3. **是否保留 seed 输入框**：建议从主工具栏移除（收进参数面板的「复现」折叠区），主界面只留「换一张」。
