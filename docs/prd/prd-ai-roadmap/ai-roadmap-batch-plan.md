## 四、批次计划

> **批次 ≠ 版本号**。有新增表 / 新 IPC / 新窗口的批次必须升次版本（`AGENTS.md` §8.6），
> 纯功能与 UI 的批次只升修订号。开工时按当批实际内容判定，不要照抄下表右列。

### B1 · 「先让 AI 看得见」（P0 元能力收尾）

**做**：M1a（`ai_event` 表 + 采纳/编辑/放弃事件 + 1000 条/90 天保留上限）、M7（`prompt_version` 列）、M8（`useAiAvailability` + 三个入口接门控）、M1b（看板聚合页 + 诊断包导出）

**为什么是它**：这四项加起来才构成「能度量」。缺任何一项，后面每个功能上线后都无法回答「值不值得继续做」。且 M1/M7/M1b 都已有一半，是**全表性价比最高的一批**。

**完成判据**
1. `ai_event` 与 `ai_log` 严格分工：前者只存元数据（intent / 结果 / 耗时 / 采纳），后者存 prompt 与输出；
2. 起名 → 插入正文 会落一条 `adopt` 事件，看板「采纳率」因此可算；
3. 未配置 AI 时，起名/润色/AI 记录三处入口**要么隐藏、要么禁用并说明原因**，不出现「点了没反应」；
4. 看板能答：本月调用次数、各 intent 分布、采纳率、平均耗时；
5. 诊断包导出**不含正文与作品名**（字段白名单单测）。

**依赖**：无（M2/M3 已就绪）。

---

### B2 · 「让 AI 高频化」（P0 功能）

**做**：R-AI-06 完整版 —— 扩写 / 精简 / 改写 / 换语气 / 转视角，共用 `PolishPreview` 泛化后的变换选择器。

**为什么这批**：R-AI-06 是全表最高分（7.5）。润色已验证「选中 → 预览 → 替换」整条链路，多出的只是 5 个 prompt 模板 + 一个类型选择器。且这 5 种变换与润色是**同一动作的不同意图**，作者心智能自然接纳。

**完成判据**
1. 选中文本 → 浮动工具栏出现变换分组（受 M8 门控）；
2. 5 种各出正确结果，预览可切换、可取消，替换走编辑器 undo；
3. `ai_log.intent` 能区分 `transform:expand` / `transform:condense` 等（B1 的契约在这里第一次被复用）。

**依赖**：B1（intent 契约 + 门控）。

---

### B3 · 「让 AI 陪你写下去」第一步（P0 功能）

**做**：R-AI-07 就地续写 —— **非流式**，光标处出 2–3 个候选，确认后插入。

**为什么这批**：续写是留存动作，且 B1/B2 已把上下文和契约铺好，此处只差「候选浮层 + 编排」。**明确不在此批上流式**：`stream: false` 目前写死在主进程两处，流式是整份路线图唯一需要新增主进程网络能力的事，与功能捆一版风险过高。

**完成判据**
1. 光标处续写生成 2–3 个候选，可换一批、可取消，确认后插入且可 undo；
2. 失败不动原文，错误文案可读（复用 `ai-errors` 归一）；
3. 上下文含「前文 N 字」，`BookSnapshot` 已在，不需要摘要先行。

**依赖**：B1、B2（变换预览的泛化形态可复用）。

---

### B4 · 「趟出 L3 基建」（P1 元能力 + 第一个 L3 功能）

**做**：M5（L1/L2/L3 分级 + 授权弹窗 + 范围选择 + 成本估算）、M6（来源标记 + 按批次撤销 + 占比统计口径）、R-AI-09（章节摘要 + `novel_chapters` 三列）。

**为什么这批**：09 是**最便宜的 L3 消费者**（text 输出、无批量写、无候选确认），用它趟 L3 与落地通道两条元能力，成本最低。M5 必须早于任何 L3 功能，否则会散出多份不一致的授权文案。

**完成判据**
1. 首次触发 L3 弹授权：显示将发送字数 + 范围选择（默认「仅本章」，不提供「全书」档）；
2. 关闭总开关后所有 L3 入口隐藏**并说明原因**；
3. 摘要带「AI 生成」标记与模型名；用户手工编辑后来源标记清空；删章不残留摘要。

**依赖**：B1（M8 门控是 L3 授权的前置）。

### B5 · 「流式」（P1 元能力）

**做**：M4（`protocol.handle` 流式端点 + IPC 兜底 + `aiGenerateStream` + 中断），并把 R-AI-07 升级为流式版。

**为什么单独一批**：新增主进程网络能力，风险独立。同时要同步 `ai-architecture-decision.md` 五·A 的豁免边界（流式端点属于同一豁免，必须写清楚）。

**完成判据**：续写逐字输出、可中断；中断后主进程连接释放（守卫断言）；端点 URL 不含 Key。

**依赖**：B3（升级对象已存在）。

### B6 · 「沉淀资产」（P1）

**做**：R-AI-10a（纯本地一致性校对：人名/别名近似 + 境界别名归并）、R-AI-08（实体抽取 → 一键建卡，人工勾选入库）。

**为什么这两项合并**：10a 零 token、可复现，先给出误报基线；08 是「供给方」，为后续 10b/15 供米。**顺序是 10a 在前**——它不依赖任何 AI 配置就能跑，是「AI 不可用也有价值」的证明。

**完成判据**
1. 完全不配置 AI，10a 也能查出一致性问题并跳转定位；
2. 08 的候选必须人工勾选才入库，重名项明确标注（守卫断言「不存在自动入库分支」）；
3. 批量建卡单事务 + 走 `novel-entities-changed` 广播。

**依赖**：B4（M5/M6）。

## 五、纪律（每批开工前必须过一次）

1. **元能力先行**：M5 不得晚于第一个 L3 功能；M8 不得晚于第二个 AI 入口；M3 已有（结构化输出不再重复造）。
2. **不许新增 production 依赖**：token 估算、分块、检索、排序一律自研纯函数；向量库 / embedding / 分词器不进 `dependencies`。
3. **入口可消失**：AI 不可用时，入口必须「隐藏 / 禁用 + 说明 / 有本地兜底」，禁止「点了没反应」与空聊天框。
4. **产出必须沉淀且可溯源**：结构化 AI 产出（名字 / 要素卡 / 摘要 / 关系边）必须有「存入用户库」的出口，并带来源标记（模型 + 时间 + 批次）。
5. **AI 事件落 `ai.db`**，不得写进 `novel_usage_log`（域边界）。
6. **每个功能新增都必须在 `PROMPT_BUILDERS` 登记 + 声明 `OutputFormat`**，不要在业务组件里手拼 system。
