## 4. 分批排期

### B1 · 一天批次：可见性与文案（8 项，2.57.0 已全部闭环）

**目标**：把已经建好的能力摆到台面上，把说错的话改对。**不动状态模型、不动布局**。

- 包含：O-05、O-07、O-14、O-13a、O-11、O-15、O-16、D-15。**（已闭环，验收①~④已由 2.57.0 落实）**
- **为什么排第一**：八项里有六项是「用户已经在用、只是找不到 / 看不懂」，改动面全是单文件或常量，回滚成本几乎为零；O-05 是全表唯一 P0。
- **验收**：① `SHORTCUTS` 有阅读模式键位且帮助中心同步；② 构造 `loadError` 时正文区出现 `role="alert"` 与可点重试；③ 空要素书的右栏默认落 `outline`；④ 两处删除弹窗文案含「不可恢复」；⑤ 全量单测 + `tsc` 绿。
- **注意**：文案类守卫按源码字符串钉（`indexOf`），别断行 —— 格式化会拆行造成假红。

### B2 · 单组件补强（6 项，闭环 4 项：O-01 / O-08 / O-04 / O-06）

**目标**：每个条目只改一个组件，互不阻塞，可拆给不同人并行。

- 包含：O-01、O-08、O-04（2.57.0 闭环）、O-06（2.71.0 闭环三态）、D-08、D-13（未动，原因见 §8）。
- **为什么第二**：都是 P1 级「用起来别扭」的问题，但每项只碰一个组件，不需要设计评审；O-06 与 D-08 都落在「视觉语言 / 开关语义」上，同一批做能顺手对齐。
- **验收**：① 保存失败态点击即触发 `flushSave()`，且有原因文案；② 顶栏三颗分组后首次使用者能指名各自归属（走查 3 人）；③ 章节树与大纲的点击行为一致（跳转 + 同步展开）；④ 敏感词开关独立生效且不与标注层互锁。

### B3 · 信息架构（6 项，2.57.0 闭环 4 项：O-02 / O-03 / O-09 / O-10）

**目标**：顶栏、右栏、书架三处「入口太多、主次不分」。

- 包含：O-02、O-03、O-10、O-09（已闭环，依据 `design/novel-ui-refresh/` 交互稿）、O-12、O-17（未动，原因见 §8）。
- **为什么必须一次做**：O-02（顶栏收入口）、O-03（工具 Tab 降级）、O-10（书架顶栏归位）动的是同一套「入口从哪进」的约定；分三次改同一块布局 = 三次返工 + 三次回归。
- **前置**：三张布局草图（顶栏 / 右栏 / 书架）已随交互稿 `design/novel-ui-refresh/` 出具，边界确认完毕。
