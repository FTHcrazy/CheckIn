## 二、产品目标

本次迭代要给小说模块补上**一套能跨作品复用的「全局设定库」**：作者此前只能在单本书内建设定（境界体系、功法等级、品阶等），每开一本新书都要重来一遍；「本书设定中心」与「全局设定中心」打通后，作者既能把本书已打磨好的设定**一键上架**到全局库、也能在任意新书里**直接引用**全局等级，从「一本书一套设定」升级为「一套设定喂所有书」。同时修复/优化七处已确认的体验问题（要素小境界、出场章节间距、工具卡文字溢出、伏笔章节跳转、自定义要素入口可见性、顶栏按钮二击、行囊境界显示格式），保证核心写作闭环不因新功能而降级。

## 三、用户故事

**A 全局设定中心**

- 作为**多部作品的作者**，我希望有一处跨书共享的设定库，以便不用为每本新书重复搭建境界/品阶体系。
- 作为**正在写第二本书的作者**，我希望在本书设定中心里直接勾选全局库里已有的等级，以便新书开局就站在旧书的设定肩膀上。
- 作为**刚打磨完一套自创体系的作者**，我希望把本书设定「放置到全局设定中心」，以便别的书也能复用我这套心血。
- 作为**打开应用刚上书架的作者**，我希望书架主页就有全局设定中心入口，以便不进入任何一本书也能先维护设定库。

**B 要素境界 / 出场章节**

- 作为**设定粒度很细的作者**，我希望在要素的「境界」里能选到小境界（阶内小层），以便表达「筑基初期第 3 层」这种精度，而不是只能挂一个大境界。
- 作为**靠出场章节回顾人物戏份的作者**，我希望出场章节列表排得松一点，以便一眼扫清而不觉得挤。

**C 工具卡**

- 作为**浏览右侧工具箱的作者**，我希望工具卡的描述文字完整可见、不撑破卡片，以便快速判断每个工具能做什么。

**D 伏笔章节跳转**

- 作为**管理伏笔的作者**，我希望点击伏笔归属的章节名就能跳到那一章，以便立刻回到埋线处核对或回收，不用手翻。

**E 自定义要素入口**

- 作为**需要自建要素类型的作者**，我希望「自定义要素/类型管理」的入口一眼可见，以便不用摸索才发现能自建类型。

**F 顶栏按钮二击**

- 作为**频繁在顶栏切换面板的作者**，我希望点一次「行囊 / 本书设定」就打开，以便不被「点了没反应、要再点一次」打断。

**G 行囊境界显示**

- 作为**看主角修为状态的作者**，我希望境界显示成 `筑基 * 初期 1/4`、`练气 * 第七层 7/13` 的形式，以便一眼看出「当前是什么境界、走到第几层」。

## 五、关键设计决策（D1–D5）

### D1：全局设定的数据归属 —— 新增全局表 **（推荐）** vs 复用 `novel_setting_categories` + `work_id` 哨兵值

**推荐方案：新增全局表** `novel_global_setting_categories` / `novel_global_setting_levels`（结构对齐现有两张表，去掉 `work_id`），引用关系用新增的可空列（如本书侧 `novel_setting_categories.source_global_id`）记录。

理由：
1. **生命周期隔离**：本书设定随书删除而消亡，全局设定是跨书长期资产。共用一张表会让「删书是否连带删全局」「按 `workId` 统计分类数」处处需要哨兵例外，长期是 bug 温床。
2. **迁移最安全**：新增表走 `CREATE TABLE IF NOT EXISTS`，**完全不触碰既有表结构**，旧数据零影响，比给老表 `ALTER` 补列更符合 §6.5「增量、可空、旧数据可读」的精神。
3. **唯一性约束天然独立**：每书至多一个 `kind='realm'` 的规则对全局同样成立（全局唯一的境界体系），独立表更易表达与校验。
4. **哨兵值方案的硬伤**：项目已有「空 `workId` 会被当作真实作品播种垃圾数据」的历史（见 `openPackWindow` 守卫、`novel_pack_characters` 注释），用空串当哨兵会与既有语义直接冲突；若另造哨兵值又增加了隐晦耦合，任何按 `work_id` 过滤的 SQL 都得记得排除它。

**备选方案**：复用 `novel_setting_categories` + 哨兵 `work_id`（如 `__global__`）。优点是可复用全部现有 IPC 与查询；缺点是语义隐晦、过滤面广、易被误删联动。**仅在「想极致复用现有 handler、且团队能接受语义耦合」时选择。**

### D2：本书「选择全局等级」的语义 —— 引用（实时同步）**（推荐）** vs 复制快照

**推荐方案：引用（实时同步）。** 本书侧只存 `source_global_id` 引用，全局改动即时反映到所有引用书。

理由：
1. 本需求的核心价值是「**跨书共享同一套设定**」。若采用复制快照，则退化为「一次性导入模板」——而现有 `novel_setting_templates`（「另存为模板 / 从模板导入」）已经覆盖了「复制一份」的场景，全局中心便没有存在意义。
2. 作者改全局 = 改**标准**，符合「全局设定中心」的心智；引用让修正在所有书里一次生效，维护成本最低。
3. 需求原文即「本书可**引用**全局等级」，语义即引用。

**配套护栏**：① 本书侧引用分类/等级带「全局 · 自动同步」标识，颜色/样式区分于本书自有项；② 引用项在本书侧只读，编辑需先「脱离全局」；③ 提供「脱离全局 · 转为本书独有」动作（建议 P2，见待确认 Q3），给需要魔改本书设定、又不想影响其他书的作者。

**备选方案**：复制快照。优点是本书独立、全局后续改动不惊扰已写好的书；缺点是失去统一维护价值、副本与全局持续漂移。

### D3：本书设定「放置到全局」的语义 —— 复制一份（快照上架）**（推荐）** vs 移动 vs 建立引用

**推荐方案：复制一份（快照上架）。** 把本书分类 + 等级**拷贝**进全局库，本书保持原样（双向解耦）。

理由：
1. 「放置到全局」的心智是「把我定好的这套**上架**，让别人/别的书也能用」。**移动**会破坏本书（书丢了设定就废）；**建立引用**会让本书设定反过来受全局控制（改全局把本书也改了）——都不符合「上架」直觉。
2. 复制是幂等、无破坏的操作，可随时重来。

**同名冲突处置（推荐：询问 + 三选）**：
- 弹确认「全局库已有同名分类『XXX』，如何处理？」——
  - **新建为副本（默认）**：在全局新建「XXX（副本）」；最安全、零副作用。
  - **合并到现有类别**：把本书等级并入全局同类；涉及 `rank` / 小层交错，风险高，仅在作者明确选择时执行并提示影响。
  - **取消**。
- 若上架的是 `kind='realm'` 境界体系而全局已有 realm，则提示「全局已有境界体系，是否替换」，**默认不替换**。

### D4：全局与本书的从属关系 —— 全局被引用的等级能否删除？删除后引用方如何表现？

**推荐方案：允许删除，但删除前二次确认 + 引用方就地固化为快照副本（防丢数据）。**

规则：
1. 删除全局分类/等级前，先统计引用它的书数量，弹确认：「有 N 部书引用了该设定，删除后这些书的对应项将转为本书独立副本（内容保留、不再自动同步），是否继续？」
2. 引用方表现：删除时把被引用项在**每本引用书里就地固化**为一份本书自有副本，并在本书侧标注「原全局项已删除，已转为本书副本」。
3. 不采用「硬删除 + 引用方直接消失/报错」——那会让作者丢已写内容。

**备选方案：软删除**（全局侧保留 `deleted` 标记，引用方仍显示但标「已下线」，不支持物理删除）。更保守，但数据长期堆积、全局列表需过滤已删项。**若团队更看重「绝不改变任何书的数据」，可改为软删除**（见待确认 Q）。

### D5：迁移策略 —— 走 §6.5 增量迁移（`compat`）**（推荐）**，**不开** `refactor`

**推荐方案：保持 `compat`（默认），走 §6.5 增量迁移。**

理由：
1. 本次是**纯增量**：新增全局表（`CREATE TABLE IF NOT EXISTS`）+ 至多给 `novel_setting_categories` 加 1 个**可空**列（如 `source_global_id`，默认 `NULL`）即可落地，天然满足「新列可空 / 带默认值 / 旧数据可读」。
2. **没有破坏性重构诉求**：不动现有表结构、不删表、不改主键、不合并——不满足 §6.7 对 `refactor` 的适用前提（`refactor` 是「授权对 novel 存储做破坏性重构、允许丢弃旧数据」的窗口）。
3. `refactor` 的代价不成比例：需在交付时改回 `compat` 并验证兼容，且必须明文声明「旧数据不兼容」，对已上线的真实小说数据风险过高。
4. §6.5 明确：唯一例外是重构窗口期，其余（含 `compat` 与所有非 novel 模块）无例外。

**备选方案**：仅当团队决定「借本次把 `novel_setting_*` 表结构彻底重设为全局维度」时才考虑 `refactor`；但本需求不要求，且必须在 PRD / 交付说明中明示旧数据不兼容。**不建议在本次采用。**

## 六、UI 设计稿（文字描述版）

### 6.1 A 项：全局设定中心

**（1）全局设定中心页面（建议独立窗口，与行囊窗口同范式、单实例）**

- **版式**：复用本书设定中心的三栏结构 —— 顶部标题 + 动作区、左栏分类列表、右侧主区（等级序列 + 分类信息卡）。
- **差异点**：
  - 标题为「全局设定中心 · 跨书共享」，副标题一句：「这里的设定可被任意作品引用；改动会同步到仍引用它的书。」
  - 去掉「本书」概念，无作品切换器。
  - 每个分类/等级行右侧增加**引用计数徽标**「N 部书引用」（0 时灰显「暂无引用」）。
  - 动作区保留：新建分类 / 模板库 / 导入 / 导出。删除动作走 D4 二次确认流程。
- **空态**：复用「还没有设定分类」空态 + 「从模板库套用」/「新建分类」CTA。

**（2）本书设定中心内的「选择全局等级」入口（REQ-041）**

- **入口位置**：本书设定中心左栏「＋ 新建分类」附近增加「从全局库选择」按钮（次按钮形态）。
- **交互流程**：点击 → 弹出**全局库选择器**（Modal/Drawer）→ 列出全局分类与等级（支持按名称搜索、多选）→ 确认 → 以「引用」方式加入本书左栏。
- **引用态表现**：本书左栏该分类名后带「全局」小标签（弱色 pill）；进入该分类，等级行带来源徽标；编辑区顶部提示「本分类引用自全局设定中心，改动请到全局中心；如需在本书中单独修改，请先『脱离全局』」。

**（3）本书设定「放置到全局」入口（REQ-042）**

- **入口位置**：本书设定中心分类信息卡（右侧）动作区，增加「放置到全局」按钮。
- **交互流程**：点击 → 若全局有同名分类，走 D3 冲突三选弹框（默认「新建为副本」）；否则直接确认「将『XXX』共 M 个等级上架到全局设定中心？」→ 成功后 Toast「已上架到全局设定中心」，并在全局中心可见。

**（4）书架主页入口（REQ-043）**

- **位置**：`ShelfTopBar` 右侧动作区，在「搜索框 / 导入书籍 / 新建作品」同一行，新增「全局设定中心」按钮（图标 + 文字标签）——紧邻新建作品左侧，语义上属「库/资源」而非「写作」分组。
- **行为**：单击打开全局设定中心页面（单实例，已开则聚焦）。

### 6.2 B 项：要素境界小境界 + 出场章节间距

**（1）要素境界选小境界（REQ-045）**

- 在 `EntityDetail` 的「当前境界」区块，选定某阶后：若该阶有小层/派生段，展示小境界选择行（chip 组，如「初期 / 中期 / 后期 / 圆满」或「第 1 层…第 N 层」）；点击落到具体 `sub` 坐标。
- 已支持派生段（`nv-edetail__rung-seg`）的场景保持；本次**补齐「该阶无拆分、仅设 `sub_levels>1` 时也能直接选到第 N 层」**（详见待确认 Q5）。
- 绑定后卡片读数随 G 项新格式显示。

**（2）出场章节列表间距（REQ-046）**

- 出场章节列表（`nv-edetail__chip` 行）行间距由 4px 提升到 ≥8px；行内「序号徽标 ↔ 标题」间距同向放宽。
- 同步修改 TS 常量 `APPEAR_ROW_HEIGHT` 与 SCSS 行盒，保证 Virtuoso 行高一致、不跳白条。

### 6.3 C 项：工具卡描述溢出（REQ-047）

- **方案：换行自适应**。在 `.nv-tools__desc` 显式声明 `white-space: normal;`（覆盖 antd `.ant-btn` 继承来的 `nowrap`）+ `overflow-wrap: anywhere;`。
- **理由**：工具描述是「选哪个工具」的关键决策信息（如「八类名称 × 东西方多风格，避开本书已用名…」），**截断会隐藏卖点**；工具卡是纵向单列列表，卡片高度自适应不影响版式。
- **备选**：单行 `ellipsis` 截断（卡片等高整齐，但丢信息）——不推荐。

### 6.4 D 项：伏笔章节跳转（REQ-048）

- 在「伏笔」子视图的非紧凑行中，把来源章节名（`nv-outline__fs-src` 的 `node.source`）渲染为可点击元素（按钮/链接样式）。
- 点击 → `onSelectChapter(node.chapterId)` 跳转到对应章节。
- 卷级伏笔（`chapterId` 为空）保持纯文本、不可点。

### 6.5 E 项：自定义要素入口可见性（REQ-049）

- 「要素」tab（`SupportPanel` 的 entity 面板头）现有「要素类型管理」为纯图标按钮（`TagsOutlined`，仅 Tooltip）。本次改为**图标 + 文字「类型管理」**的可识别按钮；并在要素面板为空态时增加一条「还没有自定义类型？点『类型管理』新建」引导文案 + 直达按钮。

### 6.6 F 项：顶栏按钮二击 bug（REQ-050）

- **现象**：先点开其他功能（如「历史快照」「排版与偏好」抽屉），再点「行囊」/「本书设定」，偶现需点两次。
- **疑似根因（供架构参考，不作为定论）**：`SettingsDrawer` 用一层透明捕获遮罩（`.nv-setting__mask`，`onClick` = 关闭）实现「点外部关闭」；当抽屉/面板打开时，点击顶栏按钮的第一击被这层遮罩**吞掉**（只关了抽屉，未落到按钮），需第二击才命中按钮。
- **修复方向（择一，需架构定）**：① 遮罩关闭时不吞同一点击（对落点为顶栏按钮的事件放行）；② 改为无遮罩抽屉（用 Esc / 点按钮自身关闭）；③ 用 `mousedown` 分流。
- **验收**：见 REQ-050 池中标准。

### 6.7 G 项：行囊境界显示格式（REQ-051 / REQ-052）

- 现状：`formatRealm(rungs, pos)` 输出 `筑基 1/4`，小层别名在旁单独一枚 chip（`.cpk-rlm__alias`）。
- 目标：合并为 `阶名 * 小层名 进度`，即 `筑基 * 初期 1/4`；`{n}` 模板命名为 `练气 * 第七层 7/13`。
- 规则：① 无小层名（纯数字小层 / 无别名）时省略 `* 小层名`，回退 `筑基 1/4`；② `subLevels<=1` 时只显示阶名（维持现状）；③ 数字→中文走既有 `formatSubLevel` / 小层命名纯函数，不新增第二份实现。
