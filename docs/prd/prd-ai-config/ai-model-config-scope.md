## 二、背景与目标

### 2.1 背景

CheckIn 是纯离线的 Electron 桌面应用（无后端服务），现有两大业务域：checkin（Todo/Memo/Daily/Code/Ledger/News/Home）与 novel（小说创作：书架/编辑器/行囊/关系图谱/设定中心）。项目当前**零 AI 依赖**，唯一的「生成」能力（名字生成器）是本地字典 + PRNG 规则引擎，非 AI。

拟接入 AI 能力，为 novel 域的创作场景（起名、润色、续写、实体抽取）与 checkin 域的办公场景（记账分类、摘要）提供智能增强。

### 2.2 核心约束

1. **无后端**：产品无服务端，无法提供「官方托管 / 统一鉴权 / 计费转发」。AI 调用必须纯客户端完成。
2. **双目标人群**：
   - **AI 小白**：希望「上手就能用」，不被 API Key / Base URL / 参数等术语劝退；
   - **资深 AI 用户**：希望「用自己的模型」，完全掌控模型服务、密钥与参数。

### 2.3 要解决的问题

在「无后端 + 双目标人群」约束下，解决：用户如何**配置**一个可用的 AI 模型服务，且配置路径对两类人群都友好，配置结果能被后续所有 AI 功能复用。

### 2.4 成功指标

| 指标    | 口径                           | 目标值        |
| ----- | ---------------------------- | ---------- |
| 配置成功率 | 用户完成「配置 → 测试连接通过」的比例         | ≥ 90%（估算）  |
| 配置耗时  | 小白从进入设置到完成首次可用配置的中位时长        | ≤ 3 分钟（估算） |
| 配置留存  | 首次配置成功后，7 日内仍保留有效配置的比例       | ≥ 80%（估算）  |
| 降级可用率 | Key 失效 / 服务不可用时有明确可恢复提示的场景占比 | 100%       |

> 以上均为估算目标，上线后以埋点数据复核（埋点需求见 §十）。

| 术语          | 定义                                                                              |

| BYOK        | Bring Your Own Key，用户自备 API Key 的接入模式                                           |
| OpenAI 兼容接口 | 遵循 OpenAI `/v1/chat/completions` 协议的模型服务端点（DeepSeek、通义、智谱、Moonshot、Ollama 等均兼容） |

| 测试连接        | 配置保存前的连通性验证动作                                                                   |

## 四、需求范围

### 4.1 包含

- AI 设置入口（挂到 `SettingsWindow` 设置窗口）
- 模型服务商选择（预置模板 + 自定义）
- API Key 的录入、加密存储、回显
- 本地 Ollama 探测与模型选择
- 「测试连接」连通性验证
- 高级参数（可选，默认折叠）
- 主进程 AI 调用通道（`ai-handlers.ts`）
- 异常 / 降级处理

### 4.2 不包含（本期不做）

- 任何具体 AI 功能（写作助手、起名增强、实体抽取等）—— 后续独立 PRD
- 官方托管 / 平台代付 / 统一计费（无后端，不做）
- 内置免费 Key（避免限流与稳定性问题，只做引导）
- 多模型并发路由与成本看板 —— 后续版本

## 五、方案对比与选型

### 5.1 候选方案

| 方案       | 思路          | 小白体验    | 资深体验 | 成本  | 结论                          |
| -------- | ----------- | ------- | ---- | --- | --------------------------- |
| A 官方托管   | 平台代付、统一鉴权   | 最好      | 弱    | 需后端 | ❌ 无后端，出局                    |
| B 纯 BYOK | 用户自填 Key 直连 | 中（靠引导补） | 最好   | 零   | ✅ 主路线                       |
| C 本地模型   | 本地 Ollama   | 中（需装软件） | 好    | 零   | ✅ 辅路线，复用 B 的自定义 Endpoint 能力 |

### 5.2 推荐方案

**B（BYOK）+ C（本地模型）双轨，共享同一套调用通道。**

- 主路线 BYOK：预置服务商模板 + 「获取 Key」引导 + 测试连接，把小白路径压到最短；
- 辅路线本地模型：自动探测 Ollama、列模型、零 Key，服务隐私/离线人群；
- 本地模型技术上复用 BYOK 的「自定义 Endpoint」能力（Ollama 暴露 OpenAI 兼容端点），**不单独造一套**。

### 5.3 演进路径

| 阶段 | 内容                          | 触发条件          |
| -- | --------------------------- | ------------- |
| 本期 | BYOK + 本地模型双轨配置层            | 本 PRD         |
| 后续 | 模型路由（任务→模型映射）、成本看板、多 Key 管理 | 首个 AI 功能上线后按需 |

## 七、功能需求

### FR-01 AI 设置入口

- **描述**：在 `SettingsWindow` 设置窗口新增「AI 助手」分区（`AISection` 组件），位于外观分区之后、个人资料分区之前（或按最终视觉排布）。**仅在含 novel 模块的版本（full / novel）展示，lite 版不展示**（与 ai.db 的 edition 开关对齐，见 R-AI-04 预研点 2）。
- **业务规则**：分区内默认只展示「总开关 + 模式选择」，高级项折叠。
- **验收标准**：
  - Given 打开设置窗口，When 滚动设置页，Then 可见「AI 助手」分区，含总开关。
  - Given lite 版打开设置窗口，Then 不出现「AI 助手」分区。

### FR-02 模式选择

- **描述**：提供「使用自己的模型（BYOK）」与「本地 Ollama」两种模式。
- **业务规则**：默认选中 BYOK；切换模式时重置下方对应表单区域，不清除已保存的其他模式配置。
- **验收标准**：
  - Given 配置页，When 切换模式，Then 表单区域随模式切换，且不丢失另一模式已保存配置。

### FR-03 服务商模板

- **描述**：预置常用服务商（DeepSeek / 通义千问 / 智谱 / OpenAI / Moonshot 等），选中自动填充「接口地址 + 默认模型名」。
- **业务规则**：模板为只读默认值，可被用户覆盖；自定义时清空模板选中。
- **验收标准**：
  - Given 选「DeepSeek」，Then 接口地址与模型名自动填充为 DeepSeek 默认值，用户只需填 Key。

### FR-04 API Key 录入与加密存储

- **描述**：录入 Key，主进程用 Electron `safeStorage` 加密后持久化。
- **业务规则**：Key 仅本机保存、绝不落日志/明文；回显为掩码（`sk-****xxxx`），支持重新录入。
- **验收标准**：
  - Given 填入 Key 并保存，Then 落库为密文（不可明文检索），UI 回显掩码。

### FR-05 获取 Key 引导

- **描述**：提供「去哪里获取 Key」入口，展示所选服务商的申请步骤，并可 `shell.openExternal` 打开对应申请页。
- **业务规则**：引导文案为通用指引，不内置任何真实 Key 或跳转第三方营销页。
- **验收标准**：
  - Given 点击「获取 Key」，Then 展示该服务商申请步骤并可跳转官方申请页。

### FR-06 本地 Ollama 探测

- **描述**：模式为「本地 Ollama」时，自动探测 `localhost:11434`，列出已下载模型。
- **业务规则**：探测失败给出明确提示（未安装 / 服务未启动）；选中模型后无需 Key。
- **验收标准**：
  - Given 已启动 Ollama，When 进入本地模式，Then 列出可用模型；Given 未启动，Then 提示未检测到服务并给出启动指引。

### FR-07 测试连接

- **描述**：配置保存前提供连通性验证，返回成功或具体失败原因。
- **业务规则**：失败原因至少区分「Key 无效 / 额度不足 / 地址不可达 / 模型不存在 / 超时」；测试不消耗大量 token（用最小请求）。
- **验收标准**：
  - Given 填写错误 Key，When 测试连接，Then 明确提示「Key 无效」；Given 地址错误，Then 提示「地址不可达」。

### FR-08 高级参数

- **描述**：高级参数（Temperature / Top-p / 上下文长度 / 自定义 System Prompt）默认折叠，展开可调。
- **业务规则**：全部参数有默认值，小白无感；自定义值持久化并用于后续所有 AI 调用。
- **验收标准**：
  - Given 展开高级项，When 调整参数，Then 保存后生效；Given 未展开，Then 使用默认值。

### FR-09 主进程调用通道

- **描述**：新增 `electron/handlers/ai-handlers.ts`，功能面板经 `shared/ai/` 服务层 → `window.electronAPI.ai.*` 调用（见 `ai-architecture-decision.md`）。
- **业务规则**：请求必须走主进程（Node 侧无 CORS 限制）；主进程负责读配置、解密 Key、请求路由（OpenAI 兼容 / Ollama）、流式转发、错误归一。
- **验收标准**：
  - Given 渲染进程发起 AI 调用，Then 请求由主进程发出并正常返回/流式返回。

### FR-10 异常与降级

- **描述**：Key 失效 / 服务不可用 / 超时 / 限流时，给出明确、可恢复的提示，并支持一键切回有效配置。
- **业务规则**：不白屏、不无限转圈；所有错误归一为可读文案；提供「去设置」跳转。
- **验收标准**：
  - Given Key 失效，When 调用 AI，Then 提示「密钥失效/额度不足」并附「去设置」入口。

## 九、业务流程与状态流转

### 9.1 配置主流程

```
进入 AI 设置 → 开总开关 → 选模式
  ├─ BYOK：选服务商模板（自动填地址/模型）→ 填 Key → 测试连接 → 保存
  └─ 本地：探测 Ollama → 选模型 → 保存
保存 → 可用状态（后续 AI 功能可调用）
```

### 9.2 配置状态机

| 状态      | 触发事件             | 允许操作          |
| ------- | ---------------- | ------------- |
| 未配置     | 总开关关闭 / 无有效配置    | 配置、开关         |
| 配置中     | 填写表单             | 编辑、测试连接、取消    |
| 已配置-未验证 | 保存但未测试通过         | 测试连接、编辑、清除    |
| 可用      | 测试连接通过           | 调用 AI、编辑、清除   |
| 失效      | 调用返回 Key 失效/额度不足 | 提示 + 去设置、切换配置 |

## 十、数据与埋点需求

### 10.1 配置存储

| 字段            | 类型     | 说明                   |
| ------------- | ------ | -------------------- |
| mode          | enum   | byok / local         |
| provider      | string | 服务商标识（模板或 custom）    |
| baseUrl       | string | 接口地址                 |
| apiKeyEnc     | blob   | safeStorage 加密后的 Key |
| model         | string | 模型名                  |
| contextLength | int    | 上下文长度                |
| temperature   | float  | 采样温度                 |
| topP          | float  | top-p                |
| systemPrompt  | string | 自定义系统提示词             |

> **已定（2026-10-26）**：AI 相关配置独立建 `ai.db` 存储（不塞 `checkin.db` / `novel.db`），
> 并**随用户隔离**（与 `checkin.db` 同目录、按 `user-data/{email-hash}/` 分用户）。
> 独立库的理由：后续可能扩展「记忆 / 使用偏好」等 AI 专属数据，单独成库避免污染既有两域。

>
> **首版只建 `ai_config` 一张表**；`ai_memory` 等留到真正需要时再建（见 R-AI-04 预研点 2）。
>
> **edition 开关**：`ai.db` 只在含 novel 模块的版本（full / novel）初始化，lite 版不初始化；
> 后续 checkin 窗口接入 AI 时再放开到全版本（见 R-AI-04 预研点 2）。

## 十一、权限与安全要求

- 无后端，不涉及服务端鉴权；核心安全面是**本机密钥保护**：
  - Key 用 `safeStorage` 加密存储，禁止明文、禁止写日志；
  - 配置变更留审计（本地日志记录「何时改了什么字段」，不含 Key 值）；
  - UI 首次使用明示「文本将发送至所选模型服务商，Key 仅本机保存」。

## 十二、异常处理清单

| 场景         | 处理                   |
| ---------- | -------------------- |
| Key 无效     | 提示「密钥无效」，附重新获取引导     |
| 额度不足       | 提示「额度不足」，附充值/切换配置    |
| 地址不可达      | 提示「接口地址无法访问」，附地址检查建议 |
| 模型不存在      | 提示「模型不存在」，附模型名检查建议   |
| 超时         | 提示「连接超时」，附重试         |
| Ollama 未启动 | 提示「未检测到本地服务」，附启动指引   |
| 保存失败       | 保留表单，提示失败原因，可重试      |
| 流式中断       | 保留已生成内容，提示「生成中断」，可重试 |

## 十五、附录

### 15.1 原型思路（设置窗口 AI 分区）

设置窗口新增「AI 助手」分区（`AISection` 组件），复用现有 `settings-section` / `settings-item`  
视觉结构（卡片 + 左文案右控件），挂载位置在 `SettingsWindow/App.tsx` 的 `AppearanceSection`  
之后。分区内含三种模式，随总开关与模式单选切换：

**模式一 · 使用自己的模型（小白主路径，默认）**

```
┌──────────────────────────────────────────────────┐
│ AI 助手                                       [开] │
├──────────────────────────────────────────────────┤
│  ○ 使用自己的模型（推荐）   ○ 本地 Ollama         │
│                                                  │
│  服务商      [ DeepSeek ▾ ]                       │
│  接口地址    [ https://api.deepseek.com/v1 ]      │ ← 按服务商预填，只读
│  API Key     [ sk-**** ] [获取 Key] [测试连接]    │
│  模型名      [ deepseek-chat ▾ ]                  │ ← 按服务商预填
│                                                  │
│  ▸ 高级参数（默认折叠）                           │
│    ├─ Temperature     ═══●══════  0.7            │
│    ├─ 上下文长度      [ 32K ▾ ]                  │
│    └─ 系统提示词      [ （可选） ]                │
│                                                  │
│  ● 连接成功，可以直接使用                          │ ← 绿色状态条
└──────────────────────────────────────────────────┘
```

**模式二 · 自定义接口（资深用户）**

```
┌──────────────────────────────────────────────────┐
│ AI 助手 · 自定义接口                          [开] │
├──────────────────────────────────────────────────┤
│  接口地址    [ https://your-endpoint/v1 ]         │ ← 任意 OpenAI 兼容端点
│  API Key     [ sk-**** ]              [测试连接]  │
│  模型名      [ gpt-4o / deepseek-chat / ... ]     │ ← 可手输
│                                                  │
│  ▾ 高级参数（默认展开）                           │
│    ├─ Temperature     ═══●══════  0.7            │
│    └─ Top-p           ════●═════  0.9            │
│                                                  │
│  ● 测试失败：Key 无效（401）                       │ ← 红色状态条，错误归一
└──────────────────────────────────────────────────┘
```

**模式三 · 本地 Ollama（隐私/离线）**

```
┌──────────────────────────────────────────────────┐
│ AI 助手 · 本地 Ollama                         [开] │
├──────────────────────────────────────────────────┤
│  ○ 使用自己的模型（推荐）   ● 本地 Ollama         │
│                                                  │
│  本地服务探测  localhost:11434                    │
│    ● 已检测到 Ollama，共 3 个模型                 │
│  选择模型      [ qwen2.5:7b ▾ ]                   │
│                （llama3.1 / deepseek-r1 ...）      │
│                                                  │
│  说明：本地模型无需 API Key，数据不出本机          │
└──────────────────────────────────────────────────┘
```

**关键交互说明**：

| 控件 | 行为 |
|------|------|
| 总开关 | 关闭时隐藏下方全部表单，仅保留开关；AI 功能调用时若关闭则提示「请先在设置中开启 AI」 |
| 模式单选 | 切换时重置表单区域，但保留另一模式已保存的配置 |
| 服务商模板 | 选中即预填「接口地址 + 模型名」；改地址/模型名即视为「自定义」，模板高亮取消 |
| 获取 Key | `shell.openExternal` 打开所选服务商官方申请页，并展示 3 步图文指引 |
| 测试连接 | 内联状态条反馈（不弹窗）；成功绿条、失败红条并写明原因（401/超时/地址不可达/模型不存在） |
| 高级参数 | 模式一折叠、模式二展开；全部有默认值，未展开即用默认 |

**异常状态条文案（错误归一，不白屏不转圈）**：

| 场景 | 状态条文案 |
|------|-----------|
| 连接成功 | 连接成功，可以直接使用 |
| Key 无效 | 测试失败：Key 无效（401） |
| 额度不足 | 测试失败：额度不足（402/429） |
| 地址不可达 | 测试失败：接口地址无法访问 |
| 模型不存在 | 测试失败：模型不存在（404） |
| 超时 | 测试失败：连接超时，请重试 |
| Ollama 未启动 | 未检测到本地服务，请先启动 Ollama |
