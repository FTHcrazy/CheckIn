# 嵌套子地图 · 主方案（数据模型 / 场景图 / 两条生成路径 / 无级缩放 / 缓存扩展）

> 状态：**实现中**（主方案已落地到 2.18.0）。Phase 2（数据模型 / 递归场景图 / 两条生成路径 /
> 子图渐入与内部 LOD）与 Phase 2.4（子图自己的海岸、海面、分区、素材、地名、剔除）已实现；
> 仍开放：路径 A′「绑定已有地图」的跨地图选择器（依赖地图文档落库）、子图内部的静态层缓存。
> 归属 R-MAP 系列（地图渲染改造）的**增量**：新增「区块内嵌子地图」
> （单图/多图**无级嵌套**）能力。
>
> 本文是嵌套子图的**主方案**；与之平级的是 `nested-submap-boundary.md`
> （无级缩放丝滑度与**边界割裂感**的成熟方案选型专篇）。边界过渡的实现细节见那篇，本文只引用其结论。
>
> 用户确认的两个决策：
> ① 「多图嵌套」的最小渲染单位 = **区块内嵌子地图**（每个区块内部可再放一张独立可缩放的地图）；

>
> 用户追加的核心约束（本文设计的最高优先级）：
> > **「所有的嵌套大小地图，都需要支持无级缩放（这是核心亮点），渲染保持高性能要求。」**

## 0. 结论速览

1. **架构定调：单一场景图 + 递归子树 + 局部坐标变换。** 明确排除两个错误方向：
   - ❌ 子图烤成位图 —— 烤死即失去无级缩放，且每张 4096² 纹理内存爆炸；
   - ❌ 每张子图独立 WebGL 上下文 —— `Application` 一次只能一个上下文，多开需重写事件/纹理/导出。
2. **数据模型**：`MapSubmap` 是「独立坐标系 + 独立内容」的完整小地图，挂在 `MapRegion.submap`
   上，递归定义，可无限嵌套。全部新字段可选，老文档零迁移成本。
3. **场景图**：子图是 `world` 下的一棵递归子树，`submapTransform`（`position+scale`）承载
   「子图本地 → 父图世界」变换，`clipMask` 用区块多边形裁剪，递归零额外代码。
4. **两条路径落地同一个结构**：路径 A（小图嵌入）用贴合变换 + mask；路径 B（圈定区域）用
   `generateHierarchy` 的 `container` 参数现场生成，边界天然重合。另有**路径 A′**（绑定已有地图到
   指定区块），是用户「小溪村 → 县城」场景的落点（见 §4.1.1）。
5. **无级缩放 + 高性能**：缩放仍是单一事实源（根 `world.scale`），子图 LOD 用「等效缩放」
   `z × submapTransform.scale` 查自己的 `levelAlphas`，权重只落容器 alpha，几何零重建。
6. **子图渐入**：父图尺度只看「绑定态轮廓」，缩到阈值才平滑淡入子图，再深才无级显露子图内部
   细节（见 §5.3）——这是「县城尺度只看小溪村大致轮廓」的落地机制。
7. **质感一致**：子图复用 `coastBake` / `style` / 纸纹，缓存倍率封顶 `STATIC_CACHE_MAX_RES=3`。

## 2. 数据模型设计（`types.ts`）

新增「子地图」结构，挂在区块上（`MapRegion` 增加可选字段，向后兼容）：

```ts
/** 一张嵌套子地图（区块内嵌的独立地图） */
export interface MapSubmap {
  id: string;                       // 前缀 sm_
  /** 子图自己的世界范围（相对子图本地坐标），子图内部一切几何以此为参照 */
  bounds: Rect;
  /** 子图自己的陆地（null = 只有底图海面，未生成陆地） */
  land: MapLand | null;
  /** 子图自己的区块树（递归：子图的区块还能再嵌子图） */
  regions: MapRegion[];
  /** 子图自己的素材 / 标注（复用 MapElement / MapLabel，level 语义在子图局部） */
  elements: MapElement[];
  labels: MapLabel[];
  style: MapStyle;                  // 子图可独立换风格
  baseImageId: string;              // 子图可独立换底图（默认继承父图，见 boundary 篇 §4）
}

/** MapRegion 增加字段 */
interface MapRegion {
  // ...现有字段不变
  /** 区块内嵌的子地图；undefined = 该区块没有子图（老数据兼容） */
  submap?: MapSubmap;
  /**
   * 子图「渐入」的父图缩放阈值（可选）。父图缩放 ≥ 此值，子图才开始淡入
   * （低于它时只显示「绑定态轮廓」，见 §5.3）。缺省 = 自动按区块屏幕尺寸反推，
   * 见 `enterScaleForRegion`。
   */
  submapEnterScale?: number;
}
```

**关键设计点**：

1. **子图是「独立坐标系 + 独立内容」的完整小地图**，不是把父图一部分切开复用。它的
   `land` / `regions` / `elements` / `labels` 全部在子图局部坐标表达，与父图零耦合。
2. **递归定义**：`MapSubmap.regions: MapRegion[]`，而 `MapRegion.submap?: MapSubmap` —— 理论上
   可无限嵌套（对应「无级嵌套」）。
3. **向后兼容**：新字段全可选，`migrateDoc` 的「未知字段原样保留」策略天然覆盖，老文档打开不变。
4. **子图内容不进父图撤销栈坐标空间**：子图内部编辑是独立事务，避免一次子图拖动污染父图快照。
   （实现上子图编辑 commit 时做深拷贝快照，或用结构化克隆隔离。）

**「绑定态」与「子图内容」是两个概念**：`submap` 一旦存在，区块就处于「绑定态」——在父图尺度下
它表现为一个**区块轮廓 + 淡色填充**（表示「这里绑了一张子图」），而**不是**直接显示子图内部内容。
子图内容是否可见、显示多细，由 §5.3 的「渐入权重」按父图缩放决定。这让「县城尺度只看小溪村大致
轮廓」成为可能：轮廓来自**父图区块**，与子图内容无关。

## 3. 场景图架构（`MapCanvas/index.tsx`）

把现有「一套图层」（staticLayer + coast + regionLayer + elementLayer + labelLayer + overlay）
抽成可复用的**子场景构造器**。父图区块渲染时若 `region.submap` 存在，就在该区块内挂子图子树：

```
world
├─ staticLayer / coast / regionLayer / elementLayer / labelLayer / overlay   ← 父图
└─ submapLayer（z 序插在父图 elementLayer 与 labelLayer 之间）
   └─ submapTreeNode（每个带 submap 的区块一个）
      ├─ clipMask        ← 用该区块 polygon 做遮罩，子图内容不越界
      └─ submapTransform ← 承载「子图本地 → 父图世界」仿射变换
         ├─ staticLayer / coast / regionLayer / ...   ← 子图完整一套图层（递归）
         └─ submapLayer（子图的区块还能再嵌）...
```

**三个关键机制**：

1. **子图挂载的变换**：`submapTransform` 位置 = 该区块 `polygon` 包围盒中心，缩放 =
   `min(blockW / submap.bounds.width, blockH / submap.bounds.height)`（子图内容自适应铺满区块）。
   这是两条路径共同的落地处（路径 A/B 共用同一个 `fitSubmapTransform` 纯函数）。
2. **裁剪**：`clipMask` 用区块多边形做 mask，子图内容严格不出区块边界——这是「边界约束」在
   渲染层的统一解法（边界过渡的羽化见 boundary 篇）。
3. **递归**：子图内部复用同一构造器，因此「子图的区块再嵌子图」零额外代码。

## 4. 两条生成路径 + 边界约束方案对比

### 4.1 路径 A：先生成小地图，再嵌套进大地图

流程：用户先独立画/生成一张小图（或从已有图选），再指定某区块把这张小图放入。

**核心难点 = 边界约束**（小图是矩形、区块是不规则多边形），四种可行方案对比：

| 方案 | 做法 | 优点 | 缺点 | 建议 |
|---|---|---|---|---|
| **A1 外接矩形 + 多边形遮罩** | 小图按区块包围盒缩放贴合，再用区块 polygon 做 mask 裁掉出界部分 | 实现最简单；内容不变形失真；无级缩放天然保留；与场景图 clipMask 完全一致 | 小图四角被裁掉 | ✅ 首选 |
| **A2 仿射贴合（旋转/拉伸对齐主方向）** | 用完整仿射变换（含旋转、非等比缩放）对齐主方向 | 贴合度更高、裁掉更少 | 非等比拉伸变形；旋转引纹理锯齿 | 作为 A1 可选增强 |
| **A3 内容重排（区块形状当容器重切）** | 把区块多边形当 `container` 重跑 `generateHierarchy` | 严丝合缝、无裁切、与父图风格统一 | 失去「独立小图」语义；无法复用已画好的小图 | 仅路径 B 用 |
| **A4 边界融合（多边形求交）** | Greiner–Hormann 等真实求交 | 几何最精确 | 成本风险极高；与手绘质感冲突 | ❌ 不做 |

**结论：A1 为主，A2 可选增强，A3 用于路径 B，A4 不做。**

> 边界过渡的「共享几何 + 羽化」叠加在 A1 之上，进一步消除硬边——见 boundary 篇。

#### 4.1.1 路径 A 变体：绑定「已有地图」到指定区块（用户核心场景）

用户的实际旅程往往不是「拖一张图进去」，而是「**把一张已经独立编辑好的地图，绑定到当前图的某个
区块**」——例如：先独立编辑了「小溪村」，之后生成「县城」，把县城的某个区块**绑定**到小溪村。

它与 A1 的**唯一区别**是「目标矩形从哪来」：

| 变体 | 目标矩形 | 行为 |
|---|---|---|
| A1 自由嵌入 | 用户拖出的任意矩形 / 手动指定 | 贴合该矩形，靠 mask 裁剪 |
| **A1′ 绑定到区块** | 点选一个已有区块，取其 `polygon` 包围盒 | 贴合该区块，`submapEnterScale` 自动按区块屏幕尺寸反推 |

两者的 `submap` 数据结构、`submapTransform`、`clipMask` **完全相同**，只是「谁算目标矩形」不同。
因此 A1′ 不引入任何新机制，只是 `embedSubmap` action 多一个「目标 = 区块 id」的入参分支。

> ⚠️ **语义澄清**：A1′ 是「绑定一张**已存在**的图」（内容来自外部），属于路径 A，**不是**路径 B。
> 路径 B 是「圈定区域后**现场生成**新内容」，两者的 `submap` 内容来源不同（引用/拷贝 vs 现场生成），
> 但落地同一数据结构。用户场景「圈定县城区块 → 绑定小溪村」是 A1′，不是 B1。

### 4.2 路径 B：先生成大地图，再圈定区域生成对应小地图

流程：用户在大图上框选/点选一个区块（或任意矩形），系统在该区域内生成一张新小图。

这一路径**天然没有「小图并入」的边界问题**（小图是被「圈」出来的，边界就是圈选区本身）。两个子方案：

- **B1 按区块圈选（推荐）**：点选已有区块，子图 `bounds` = 该区块包围盒，内容用
  `generateHierarchy` 的 `container` 参数（`regions.ts` 第 890 行，已原生支持）在该区块内重新生成。
  生成后小图立即「无缝长在」该区块里。
- **B2 任意矩形圈选**：拖任意矩形作为子图 bounds，内容在矩形内生成。边界简单（矩形），但矩形
  可能与父图区块错位，视觉上「子图边界线」会横穿父图区块——需额外画一圈子图外框线。

**两条路径落地同一数据结构 + 同一场景图节点**，区别只在「谁生成内容、变换怎么算」：
- 路径 A：内容来自外部小图 → `submapTransform` = 贴合变换，边界靠 mask；
- 路径 B：内容现场生成 → `submapTransform` = 贴合变换（bounds 就是区块），边界天然重合。

## 5. 无级缩放 + 高性能保证（核心约束）

直接回答用户强调的「**所有嵌套大小地图都必须无级缩放 + 高性能**」：

1. **缩放仍是单一事实源**：所有子图不各自持有缩放，唯一缩放仍是根 `world.scale`。滚轮每一格
   依旧只改 `world` 的 `position` + `scale` 两个浮点数——既有架构底线，子图子树只是被连带变换，
   零额外成本。
2. **子图 LOD 是「局部 LOD」**：每个子图子树用子图自己的 `bounds` + 区块树数量，独立算一组
   `naturalScales` / `levelAlphas`（`lod.ts` 已是纯函数，换 `bounds` 即复用）。但激活它需换算：
   子图局部等效缩放 `z · submapTransform.scale`，用这个值查子图自己的 `levelAlphas`。这样
   「缩进去看大图 → 大图的子图开始显露它自己的洲/国家/郡」也是无级的。
3. **层级权重仍只落在容器 alpha**：子图内部继续「每级一个容器，权重写 alpha」，不重建几何。
   子图交叉淡化与父图完全同构。
4. **剔除递归化**：`cull.ts` 粗剔除按层级容器做，扩展到子图时，每个 `submapTransform` 先算
   自己的全局包围盒（`toGlobal`），不在视野内整棵剪掉——递归剪枝，俯瞰时视口外子图整棵不画。

### 5.3 子图渐入：父图尺度轮廓 vs 子图尺度无级细节（用户核心约束）

用户明确要求：**「小溪村地貌在县城地图的层级只能看一个大致轮廓」**。这条不能靠「子图 LOD 缩到
最粗」实现——因为子图最粗一级仍是「小溪村自己的陆地」，那已经是「细节」，不是「轮廓」。正确的
做法是把「父图尺度的轮廓」和「子图尺度的无级细节」分成**两个连续阶段**：

```
父图缩放 z 递增 →
  z < z_enter         → 子图内容完全不可见；区块显示「绑定态轮廓」
                        （区块边界 + 淡色填充，表示「这里绑了一张子图」）
  z_enter ≤ z < z_detail → 子图以「大致轮廓」淡入（submapEnterWeight 从 0→1）
                        此时子图等效缩放仍小，只露它自己的最粗一级（大致轮廓）
  z ≥ z_detail        → 子图进入自己的无级 LOD（等效缩放驱动，洲/国家/郡逐级显露）
```

三件事，全部便宜、纯函数化：

1. **绑定态轮廓**：`region.submap` 存在但 `z < z_enter` 时，父图该区块的渲染样式从「普通区块」
   切换为「绑定态」（轮廓 + 淡色填充 + 可选一个「子图」小图标）。轮廓来自**父图区块 polygon**，
   与子图内容无关——这就是「县城尺度看小溪村 = 一个轮廓块」。
2. **渐入权重 `submapEnterWeight(z, enterScale)`**：复用 `lod.ts` 的 `bandProgress`（log2 域
   smoothstep）思路，在 `z_enter ~ z_detail` 之间从 0 平滑到 1，乘在 `submapTreeNode.alpha` 上。
   子图是「淡入」的，不是突现。`z_detail = z_enter × 2^(2·LOD_BAND_OCTAVES)` 左右，与既有
   交叉带宽度同源。
3. **进入阈值 `enterScaleForRegion(region, viewport)`**：默认按「该区块在屏幕上长边约
   `LOD_BLOCK_PX`（360px）时」反推父图缩放，即「用户已经能看清这个区块」才让它渐入；也可由
   `MapRegion.submapEnterScale` 手动覆盖。

这样「县城尺度看轮廓」和「缩进去看小溪村内部无级细节」是两个**连续的、无跳变的**阶段，正好
对应目标场景的第 4、5 条。

## 6. 底图质感在各缩放层级一致（目标四的扩展）

既有 `STATIC_CACHE_MAX_RES = 3` 机制已解决父图底图模糊。扩展到子图，规则一致，只是每棵子图
子树各自缓存：

- 子图 `staticLayer`（投影 + 海面）同样 `cacheAsTexture`，倍率 = `min(3, max(1, 2^ceil(log2(等效缩放))))`，
  跨 2 的幂次档才重烤；
- 子图 `coast` 同样用 `bakeCoast` 烘成 RenderTexture，`bakeKey` 换成子图自己的 `land + style + resolution`；
- 关键约束：**缓存倍率永远封顶 3**（与 `ZOOM_ABS_MAX=40` 的既有推理一致——40/3≈13 倍拉伸是海面
  上限，再高无更多细节）。子图因「贴在大图里被整体放大」，其等效缩放可能超过父图，但缓存倍率
  仍封顶 3，不会无上限涨纹理内存。

这样「缩到任何一层、任何一张子图」，底图质感都与父图一致，不出现「子图比父图糊」的断层。

| 渲染 | `MapCanvas/index.tsx` | 一套图层抽成子场景构造器；新增 `submapLayer` + `submapTreeNode`（含 clipMask）；递归挂载；子图 LOD/缓存/剔除递归化 |
| 状态 | `useMapEditor.ts` | 新增 `embedSubmap`（路径 A）、`carveSubmap`（路径 B）两个 action，走 `commit` 入撤销栈 |
| 文档 | `docs/prd/prd-map-render/` | 本文 + `nested-submap-boundary.md` 边界专篇 |

**改动边界**：`regions.ts` / `coastBake.ts` / `lod.ts` / `coords.ts` 这些**纯函数核心几乎不动**
（它们是前几批已闭环、有测试钉住的东西），新能力全部以「新增入口函数 + 递归容器」形式叠加，
不破坏现有测试语义。

## 8. 验证方式

1. **单元测试（纯函数，最易钉住）**：
   - `submapEffectiveScale` 换算正确性（父缩放 × transform 缩放）；
   - `fitSubmapTransform` 对「外接矩形贴合」的缩放/位移正确性；
   - `generateSubmapInRegion` 产出的子图 `regions` 全部落在父区块 polygon 内（复用 `pointInPolygon` 断言）；
   - `submapEnterWeight`：`z < z_enter` 恒 0、`z ≥ z_detail` 恒 1、中间单调平滑；
   - `enterScaleForRegion`：按区块屏幕长边 ≈ 360px 反推的阈值正确，且受 `submapEnterScale` 手动覆盖；
   - `migrateDoc` 对老文档（无 `submap` / `submapEnterScale` 字段）的兼容性。
2. **截图比对（视觉正确性）**：
   - 单图：嵌套前 vs 嵌套后，子图质感与父图一致（海岸四层、纸纹、风格）；
   - 多图：大图嵌 3 张子图，缩到不同层级，子图边界无越界、无重影、交叉淡化平滑；
   - 无级缩放：从整图俯瞰一路缩到最深子图的郡，全过程无跳变、底图不糊。
3. **性能指标（高性能要求）**：
   - 滚轮缩放：无论嵌套几层，每格只改根 `world` 的 2 个浮点数，几何零重建——用「子节点数不变」
     断言 + 帧率不跌（目标 ≥ 60fps，沿用架构 L-7）；
   - 内存：子图缓存纹理总尺寸受 `STATIC_CACHE_MAX_RES=3` 封顶，不随嵌套深度线性爆内存。

### 8.1 端到端验收用例：小溪村 → 县城（钉死的用户场景）

> 这是「绑定已有地图 + 父图尺度轮廓 + 子图尺度无级细节」的完整回归用例，验收时逐条核对。

1. 用户独立编辑一张「小溪村」地图（有完整陆地、区块树、素材，可无级缩放）。
2. 用户生成一张「县城」区域地图，得到县城的区块树。
3. 用户在县城地图上点选某个区块，执行「绑定到小溪村」→ 走路径 A′（§4.1.1），
   该区块进入**绑定态**。
4. **县城尺度（缩到能看全县城）**：小溪村绑定的区块只显示**大致轮廓**（绑定态轮廓 + 淡色填充），
   **不显示**小溪村的内部细节（洲/国家/郡、素材、标注均不可见）。
5. **放大县城、缩向该区块**：区块轮廓**平滑淡入**为小溪村（无突现、无跳变），先露出小溪村的
   大致轮廓（其最粗一级）。
6. **继续放大**：小溪村进入自己的无级 LOD，逐级显露其洲/国家/郡、素材、标注，全过程无级、不糊。
7. **再缩回县城**：上述过程**逆序可逆**——小溪村逐级收敛回「大致轮廓」，最终只剩绑定态轮廓。

**验收判定**：第 4 步若直接显示了小溪村内部细节，则「子图渐入」未生效（P0 失败）；第 5、6 步若
出现跳变或边界硬切，则无级缩放 / 边界过渡未达标。
