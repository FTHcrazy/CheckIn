# R-REG-10 · 子图内部的区域编辑（立项需求稿）

> 状态：草案
> 输入：region-editing.md（R-REG-10 条目，:161）、spec/map-interaction-spec.md（定稿）、nested-submap-main.md（Phase 2/2.4 已落地）、nested-submap-boundary.md（羽化 2.32.0）
> 基线：CheckIn **2.36.0**（工作区）｜`src/windows/MapWindow/` 44 文件 / 750 用例（全量并发有 1 条重组件用例超时、隔离复跑通过 —— 不是"750 全绿"）

**一句话需求**：把已闭环的 P0 区域编辑能力（画区 / 合并 / 高亮分级）搬进子图，让用户在子图视野里编辑 `submap.regions`，且父图数据零污染、撤销行为可预期。
**本稿体裁**：`scope`（定范围与判据，不含实现方案；技术拆解归架构师）。

## §6 不做什么与后续

本条只做"把 P0 三件事（画区 / 合并 / 高亮分级）搬进子图 + 建立编辑作用域"，闭环后 P1 顺位建议 **R-REG-07 → R-REG-06 → R-REG-08 → R-REG-09**：07 是误操作兜底最刚需、且孤儿规则已由 R-REG-04 定义清楚；06 是原文"微调"的另一半、用户价值最高但需 wobble 重算；08 是纯属性可随时插队；09 是唯一 L 级（polygon 布尔）最后做。
