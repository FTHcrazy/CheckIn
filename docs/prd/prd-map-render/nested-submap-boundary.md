## 0. 结论速览

1. **「丝滑」你已具备 80%**：PixiJS WebGL + `lod.ts` 帽函数（partition of unity）就是
   高德/Google Maps「矢量 + WebGL + 连续 LOD」的同一套思想。缺的不是缩放连续性，而是
   **边界过渡的连续性**。
2. **边界割裂感的根因不是渲染，是几何**：子图是「独立坐标系的另一张图」，塞进父图区块时
   多了一次仿射贴合 + 遮罩，于是出现「贴上去的硬边」。解法是让子图内容**在几何上长在父图里**，
   而不是贴进去。
3. **成熟方案的选型结论**（详见 §2）：
   - ✅ **共享边界几何**（复用 `regions.ts` 已实现的 `HostEdge` 机制）—— 对齐几何，消除错位重影；
   - ✅ **边界羽化带**（子图边界向内 alpha 渐隐 + 共用底图/纸纹统一色）—— 消除色差硬边；
   - ✅ **岛屿形态 / 自动过渡地貌**（可选增强）—— 用有机轮廓从审美层面消解割裂；
   - ❌ **真实多边形布尔运算**（Greiner–Hormann 等）—— 不做，与手绘质感冲突、性价比极低。
4. **「自然地貌边界」正确形态是「可选增强」而非「强制前置」**（详见 §3）：
   系统自动兜底（几何对齐 + 羽化）+ 用户可选地貌美化。强制设边界会抬高门槛、阻塞
   路径 B、且不解决几何错位，是负优化。

## 1. 无级缩放的「丝滑」从哪来（成熟方案对齐）

### 1.1 高德 / Google Maps 的丝滑本质

它们**没有「嵌套小图」**，所有行政区、POI、路网都在**同一个连续坐标系**里，缩放只是改
camera 的 scale。所谓「省界/市界切换」是同一批矢量数据按 LOD 权重**淡入淡出**——边界线
在数据上本来就连续，不存在「两块拼接」。

### 1.2 本项目现状对齐

| 高德/Google 的机制 | 本项目对应实现 | 状态 |
|---|---|---|
| 矢量 + WebGL | PixiJS 8.22.0 WebGL 渲染 | ✅ 已具备 |
| 缩放只改 camera scale | 缩放只改根 `world` 的 `position`+`scale` | ✅ 已具备 |
| 连续 LOD（无级） | `lod.ts` 帽函数 `levelAlphas`（Σα≡1，log2 域 smoothstep） | ✅ 已具备 |
| 同坐标系、无拼接 | —— | ❌ **缺：子图是独立坐标系，产生拼接** |

**结论**：丝滑的缩放连续性你已经有了。缺口是「子图嵌套」带来的「第二坐标系 + 拼接」，
即边界过渡的连续性。所以本文的重心是 §2、§3，而不是重做缩放。

### 1.3 子图的 LOD 是「局部 LOD」（把无级延伸到嵌套）

缩放仍是**单一事实源**（唯一缩放 = 根 `world.scale`）。每个子图子树内部用子图自己的
`bounds` + 区块树数量，独立算一组 `naturalScales` / `levelAlphas`（`lod.ts` 是纯函数，
换 `bounds` 即复用），但**激活它的等效缩放**是：

```
submapEffectiveScale = 父图缩放 z × submapTransform.scale
```

用这个等效值查子图自己的 `levelAlphas`。这样「缩进去看大图 → 大图的子图开始显露它自己的
洲/国家/郡」同样是**无级**的，与父图完全同构。层级权重仍只落在容器 alpha，不重建几何。

## 2. 边界割裂感 —— 成熟方案全景与选型

### 2.1 市面上真实在用的四类方案

| # | 方案 | 代表 | 本质 | 对「插画质感地图」的适配 |
|---|---|---|---|---|
| 1 | 无缝裁剪（同坐标系） | 高德 / Google | 没有子图，同一坐标系连续 | 方向性指导：让子图「长」在父图里 |
| 2 | 边界羽化 / 融合带 | 游戏地形 / Tiled 瓦片 / 开放世界插画 | 接缝处做 alpha 渐变或噪声羽化，不硬切 | ✅ 成本最低、最对口 |
| 3 | 边界细化 / 共享几何 | Mapbox 风格切换 | 同一几何多级简化 + 顶点匹配 + 权重插值 | ✅ 本项目 `HostEdge` 已是此思想 |
| 4 | 真实多边形布尔运算 | GIS（ArcGIS / QGIS） | 子图 ∩ 父区块做真实求交 | ❌ 机械精确，与手绘质感冲突、成本高 |

### 2.2 选型结论（按优先级）

**首选 —— 方案 1 + 3 融合：共享边界几何 + 同一坐标系贴合**

- 让子图内容**沿用父区块的边界折线**作为自己的外轮廓（复用 `regions.ts` 已实现的
  `HostEdge`「子块外轮廓沿用父级折线」机制）。这样子图边缘与父图区块边界是**同一条线**，
  天然无错位、无重影——这正是 Mapbox「共享几何」思想，也是你代码里已经埋好的伏笔。
- 子图内容若设计成「岛屿」形态（`land.ts` 已支持多岛），它自带海岸柔边 + 白边，
  「浮在区块里的一块大陆」从审美层面消解割裂。

**增强 —— 方案 2：边界羽化**

> ✅ **已落地（2.32.0）**：`erase` 混合 + `AlphaFilter` 隔离的渐隐带（见 §2.2 末「落地口径」）。

即使共享几何，子图底图海面与父图底图海面若颜色/纹理不一致，仍会有一条色差缝。解法：

- 给子图边界向内做一个 8~16 世界单位的 **alpha 渐变羽化带**（`Graphics` 画「沿边界向内渐隐」
  的遮罩，复用 `BlurFilter` 思路）；
- 让子图海面与父图海面**共用同一张纸纹 + 同一 `baseImageId`**，从根上让颜色一致。

**落地口径（2.32.0，与上面的初稿有三处有意偏离）**：

1. **带距用子图本地单位（24 ≈ 纸宽 2.3%），不是父图世界单位**：羽化画在子图本地坐标里
   随贴合变换缩放，按本地单位让「羽化 ≈ 纸宽的固定比例」，与区块大小无关。
2. **`erase` 混合 + `AlphaFilter` 隔离，不是 BlurFilter**：`erase` 是 destination-out 的基础
   混合模式（直接设 GL state，不走 advanced 批处理的纹理隔离）—— 不隔离会把**父图已画进
   帧缓冲的像素一起擦穿**；给子图 `content` 挂 alpha=1 的 `AlphaFilter` 让它先渲进独立纹理，
   erase 只擦子图自己的内容，羽化处自然透出父图地表。零滤镜开销（AlphaFilter 视觉恒等）。
3. **环带 = 内缩多边形的中点描边（alignment 0.5），不打孔填充**：几何是纯函数
   （`insetPolygon` / `featherBands`，miter 锐角限幅防尖刺），每段宽 `总宽/6`、擦除强度取
   环带中点的线性值，肉眼无台阶。只挂在**有海面**的子图上（路径 A′ 的色差缝；路径 B
   没有自己的海，无缝可糊）。

**不做 —— 方案 4：布尔运算**

理由：与手绘质感冲突 + `regions.ts` 已明确「0.2% 越出按可接受处理」（说明早已判定这条路
性价比低）。

### 2.3 一个设计反转：子图 = 区域的「更多细节」，而非「另一张图」

若把「子地图」理解为「这块区域放大后的更多细节」，而非「外来图塞进来」，则它与大图之间
**没有边界**——它和大图是同一张图的两个分辨率档，边界就是区块边界本身，天然连续。

这同时满足两条生成路径：

- **路径 B（先大地图再圈定区域）**：圈定区块 → 在区块内生成更细一层内容（复用
  `generateHierarchy` 的 `container` 参数）。本就是「同一张图继续往下切」，边界严丝合缝，零割裂。
- **路径 A（先小图再嵌入）**：小图嵌进来时，不把它当「外来图」，而是当「这块区域的高分辨率
  版本」——用共享几何让它「长」进去，再用羽化消掉色差。

## 3. 「自然地貌边界」：可选增强，而非强制前置

### 3.1 用户直觉对在哪

「用山脉、草原、海岸等自然地貌当边界」确实是消解割裂感的真实高级做法（制图学里「以山脉、
河流为界」同理）：子图四周若本就画着不规则地貌，边缘天然有机、渐隐，不需要额外处理。

### 3.2 但「强制」是错的（三条理由）

1. **违背核心亮点「无级缩放 + 高性能」**：嵌图应是零门槛、立即生效。强制「先设一圈山脉」
   会让「嵌图」从一步变成一次义务劳动，且多数用户无此意识。
2. **强制设边界 ≠ 自动模糊**：「山的形状」和「父区块多边形」仍对不上。它解决的是子图边缘
   观感，**没有自动解决几何错位**（割裂的真正来源），是把「内容软化」误当成「几何对齐」。
3. **阻塞最顺的路径 B**：路径 B 天然无边界问题。强制前置会把这条最顺路径也拖慢变复杂。

### 3.3 正确形态：自动兜底 + 可选增强

| | 强制设边界 | 自动兜底 + 可选地貌（推荐） |
|---|---|---|
| 用户门槛 | 高（必须先懂「边界要设地貌」） | 低（直接嵌） |
| 割裂感 | 只软化，不对齐几何 | 几何对齐（自动）+ 观感软化（可选）双保险 |
| 阻塞主路径 | 是 | 否 |
| 与无级缩放关系 | 被前置步骤拖累 | 无冲突 |

- **第一层（默认，零成本）**：系统自动边界过渡（共享几何 + 羽化 + 岛屿形态），用户随手一嵌即丝滑。
- **第二层（可选，更好的结果）**：界面**建议**（不强制）用户给四周放一圈 `SPRITES` 里已有的
  山脉/森林，或一键「沿边界生成山脊/海岸」；素材用「沿边界等距排布 + 随机缩放/旋转」自动铺一圈。

### 3.4 更优替代：把地貌边界做成**生成器输出**，而非用户输入

让「自然边界」自动生成：子图嵌入时，系统沿子图边界**自动生成一圈过渡地貌**（模糊植被/山脊
渐变带，用 `fbm` 噪声做随机起伏）——与 `land.ts` 生成海岸、`regions.ts` 崎岖化边界是**同一套
噪声工具**，几乎零新增成本。「自然边界」从「用户必须做」变成「系统免费给」，门槛仍为零。

## 4. 实现要点（可执行，不含代码）

> 以下为边界过渡的落地要点，数据模型 / 场景图递归 / 两条生成路径 / 缓存扩展的完整方案，
> 见主方案文档（待补，本文是其「边界过渡」专篇）。

1. **共享边界几何**：子图外轮廓折线 = 父区块 `HostEdge` 折线（直接引用参数区间切下的子折线，
   与 `regions.ts` 第 4 步「继承」同机制），不做第二次崎岖化，避免父子两条线错位。
2. **边界羽化带**：子图 `staticLayer` 上叠一个 `Graphics` 遮罩，沿边界向内做 8~16 世界单位
   的 alpha 渐变（`BlurFilter` 思路，烘进子图自身的 `RenderTexture`，运行期零成本）。
3. **共用底图/纸纹**：子图 `baseImageId` 默认继承父图；纸纹默认沿用，从根上统一颜色。
4. **自动过渡地貌（可选）**：沿子图边界等距采样 → `fbm` 横向位移（复用 `regions.ts` 崎岖化
   噪声函数）→ 生成一圈 `SPRITES` 地貌素材（随机缩放/旋转）→ 作为「可选一键美化」入口。
5. **LOD 局部化**：新增纯函数 `submapEffectiveScale(z, transformScale)`，子图 LOD 用等效缩放
   查自己的 `levelAlphas`；权重仍只写容器 alpha。
6. **缓存扩展**：子图 `staticLayer` / `coast` 各自 `cacheAsTexture`，倍率封顶 `STATIC_CACHE_MAX_RES=3`
   （与 `ZOOM_ABS_MAX=40` 的既有推理一致），不随嵌套深度线性爆内存。

## 5. 验证方式

1. **单测（纯函数）**：`submapEffectiveScale` 换算；共享几何「子图外轮廓 == 父区块折线」逐点相等
   （复用 `HostEdge` 断言）；自动过渡地貌素材全部落在子图边界内侧。
2. **截图比对（视觉）**：单图嵌 1 张子图、多图嵌 3 张子图，缩到不同层级，子图边界**无硬边、
   无错位重影、无色差缝**；从整图俯瞰一路缩到最深子图的郡，全过程无跳变、底图不糊。
3. **性能**：滚轮每格仍只改根 `world` 的 2 个浮点数，子节点数不随缩放变化；子图缓存纹理总尺寸
   受 `STATIC_CACHE_MAX_RES=3` 封顶，帧率 ≥ 60fps（沿用架构 L-7）。
