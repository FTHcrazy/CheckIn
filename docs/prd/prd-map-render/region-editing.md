# 区域编辑 · 增量方案（自定义层级 / 手动划分 / 区域合并 / 叶子高亮）

> 模块全貌与进度见 [map-window-overview.md](map-window-overview.md)（地图模块唯一入口）。

> 状态：**已实现**（2.19.0）：R-REG-01~05 五条 P0 全部落地并通过独立验证（QA 9 处变异 8 红，
> 第 9 处揪出一个"改了源码也不红"的假守卫并已补强）。实现期有两处对本文的修订，见
> R-REG-02 的「裁决补充」与 §8-Q1；P1（R-REG-06~10）待排。
> 本文只描述**增量**，不重写 `nested-submap-main.md` 的整体架构。
> 输入：`nested-submap-main.md`（区块内嵌子地图模型，已实现 Phase 2 + 2.4）、
> `nested-submap-elements.md`（要素的 `level` 语义）、代码基线 `MapEditorPage/{regions,types,lod}.ts`。
> 基线：**2.18.0**（嵌套子图 Phase 2 / 2.4 已落地）。
> 归属 R-MAP 系列的**增量**：区域（区块）的**编辑能力**——从"只能一键随机切"扩到
> "可配置层级 / 可手画 / 可合并 / 高亮分级"。
>
> 用户四点原话（本文逐条落成需求项）：
> 1. 生成的大地图支持**默认不划分区域**，用户**手动划分**，或者区域划分支持**用户微调**。
> 2. 用户可**定义生成的区域层级**（层数、名称、各级数量）。
> 3. 用户可选中某个**高级区域，将其子区域合并**（该高级区域成为最小单位；**若有关联地图要先提示**）。
> 4. **当前选中高亮区域效果只在最底层级的区域选中才有效果。**
>
> 本文与既有文档的边界：`nested-submap-main.md` 管"区块里嵌什么"，
> 本文管"区块本身怎么被划出来、怎么被改"。两者唯一的耦合点是
> `MapRegion.submap`——合并会删区块，**删掉的区块上挂的子图会一起消失**（§6-C）。

## 0. 结论速览

1. **四点需求全部本轮做，但只做每条的最小可交付切片（P0）；手动划分的"顶点微调"整条排到 P1。**
   理由：需求 1 原文是"手动划分，**或者**微调"——两条路径是**或**关系，交付任一条即闭环。
   手画（L）与顶点编辑（L）都做会把本轮撑成两个月；手画是"从零到能用"，顶点编辑是"能用变好用"。
2. **冲突 A（需求 4 vs 需求 3）：把「选中」与「高亮」解耦，判据用「叶子」而不是「最深层级」。**
   - 任何区块**都可被选中**（选中是逻辑态，合并/命名/子图都靠它）；
   - 只有**叶子区块**（`regions.filter(r => r.parentId === P.id).length === 0`）才画**面高亮**（现状三笔）；
   - 非叶子区块被选中时画**容器态**（沿 `P.polygon` 描边 + 面板面包屑），不铺面。
   - 核心论据：合并恰恰会造出 `level` 比最深级**更浅的叶子**（把"国家"的郡全合并掉后，"国家"成为叶子但
     `level = 2`）。所以判据**只能是叶子，不能是 level**——用 level 判断的方案会自相矛盾（详见 §6-A）。
3. **冲突 B（需求 1 vs 需求 2）：不是两套入口，是同一套能力的「配置 → 两种落地」两段。**
   新增文档级 **`regionSchema`（层级定义：名称 + 数量，长度即层数）**，它是两条路径的共同前置：
   - 路径 A：`regionSchema` → 一键生成（现状 `generateHierarchy`，从读硬编码改为读 schema）；
   - 路径 B：`regionSchema` → 手动划分（画多边形，落成 `MapRegion`）。
   而"**默认不划分**"的真正病根不在生成算法，在**「生成陆地」会连带重划区块**——用户只想要陆地，
   结果区块被一起切出来。本轮把这一条掐掉，`regions` 保持空数组（该状态数据层与渲染层早已支持）。
4. **冲突 C（合并语义）**：合并 = **删除 P 的全部后代**，P 自身 `polygon / level / parentId / name / color / seed /
   submap` **一律不变**，P 变成叶子。**polygon 不重贴合**（子区块并集边界是锯齿状，重贴合要 polygon union +
   简化，本轮不背）。**被删子树里若有子图，只提示不接管**，整个合并是**一次撤销快照**（`HISTORY_LIMIT = 50`）。
5. **本轮不做**（§7 详列）：顶点微调、单区块删除、重叠自动裁剪、合并时接管子图、层级数 > 4、
   合并后边界重贴合、子图内部的区域编辑。

## 1. 现状判定表

| 需求 | 现状能力（已核实） | 缺口 | 判定 |
|---|---|---|---|
| **① 默认不划分 / 手动划分 / 微调** | 数据层已支持零区块：`createEmptyDocument()` 的 `regions` 就是 `[]`，`MapCanvas` 缺省 `regions=[]` 不画任何区块，`lod.ts` 在 `levelCount = 0` 时把素材判为"层级无关"（有测试覆盖）。**但**「生成陆地」会**连带重划区块**（`index.tsx` 里为此专门写了确认弹窗："将重新划分区块（现有 N 块会被替换）"） | ① 没有任何"画一个区块"的交互，零区块状态只能永远空着；② 无顶点/边界编辑；③ 无"只生成陆地、不分区"的出口 | **部分具备**（数据与渲染已就绪，交互能力全缺） |
| **② 自定义层级（层数/名称/数量）** | 层数：工具栏 Slider 可调 1~4，但只存在组件内 `useState`（`levelDepth`），**不进文档、不进撤销栈、只影响下一次生成**。名称：硬编码 `REGION_LEVELS`（`大陆/洲/国家/郡`），被 3 处消费——工具栏层级胶囊、`RegionPanel` 的 `levelLabel`、生成时区块 `name` 前缀。数量：只能吃 `REGION_LEVELS` 的默认值，无 UI | 名称不可改；数量不可改；层数与层数配置都不持久化（关掉窗口就回到默认 4 层） | **部分具备**（层数有一半 UI，名称/数量是全新需求，且全部未持久化） |
| **③ 合并高级区域的子区域** | **完全不存在**。`RegionPanel` 只有「聚焦此区域 / 回到全景 / 移除子图」，Store 只有整层「清除区块」 | 无合并、无删除单个区块、无子树遍历；且 `submap` 挂在 `region` 上，删区块会连带丢子图（用户已预感到这一点，故要求"合并前提示"） | **全新需求**（且与既有子图模型强耦合，必须专门设计提示） |
| **④ 高亮只对最底层级生效** | 任意层级都可被点选并高亮：`drawOverlay` 对选中区块无条件画三笔（淡填充 + 外发光 + 白内描边），代码里**没有叶子/非叶子的概念**，只有 `level` | 无"选中 vs 高亮"的分级；无叶子判定 | **全新需求**（且判据需重新定义，见 §6-A） |

**一句话**：数据层比想象中能扛（零区块、层级序号、父子关系都已就位），缺的是**交互**与**层级定义的宿主**；
唯一的真冲突是"选中"这个词同时承担了"逻辑态"和"视觉态"两个含义。

## 2. 用户故事

| # | 角色 | 动作 | 价值 |
|---|---|---|---|
| US-1 | 世界观作者 | 我生成陆地后，希望地图上**保持干净**，一个分区都没有 | 我先看到的是大陆轮廓，而不是一堆我不认识的"郡"，避免先被错误分区干扰构图 |
| US-2 | 世界观作者 | 我想**自己画**一个区域框住"北境"，并指定它是"洲"这一级 | 我脑子里的地名边界和历史边界，比随机 Voronoi 更符合设定，不用反复点"生成区块"碰运气 |
| US-3 | 世界观作者 | 我想把层级从"大陆/洲/国家/郡"改成"界/域/城/坊"，并让每级数量符合我的设定（1 界 3 域 9 城） | 命名即世界观；数量即设定（"一界三域"这种结构写进设定后，地图要能表达出来 |
| US-4 | 世界观作者 | 我把"沧澜国"下面的 7 个郡合并掉，让"沧澜国"本身成为最小单位 | 这个国家在我的设定里是**单一政区**，不该有内部划分；合并比"重新生成整棵树"精确得多 |
| US-5 | 世界观作者 | 合并时如果被删的郡里有一张已经画了很久的子地图，我希望**先被告知** | 那张子图里可能有几十个素材和地名，不能因为点了一下合并就悄悄消失 |
| US-6 | 世界观作者 | 我选中一个大洲时，不希望整个大洲被一块高亮糊住；点中一块小郡时，我又希望它明确发亮 | 高级区域是"范围"，低级区域是"目标"——两者需要的视觉强度不同，否则我永远看不清自己在操作哪一块 |

## 3. 需求池

> 复杂度：**S** ≈ 半天，**M** ≈ 1~2 天，**L** ≈ 3~5 天（含测试）。
> 编号沿用 R-MAP 系列：`R-REG-*`。

### 3.1 P0（本轮必须做）

#### R-REG-01 · 层级定义进文档（`regionSchema`）—— 需求②核心

| 项 | 内容 |
|---|---|
| 需求描述 | 把硬编码 `REGION_LEVELS` 改为**文档级** `regionSchema: { name, count }[]`；层数 = 数组长度（1~4），名称与数量逐级可编辑。所有读 `REGION_LEVELS` 的地方（工具栏胶囊、`RegionPanel` 层级名、生成时的区块 `name` 前缀）改读当前文档的 schema |
| 交互入口 | 工具栏「区块层级」下拉 → 升级为一个配置面板（Popover，`body` portal），见 §4.1 |
| 边界条件 | ① 层数只能 1~4（`REGION_LEVEL_COUNT_LIMITS` 不变）；② 名称为空 → 该级回落为 `L{n}`，不阻塞；③ 总数量 > `REGION_TOTAL_LIMIT = 600` → 合计数字标红并禁止「应用并生成」，但**允许保存**（用户可能分次生成）；④ 减少层数时，若已存在 `level ≥ 新层数` 的区块 → 二次确认"将删除 N 个超出层级的区块"；⑤ 修改 schema **不自动重排已生成的区块**（生成是显式动作） |
| 验收标准 | ① 改名为「界/域/城/坊」并生成 → 每个 `region.name` 都以对应层级的名称开头（`name` 形如 `城 12`）；② 关闭窗口再打开同一文档，配置仍在（`regionSchema` 已进文档并随快照持久化）；③ 老文档（无 `regionSchema`）读作默认 4 级 `大陆/洲/国家/郡`，渲染与生成结果与改前逐字节一致（`regions` 深比较相同）；④ 撤销一次可回退 schema 修改（schema 进撤销栈） |
| 复杂度 | **M** |

#### R-REG-02 · 生成陆地不再连带分区 —— 需求①的"默认不划分"

| 项 | 内容 |
|---|---|
| 需求描述 | 「生成陆地」只生成 `land`，`regions` 保持为空（不再自动切分）。原先的"在陆地内部重划区块"退化为该按钮上的**显式勾选项**（默认不勾） |
| 交互入口 | 工具栏「生成陆地」按钮 → 与其配套的 `Dropdown` 菜单里加一项「同时划出区块」（`Switch`/勾选），默认关 |
| 边界条件 | ① 已有区块时点「生成陆地」**仍**弹确认（现状文案保留："将重新划分区块（现有 N 块会被替换）"→ 若勾选关，文案改为"现有 N 块将被清除"）；② 勾选「同时划出区块」时行为与现状完全一致（含陆内切分、多岛加权分配）；③ 零区块时不得阻断任何既有功能（素材可放、地名可加，`level` 记 `null`，沿用现状） |
| 验收标准 | ① 新建文档 → 点「生成陆地」（不勾选）→ `doc.land !== null` 且 `doc.regions.length === 0`；② 此时渲染层不出现任何区块边界，且素材可正常放置与命中；③ 勾选后生成 → `doc.regions.length` 与改前同参同种子一致（回归等价） |
| 复杂度 | **S** |

> **裁决补充（实现期修订，2026-11-03）：手画区块一律保留，`splitRegions: false` 也不清空。**
>
> 原文案"若勾选关，文案改为「现有 N 块将被清除」"在实现时被推翻。理由：手画区块是最贵的用户成果，
> 一次「生成陆地」把它抹掉、只能靠 50 步撤销栈找回，与本 PRD §8-Q4「重新生成不得抹掉手画成果」的
> 裁决精神直接冲突。统一后的规则：
>
> | 路径 | `regions` 结果 |
> |---|---|
> | `generateLand(seed, { splitRegions: false })` | 只清自动生成的区块，`origin === "manual"` 原样保留 |
> | `generateLand(seed, { splitRegions: true })` | 手画区块 + 新生成的自动区块 |
> | 工具栏「生成区块」 | 同上，只替换 `origin === "generated"` |
>
> 弹窗文案按实际数量二分：有自动块被清 → 「将清除 N 个自动生成的区块」；有手画块保留 → 追加
> 「保留 M 个手动区块」。**且只要 `manualCount > 0`，无论勾不勾 `splitRegions` 都要追加一句**
> 「手动区块是基于当前陆地绘制的，重新生成陆地后可能不在新大陆范围内」——手画块被强行保留了，
> 用户必须知道它的坐标会与新陆地失配。

#### R-REG-03 · 手动划分区域（画多边形）—— 需求①的"手动划分"

| 项 | 内容 |
|---|---|
| 需求描述 | 工具栏加"画区"模式：在画布上逐点连线画出闭合多边形，落成一个 `MapRegion`。落笔前需指定该区块的**层级**；若当前已选中某区块，则新画的区块成为它的**子区块**（`level = 父.level + 1`、`parentId = 父.id`） |
| 交互入口 | 工具栏模式切换：`选择` / `画区`；画区态下工具栏右侧出现「层级：L{n} 名称」只读指示 + 「撤销上一点」「完成」「取消」（见 §4.2） |
| 边界条件 | ① **自交禁止**：多边形自交 → 拒绝并提示（`Tooltip`/`message`），草稿保留供继续改；② **重叠禁止**：与同父兄弟或祖先链上任一区块相交 → 拒绝并提示"与「{name}」重叠"，草稿保留；③ **父子包含**：在父区块内画子区块时，新多边形必须完全落在 `parent.polygon` 内，否则拒绝；④ 层级封顶：`level` 不得超过 `regionSchema.length - 1`，超限提示"已达最深层级（共 N 级）"；⑤ 顶点数 < 3 → 不落库（`message` 提示后清空草稿）；⑥ 总数达 `REGION_TOTAL_LIMIT = 600` → 禁止继续画；⑦ 允许"未画满"（区块之间留缝），留缝区域就是没有区块，视觉上等同空白（**不报错**，见 §6-D）；⑧ Esc 取消整笔草稿，不产生撤销快照 |
| 验收标准 | ① 画一个 5 顶点多边形并完成 → `doc.regions` 新增 1 条，`origin === "manual"`，`polygon.length === 5`，`level` 等于落笔前选定的层级；② 选中已有区块后画子区块 → 新记录 `parentId === 父.id` 且 `level === 父.level + 1`；③ 画一个跨出父区块边界的多边形 → 不新增记录且出现提示；④ 撤销一次 → 新画的区块整条消失（一次快照），再重做一次恢复且 `id` 与 `polygon` 不变；⑤ 生成区块后再点「生成区块」不会删除 `origin === "manual"` 的区块（见 §8-Q4） |
| 复杂度 | **L** |

#### R-REG-04 · 合并子区域（含子图提示）—— 需求③

| 项 | 内容 |
|---|---|
| 需求描述 | 选中一个**非叶子**区块 P，把 P 的**整棵后代子树**从 `regions` 中删除，P 成为叶子。P 自身所有字段不变 |
| 交互入口 | `RegionPanel` 新增按钮「合并子区域」；叶子节点该按钮 `disabled` + `Tooltip`"该区块没有子区域"（见 §4.3） |
| 边界条件 | ① 确认弹窗必列：将被删除的子区块总数、其中**带子图的数量**（`submap != null`）、最多 3 个区块名 + "等 N 个"；② 父区块 P 自身已有 `submap` → 提示"该区块已关联子地图，合并后子地图保留"（因为 P 不被删除）；③ 只删除后代，**不动** P 的 `parentId`/祖先链；④ 素材/地名**不迁移**，其 `level` 保持原值（若整层被合并光，渲染侧按既有 `resolveElementLevel` clamp 到现存最深一级，见 §7-R3）；⑤ 一次合并 = **一次撤销快照**；⑥ 悬空 `parentId`（指向不存在区块）按顶层处理，不得抛错 |
| 验收标准 | ① 选中 `children(P).length = n > 0` 的 P → 确认合并 → `doc.regions.length` 减少量**精确等于** `subtree(P).length`，且 `regions.filter(r => r.parentId === P.id).length === 0`；② `P.polygon` **逐点深比较完全相等**（顶点数不变、坐标不变），`P.level / parentId / name / color / seed / submap` 全部不变；③ 被删子树含 `m ≥ 1` 个 `submap != null` 的区块时，弹窗文案包含 `m`；点「取消」后 `doc.regions` 深比较不变且 `undoStack.length` 不变；④ 撤销一次 → 整棵子树回来（`id` 全等），`undoStack.length` 减少 1；⑤ 对叶子区块：按钮 `disabled`，点击不产生快照；⑥ 悬空 `parentId` 的脏数据不影响合并（用构造数据跑用例） |
| 复杂度 | **M** |

#### R-REG-05 · 高亮分级（叶子面高亮 / 非叶子容器态）—— 需求④

| 项 | 内容 |
|---|---|
| 需求描述 | 面高亮（现状三笔）**只对叶子区块**生效；非叶子区块被选中时改为**容器态**：沿 `P.polygon` 画 1.6px 强调描边，不铺填充、不加外发光；`RegionPanel` 顶部补层级面包屑（`大陆 1 / 洲 3 / 国家 12`） |
| 交互入口 | 无新入口——沿用现行"点区块即选中"。`Esc` 清选中不变 |

| 复杂度 | **S** |

## 5. 数据模型增量

> 只给字段级增量，不写实现代码。全部新字段**可选**，老文档零迁移（沿用 `migrateDoc` 的
> "未知字段原样保留"策略）。

### 5.1 `MapDocument` 新增

| 字段 | 类型 | 必有 | 语义与理由 |
|---|---|---|---|
| `regionSchema` | `RegionLevelDef[]` | 否 | 层级定义（长度 = 层数，1~4）。**为什么必须放文档而不是常量**：① 需求 2 要求用户可改且要持久化；② 手动划分模式下 `regions` 可能为空数组，此时没有任何地方能推导出"层数/层级名"（现状 `levelCountsOf(regions)` 对空数组返回 `[]`）——零区块状态下层级定义**必须有独立宿主**；③ 子图内嵌自己的 `regions`，也内嵌自己的 schema |
| （缺省读法） | — | — | 缺失时读作 `REGION_LEVELS` 的默认 4 级；`migrateDoc` 需补兜底：数组、长度 1~4、`name` 非空字符串、`count` 为正整数，任一项不合法则整段回落默认值 |

```ts
/** 一级区域的定义（顺序即层级序号，0 起） */
interface RegionLevelDef {
  name: string;   // 展示名，进 region.name 前缀与工具栏/面板文案
  count: number;  // 目标数量：生成时用；手动模式下作为"建议上限"仅供参考
}
```

### 5.2 `MapRegion` 新增

| 字段 | 类型 | 语义与理由 |
|---|---|---|
| `origin?` | `"generated" \| "manual"` | 来源标记。缺失读作 `"generated"`（老数据全是生成的）。**为什么需要**：① 重新生成区块时"手画成果要不要保留"必须有判据（§8-Q4）；② 后续"微调"只对手画区块开放时也要靠它分流 |
| （不新增） | — | 明确**不**新增 `locked` / `vertices` / `smooth` 等字段：P0 没有"顶点编辑"，先不占位；`polygon` 仍就是 `Point[]`，语义不变（世界坐标、含崎岖化、首尾不重复） |

### 5.3 `MapSubmap` 新增

| 字段 | 类型 | 语义与理由 |
|---|---|---|
| `regionSchema?` | `RegionLevelDef[]` | 子图有自己的区域树（`MapSubmap.regions`），因此也应有自己的层级定义；缺省继承父文档 schema（读时回落，不写值，避免复制漂移） |

### 5.4 明确**不改**的东西（重要，避免下游误解）

| 项 | 决定 | 理由 |
|---|---|---|
| 层级数量的**事实源** | **仍是** `levelCountsOf(regions)`（渲染侧 `levelAlphas.length`），本轮**不**改成读 `regionSchema` | 改它会推翻既有断言"零区块 ⇒ 素材层级无关"（`lod.ts` 有测试），并影响子图递归渲染的 LOD 计算；收益（合并掉整层后元素不被 clamp）不抵风险。代价写在 §7-R3 |
| `level` 语义 | 不变：0 起，`regionSchema.length - 1` 为最深 | 只是"最深"这个名字从常量变成文档字段 |
| `REGION_TOTAL_LIMIT = 600` | 不变，作为手画数量的硬护栏 | 渲染与内存护栏，需求未要求放宽 |
| `polygon` 结构 | 不变 | 合并/手画都不引入新几何格式 |

## 6. 与既有能力的冲突与取舍

### 6.A 需求④（只有最底层级才高亮）与需求③（要选中高级区域去合并）的冲突

**选定方案：把「选中」和「高亮」拆成两层，判据用「叶子」而非「最深层级」。**

- **选中（逻辑态）**：任何区块都可被选中。`selectedRegionId` 语义不变，`RegionPanel` 对任何层级浮出。
  合并、聚焦、圈定子图都依赖它。
- **高亮（视觉态）**：分两级。
  - 叶子（`children(P).length === 0`）→ **面高亮**，现状三笔**逐参数不变**；
  - 非叶子 → **容器态**（沿 `P.polygon` 描边 + 面板面包屑），**不铺面**。
- 需求④的落地表述：**"面高亮只对最小可操作单位（叶子区块）生效，高级区域用容器态表达范围"**。

**理由（三条，按强度排序）**

1. **字面执行会否掉本轮一半需求。** 若"只有最底层级可被选中"，那么：合并（对象必是高级区域）不可做；
   `RegionPanel` 的「聚焦此区域 / 圈定生成子图 / 绑定子图」也全部失效——这三项恰恰都作用在**含子区块的高级区域**上
   （圈定子图在郡这一级虽也有，但用户真实场景"小溪村→县城"是在洲/国家上圈）。一句话：需求 4 的字面读法
   与既有子图能力直接互斥，而需求 3 只是它撞到的第一个。
2. **用户抱怨的是"糊住"，不是"能选中"。** 现状三笔是"淡填充 + 外发光 + 白内描边"，在郡这一级铺在几平方厘米上
   是"发亮"；在洲这一级铺满整屏就是"糊成一片"，把内部所有子区块的边界线压掉了。这正是需求 4 的真实痛点——
   **视觉强度不该与面积成正比**。容器态解决视觉，逻辑态保留操作，两边都不牺牲。
3. **判据只能是叶子，不能是 level——这一点由需求 3 自己证明。** 合并会把"国家"的所有郡删掉，于是"国家"成为
   **叶子但 `level = 2`**（比最深级 3 更浅）。若用 `level === maxLevel` 判断高亮，这个刚合并出来的区块
   会**既不能高亮、也无法在视觉上确认选中**——用户做完合并立刻失去操作反馈。所以"最小可操作单位"的正确
   定义是**结构上的叶子**（有没有子节点），而不是**序号上的最深**。

**被放弃的方案与代价**

| 备选 | 代价 |
|---|---|
| A1 字面执行：只有最深层级可选中 | 需求③合并无法做；「聚焦/圈定子图/绑定子图」在高级区域上全部失效。等价于用一句观感抱怨换掉三项既有能力 |
| A2 按 `level === maxLevel` 判定高亮（而非叶子） | 合并产出 `level = 2` 的叶子后无法高亮无法确认选中；且树会变成"异构的"（有的国家有郡、有的没有），任何按 level 的一刀切都会错 |
| A3 保持现状（任意层级都铺面高亮） | 需求④不解决；大区域选中时内部边界被压掉，用户看不出自己在操作哪一块，反而更容易误操作 |

### 6.B 需求①「默认不划分」与需求②「定义层级」的关系

**选定方案：同一套能力的「配置 → 两种落地」两段，`regionSchema` 是共同前置；"默认不划分"落在"生成陆地不再连带分区"这一个动作上。**

```
        ┌──────────────┐
        │ regionSchema │   ← 需求②：层数 / 名称 / 数量（进文档、进撤销栈）
        └──────┬───────┘
        ┌──────┴───────┐
        ▼              ▼
   路径 A 一键生成   路径 B 手动划分
 (generateHierarchy)  (画多边形 + 指定层级)
        │              │
        └──────┬───────┘
               ▼
        regions: MapRegion[]
```

- **为什么不是两套独立入口**：手动画出来的多边形必须记 `level`，而 `level` 的**含义（叫什么名字）与上限（最多几级）**
  只能来自 schema。若手动模式不先有 schema，画出来的区块只能记 `level = 0`，随后无法表达父子、无法参与
  层级淡入、无法被合并——手动划分会退化成"一堆没有结构的色块"。
- **"默认不划分"到底是什么状态**：`doc.regions === []`。这个状态**数据层与渲染层早已支持**
  （`createEmptyDocument()` 初始就是空数组；`MapCanvas` 缺省不画；`lod.ts` 在 `levelCount = 0` 时把素材判为
  "层级无关"，有测试）。所以需求①的病根**不在生成算法**，在入口：点「生成陆地」时区块被**连带**切了出来
  （`index.tsx` 里那句确认弹窗"将重新划分区块（现有 N 块会被替换）"就是这个耦合的证词）。
  本轮把耦合切断（R-REG-02），"默认不划分"即成立。
- **两条路径的共存规则**：schema 改动不动已生成的区块；点「生成区块」只替换 `origin === "generated"` 的区块
  （手画区块保留，§8-Q4）；手画与生成可以混用（先手画两洲，再对某洲一键细分）。

**被放弃的方案与代价**

| 备选 | 代价 |
|---|---|
| B1 两套独立入口：手动划分不依赖 schema，层级写死 | 手画区块无法表达层级/父子，合并与层级淡入全部失效；后续想接 schema 要重做整条交互 |
| B2 「默认不划分」= 干脆删掉一键生成，只留手画 | 丢掉了"223 块 3 秒出图"的生产力；绝大多数用户不会手画 223 块。且 `generateHierarchy` 是既有资产，删掉是净损失 |
| B3 schema 只存在组件 `useState`（现状层数的做法） | 关窗即丢；且零区块时（路径 B 起点）无处推导层级名，工具栏胶囊会显示不出来 |

### 6.C 需求③「合并」在树结构上的语义（必须写死）

**选定语义（逐条，均可测）**

| # | 条款 | 理由 |
|---|---|---|
| 1 | 合并对象 P 必须是**非叶子**（`children(P).length ≥ 1`）；叶子调用被禁用 | 无事可做，且避免"合并了但什么都没变"的空快照 |
| 2 | 删除范围 = **P 的整棵后代子树**（递归所有后代），不只是直接子节点 | 若只删一层，孙节点会变成 `parentId` 悬空的孤儿。用户说的"子区域"在日常语义里包含"孙子" |
| 3 | P 自身字段**全部不变**：`polygon / level / parentId / name / color / seed / submap / submapEnterScale` | 见第 4 条 |
| 4 | **`polygon` 不重贴合**（顶点数与坐标逐点不变） | ① P 的 `polygon` 本来就是闭合完整多边形（生成时父边界与子边界是"同一套曲线的切片"，父块从不缺边）；② 子区块并集边界是**锯齿状**（子边已 wobble 化），重贴合要么造出新折线要么上 polygon union + 简化；③ 顶点数不变意味着渲染缓存 key 不变、几何零重建，合并是 O(n) 数组操作，对 600 块也瞬间完成。**可验收**："合并后 `P.polygon` 深比较相等" |
| 5 | 合并后 P 的 `level` **不提升**（仍是 2，不变成 3） | `level` 是"这块在设定里属于第几级"，是语义不是深度。国家合并了内部郡，它依然是"国家"这一级。这也正是 §6-A 用叶子而非 level 判高的原因 |
| 6 | **子图**：被删子树中若有 `submap != null` 的区块，其子图内容随区块删除；**合并前必须在弹窗里报数量与名字**。不提供"接管/迁移"选项 | 用户明确要求提示。接管在本轮是陷阱：P 若已有 `submap` 则语义冲突（一张图里装两张？）；P 若没有，接管哪一张？多个都带子图时更不能选。留 P2（R-REG-11）+ §8-Q3 让用户拍板 |
| 7 | **素材/地名/道路不迁移**，`level` 保持原值 | 迁移要定义"元素坐标从被删区块换到 P"的落点规则（质心？最近点？），且元素是"面上的点"，坐标本身不依赖区块存在。保持原值最安全；整层被合并光时的 clamp 行为见 §7-R3 |
| 8 | 一次合并 = **一次撤销快照**（`undoStack +1`，受 `HISTORY_LIMIT = 50` 限制） | 与既有"生成区块 / 清除区块"一致，用户心理模型统一："一步一动作" |
| 9 | 悬空 `parentId` 视为顶层，合并过程不得抛错 | 防御老数据与异常文档 |

**不可逆性**：合并本身**不可逆**（没有反向的"拆分"能力，P2 也不打算做——拆分需要重新生成子树，
等于把合并前的手画成果重做一遍）。唯一恢复路径是**撤销栈**（50 步）。因此弹窗文案必须写明
"此操作可撤销（Ctrl+Z 一步恢复）"，且**带子图时必须显示 ⚠ 段**——那是最贵的一类误操作。

**被放弃的方案与代价**

| 备选 | 代价 |
|---|---|
| C1 合并 = 只删直接子区块，孙节点上提到 P | 层级会塌陷（原本的孙变成 P 的子，`level` 与 `parentId` 全部要重映射），且"合并"语义变成"塌一层"，用户预期不符 |
| C2 合并 + 重贴合 `polygon` 到子树并集边界 | 需要 polygon union + 顶点简化；顶点数变化会打破"渲染几何零重建"，也打破"顶点数不变"这条最干净的可验收判据；P2 再评估（R-REG-12） |
| C3 合并 = 删区块但把带子图者的 `submap` 搬到 P | P 已带子图时无解；多个子图时无法选择；迁移后 `submapEnterScale` 等参数也要重算。本轮只提示不接管（R-REG-11） |
| C4 合并 = 软删除（标记 `mergedInto`，渲染时跳过） | 数据会持续膨胀，且所有遍历（`levelCountsOf`、`hitTest`、合并自身）都要加过滤，一处漏了就现"幽灵区块"。硬删 + 撤销更简单可靠 |

### 6.D 附带取舍：手画多边形之间允许"留缝"、禁止"重叠"

| 项 | 决定 | 理由 |
|---|---|---|
| 重叠 | **禁止**（落笔时拒绝并提示） | 重叠会让填充 α 叠加变深（同一条边界被画两次）、`hitTest` 只能取最上层、`levelCountsOf` 与统计口径都开始撒谎。Voronoi 的"严丝合缝"是有价值的既有性质，不值得为了少点一次鼠标放弃 |
| 留缝（未覆盖区域） | **允许** | 未覆盖区域的本义就是"这里没有区块"，渲染上等同空白，无副作用。强求画满会逼用户为了"填满"去画无意义的区块 |
| 自交 | **禁止** | 自交多边形在 `Graphics` 填充下用的是 even-odd/nonzero 语义，视觉会出现空洞，与"地块"直觉冲突 |

## 7. 风险与不做的事

### 7.1 风险

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| R1 | 手画多边形与既有 wobble 曲线不兼容：生成的边界是崎岖的，手画是直的，同一张图上两种质感并存 | 观感割裂 | P0 接受（手画区就是"人画的界"）；P1 微调功能里给"自动崎岖化"选项复用 `REGION_WOBBLE` 同一套噪声 |
| R2 | 合并丢子图是**不可恢复**的（除撤销） | 用户几十个素材可能瞬间消失；撤销栈只有 50 步 | 弹窗强制 ⚠ 段 + 数量 + 名字；文案写明可撤销；后续可加"合并前自动存一份快照"（列 P1 待评估） |
| R3 | 合并掉整层后，该层元素 `level` 无对应区块，按既有 `resolveElementLevel` 被 clamp 到现存最深一级 | 元素尺寸/显隐可能"跳"一级（`elementSizeFactor` 依赖 `levelCount`） | 本轮接受并写进文档：`levelCount` 事实源不改（§5.4），clamp 是既有行为不是新 bug；若实测扰民，再用"schema 作 levelCount 源"重构（代价：推翻"零区块 ⇒ 层级无关"断言） |
| R4 | `regionSchema` 改动与已生成区块的 `name` 前缀脱钩（改了名，老区块还叫"郡 31"） | 用户以为改名没生效 | 面板上明示"只影响下次生成"；P1 加"按新层级名批量刷新区块 name"的显式动作 |
| R5 | 手画无数量上限约束，用户可能画出 `REGION_TOTAL_LIMIT` 级数量的碎块 | 渲染掉帧 | 600 硬上限拦截（已有常量）+ 画区模式工具栏显示"已用 N/600" |
| R6 | 本次改动全部在渲染层（`MapEditorPage`）与文档模型；若需要把 `regionSchema` 写进 `novel_maps.doc_json` 的主进程迁移逻辑 | 触及主进程 | **主进程改动需重启 dev**（项目铁律）；纯渲染层改动走 HMR 即可 |
| R7 | `regionSchema` 进撤销栈后，每次改一个数字都产生快照，50 步很容易被"调参数"吃光 | 撤销栈污染 | schema 输入做**合并提交**（同一面板连续编辑合并为一次快照，复用 Store 里已有的 snapshot 合并能力思路） |

### 7.2 本轮明确不做

| 不做 | 为什么 |
|---|---|
| 顶点/边界微调（拖顶点、插顶点、边平移） | 需求①原文是"手动划分**或者**微调"，P0 交手动划分已闭环；且父块顶一动，所有子块的 `host` 边必须同步，是独立课题（R-REG-06） |
| 单个区块删除 | 撤销与「清除区块」可覆盖；显式删除需先定义"删父留子"的孤儿规则（R-REG-07） |
| 区块重命名/改色 | 不属本轮四点（R-REG-08）；`MapRegion.name` 注释里的"阶段三"指的就是它 |
| 重叠自动裁剪 | P0 用"拒绝 + 提示"保证数据不脏，L 级成本（R-REG-09） |
| 合并时接管子图 | 语义有歧义（§6-C / §8-Q3） |
| 合并后边界重贴合 | 会打破"顶点数不变"这条可测判据（R-REG-12） |
| 层级数 > 4、任意深度 | 牵动 `levelAlphas`、素材 `level`、子图递归深度（R-REG-14） |
| 子图内部的区域编辑 | 需先补齐子图编辑主视角（R-REG-10） |
| 手画多边形的 AI 辅助/自动补全 | 无需求来源 |

## 8. 待确认问题（需用户拍板，每条附推荐选项）

**Q1 · 「生成陆地」是否彻底不再连带分区？**
推荐：**不再自动分区**，但在「生成陆地」的下拉菜单里保留「同时划出区块」勾选项（**默认不勾**）；
且**不勾选时手画区块仍然保留，只清空自动生成的区块**（2026-11-03 实现期裁决，详见 R-REG-02 的裁决补充）。
理由：默认为空才叫"默认不划分"；保留勾选让"一键出图"的老用户不多点两步。老习惯靠勾选恢复，新默认靠空图成立。

**Q2 · 「最底层级」的判据用"叶子"还是"序号最深层级"？**
推荐：**叶子**（有没有子节点）。这是本文 §6-A 的核心裁决，也是需求④能否与合并共存的关键。
请确认："合并后的国家（`level = 2`，但已无子区块）被选中时，应该出现面高亮"——预期答案是"应该"。

**Q3 · 合并时，被删子区块上的子地图怎么处理？**
推荐：**本轮只提示不接管**（弹窗报数量 + 名字，确认后随区块删除，可撤销）。选项：
① 只提示（推荐，成本最低、语义无歧义）；
② 提供"把唯一一张子图移到父区块"的勾选（父区块必须没有子图，P2）；
③ 自动全部丢掉且**不**提示（不推荐，违背用户明确要求）。

**Q4 · 手画区块遇到「生成区块」时保留还是清空？**
推荐：**保留手画区块，只替换自动生成的**（`origin === "manual"` 的区块在重新生成时原样留下），
并在确认弹窗里写明"将保留 N 个手动区块"。选项：
① 保留（推荐，否则用户手画成果会被一次误点清空）；
② 全部替换（简单，但手画价值被一键抹掉）；
③ 完全禁止在有手画区块时重新生成（过于强硬）。

**Q5 · 层级配置（`regionSchema`）何时生效？**
推荐：**即时存入文档、只影响下一次生成**，不自动重排已生成区块；改坏了靠撤销退回。
选项：① 即时保存 + 只影响下次生成（推荐）；② 点【应用并生成区块】才保存（改一半关窗就丢）；
③ 改完立即重排整棵树（会把手画/合并成果全部冲掉，不推荐）。
