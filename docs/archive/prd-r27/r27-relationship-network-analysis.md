## 一、一句话目标与目标拆解

**一句话**：把本书已建好的要素与关联，一次性渲染成可拖拽、可筛选的力导向关系图，让作者不离开编辑器、不丢一个字，扫一眼看清"谁和谁有关系、哪些势力与地点被卷进来"（产 §1.1）——它是 R24 关联数据的**只读消费端**，不产生新数据。

### 1.1 四条痛点 → 可判定的成功标志

| # | 痛点（产 §1.2） | 成功标志（可判定，均引验收条目） |
|---|---|---|
| 1 | 群像两两关系，列表读不出结构 | 打开即出图，**无需再点任何按钮**（P0-1）；模板夹具 C3 = **11 节点 / 8 边**（不是 9/8、不是 12/9）；200/500 规模 `firstPaintMs < 100`（RG-P-01） |
| 2 | 关联列表只能看一人邻居 | 节点数 = 本书**全部**要素数，不因"有没有关联"增减（C1 / RG-D-01）；两书夹具下不出现他书边（C2 / RG-D-08） |
| 3 | 卡壳要 3 秒调出设定 | 单击节点出小卡（名称/类型/一句话/境界副标题/关联数 5 项，RG-I-34）；小卡「打开资料卡」**先关浮层再 `openEntityDetail`**（RG-I-35 断言调用序列） |
| 4 | 设定库生长但从不检视 → 大量孤立卡 | 模板 2 个孤立节点虚线可见 + 提示条「另有 2 个要素暂无关联」（C8 / RG-I-41）；新建零关联角色**立刻**成虚线节点（C9 / RG-D-03） |

### 1.2 不解决什么（三条边界，防下游扩范围）

| # | 不做 | 依据 |
|---|---|---|
| 1 | 不产生、不编辑数据：不帮"想出"关系、不校验关系合理性、不做图上改要素/建关联 | 产 §1.2 末注、N-3、N-4 |
| 2 | 不做跨作品关系网、不按势力折叠/聚合 | 产 N-2（`novel_links` 无 `work_id`）、N-5（PRD 定位 P2 兜底） |
| 3 | 不做时间线/按章快照，不做 3D 与力导向以外的布局族 | 产 N-6、N-7 |

### 2.4 三条最容易漏做的（单列）

| 项 | 要点 | 漏了会怎样 |
|---|---|---|
| **P0-8 孤立要素可见** | 节点 = 全部要素，`degree=0` 也参与布局、虚线描边（**不用警示色**）、提示条 N = `isolatedIds`（模板 2）；夹具锁 11/8/1/2 | 新建角色"消失"→ 用户认为数据丢了（附录 A 的原始错误）；`RG-D-02` 是专门抓这个的**反向守卫**（P0） |
| **P0-9 双入口单一 opener** | 两入口都调 `openRelGraph({entry})`，`entry` ∈ `entity-panel`/`tool-launcher`/`entity-detail`；ToolLauncher 卡删 `plannedHint`、`state`→「已上线」、`is-planned` **2→1**、`:49-65` 断言对象换「架空地图」、新增"调 opener 不调 onNotify" | 占位卡永久显示"规划中"（最伤信任的一类不一致）；既有测试 4 处同时红；`entry` 写死成常量则"砍哪个入口"永久无据（RG-I-50b 专抓） |
| **两个诊断数字分开** | 提示条 N = `isolatedIds`（2）；「已忽略 N 条关联」= `droppedLevel + droppedSelfLoop + droppedUnknown`（1）。**不含 `duplicate`**（归组天然去重，属合并）、**不含 `droppedByOtherWork`**（随"库里几本书"漂移）、**不含 `isolatedIds`**（孤立照画） | 混算得 3 → 用户开始怀疑统计，而这行文字的唯一价值就是"让丢弃可追溯"；`RG-D-01` 断言 `Object.keys(diagnostics)` 恰为五键，多一个 `duplicate` 就红 |

### 2.5 规模降级（单列，最易做糊）

**D1~D4 判据**（产 §五 I-12）

| 档 | 判据 | 呈现 |
|---|---|---|
| D1 完全空态 | 要素 **< 3** | 居中空态卡 + 「去要素库建卡」；**不渲染画布**（避免"加载失败"错觉） |
| D2 提示态 | 要素 ≥ 3 且**可成图边 < 2** | **仍渲染节点**（散点 + 虚线）+ 提示条；可成图边已排除 level/自环/重复 |
| D3 降级态 | 节点数 **> 1200** | 五步按序、不跳级（下表） |
| D4 正常 | ≥ 3 要素 且 ≥ 2 边 | 正常渲染 |

**五步（不跳级，产 D3 / A-4 / 附录 C）**

| 步 | 动作 | 前置 |
|---|---|---|
| ① | 降信息密度：≤120 正常 → 121–200 隐角标 → 201–400 边标签仅悬停 → **401+ 只画色点不画字** | 恒执行（`<1200` **只走这一步**） |
| ② | 折叠孤立要素为一行「另有 N 个要素暂无关联 [展开]」 | 恒执行 |
| ③ | 默认把类型筛选收窄到「角色」，`Segmented` **高亮**当前档 | **守卫**：`roleCount ≥ 200` **且** 占比 ≥ 30%；任一不满足 → **整步跳过直接进 ④** |
| ④ | 提示「**当前显示 X / 共 Y 个要素**」，把决定权交回用户 | 恒执行 |
| ⑤ | `degree` Top 500 + 孤立全保留（上限 200）+ 提示条「仅显示关联最多的 500 个要素 **[显示全部]**」 | **三条同时成立**：`> 1200`、**③ 已执行**、**收窄后仍 > 800**；③ 被跳过 → ⑤ 一律不启用 |

- **③ 的守卫为什么必须双条件**：1200 要素只有 80 角色的书，收窄 = 默认藏 90%（比度数裁剪更糟，度数裁剪至少还剩 500 且有提示条）；`roleCount ≥ 200` 在当前阈值下恒真，但**两条都要写**，为将来下调阈值留护栏（附录 C「不可达说明」）。
- **⑤ 的 N**：`N = 总节点数 − 实际渲染节点数`，**被 200 上限挤掉的孤立节点也要算进 N**；「显示全部」卡顿只给性能警告，**不得置灰**（置灰 = 把可逆变不可逆，条件当场失效）。
- **A-14 可逆可见契约（四步共同约束）**：① 任何密度档 hover 仍出全名；② `[展开]` ↔ `[收起]` **双向**；③ 收窄必须 `Segmented` 高亮 + 「显示全部类型」出口，不得做成隐藏状态；④ 提示条必须给两个确定数字，不接受"部分要素未显示"；⑤ 点「显示全部」后**本次会话不再自动裁剪**。
- **阈值数值仍归架构师**（产 Q-13）：200/500/800/1200 是需求基准，改数需三方同步（1199/1201 两条验收会随之重写）。

## 三、关键约束清单（约束 → 违反后果）

### 3.1 数据与派生

| # | 约束 | 违反后果 |
|---|---|---|
| 1 | 节点 = 本书**全部**要素，`degree=0` 也成节点（产 §4.1） | 新建角色消失 / `RG-D-02` 红 / C9 失败 |
| 2 | 边 = **两端 id 都落在本书要素集内**（`links` 全库未过滤，`novel_links` 无 `work_id`，产 C-1/§4.2） | 跨作品/悬空边混入 → RG-D-08/09 红线 1，"陆行舟连到另一本书"且事后无法用 SQL 修 |
| 3 | `to_type='level'` **不画边**，降级为节点副标题（复用 `formatBoundRealmName`） | 出现无名假节点；夹具变 12/9，C3 红 |
| 4 | 自环/悬空/跨作品/非法端点类型丢弃并**分类计数**；完全重复行归组去重、**不计丢弃** | `degree` 失真；"已忽略"虚报 |
| 5 | 派生为**纯函数 + 确定性**（`localeCompare(a,b,"zh-Hans")`、类型序 → id、不依赖插入顺序） | 快照随机器/ICU 抖；同一份数据在两台机器上标签不同 |
| 6 | 坐标与 viewport **不参与派生**；孤立节点**不得**在派生层被过滤 | 记忆命中时派生重跑；孤立被"顺手优化"掉 |

## 五、对分批的输入结论（十条）

1. **派生层（T01）+ 布局内核（T02）是唯一可完全独立验收的批次**：纯函数、零 React、零 DOM、零 mock，对应 RG-D 22 例 + RG-L 8 例；两者互不依赖，可并行，也是全部后续批次的前置。
2. **入口改造与开关必须同批**：`ToolLauncher` 4 处断言（`:41`/`:46`/`:49-65`/`:74-80`）在改卡的同一次提交内必红，`is-planned` 2→1、`:49-65` 换「架空地图」是硬绑定；拆开做 = 合入即 CI 红（研风险 11）。
3. **坐标持久化按产 P0-3 与 P0 同批**（冲突 1）：它同时决定 RG-S 全 14 例、D5/D14、F1/F2/F5，以及红线 4。留到 P1 = P0 上线即"拖了记不住"。
4. **导出与边备注各需一条新 IPC，互不依赖，可并行**（研 T07 ∥ T08）；但两者都属产 P1（冲突 2、7），不要跟 T09 一起压到 P2。
5. **降级必须拆两层排期**（冲突 4）：`planDegrade` 守卫判定 + ④ 文案随派生层进 P0（可断言 `40d`/`40g`）；②③ 执行体进 P1、⑤ 进 P2。这样"默认藏掉主体"在 P0 就被拦住，P0 又不必背 1200 档造数。
6. **埋点与开关同批（P0）**（冲突 3，A-10）：同一次打开路径，成本一行 `logUsageEvent`；错过即永久缺 `entry` 分布。
7. **T09（⑤ 兜底）是 P1 的尾巴、不在关键路径**（研 §10.2：关键路径 T01/T02 → T03 → T04 → T07 ≈ 11.3 人日）；但它依赖 ③ 已在 P1 交付，不能与 ③ 同批压缩。
8. **跨批次不变量（每批都要守，不进任何单一批次验收）**：30 张表基线逐字不变、`novel_links` 不加 `work_id`、`relGraphOpen` 不进 `pageOverlayOpen`、布局循环零 `setState`、派生层不进 `shared`、`useNovelViewState`/`useNovelPage` 不 import 三个 service、`entry` 三值不得写死。
9. **每批必带的回归面**：`ToolLauncher/index.test.tsx`、`themes.test.ts`（`ELEVATED_ALLOWED` 首次引入 scss 的那批必改）、`useNovelViewState.test.ts`（追加 4 例：不进 pageOverlayOpen / dismiss 关图 / 记 entry / 切作品关图）、`novel-write-guard.test.ts`（`novel-work-delete` 级联追加 config 清理，**必须排在 modifiers 之后**）。
10. **唯一留给架构师的数值开口是降级档阈值**（产 Q-13）；1200 / 800 / 200 / 30% / Top500 / 孤立上限 200 已冻结，实现期不得自行分级（研 §5.4「单一触发，不许自行分级」）。
