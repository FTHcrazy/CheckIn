# 行囊 · 新用户渐进式上手方案（产品优化文档）

> 版本：v1.0 ｜ 日期：2026-10-12 ｜ 状态：待评审
> 关联：`docs/character-pack-prd.md` v1.5、`docs/character-pack-progress.md`
> 代码基线：模块清单 `src/shared/components/CharacterPack/types.ts`（10 模块）、布局走 `ModuleManager`（按角色存草稿）、界面偏好走 config `novel_pack_ui`、模板行囊走 `electron/novel-template.ts` `buildTemplatePack()`

---

## 1. 现状问题分析

### 1.1 一次打开，看到的是整个系统

行囊目前共 **10 个模块**，新用户（新建书籍后第一次打开行囊）会一次性看到全部模块的完整形态：

| 区域 | 首次可见内容 | 需要理解的概念 |
|---|---|---|
| 数值与状态 | 总属性汇总、人物属性（基础属性 + 战斗属性共 6 条预填）、属性映射 | 属性、加成、换算 |
| 装备与物品 | 装备栏（12 个部位的空槽）、物品栏 | 部位、槽位、容量、稀有度 |
| 能力 | 技能栏、境界 | 效果三档性质、熟练度、R25 联动 |
| 系统 | 货币、状态效果、备注 | 进制、量纲、Buff/Debuff |

再加上 3 个管理器入口（部位管理 / 量纲管理 / 模块管理），**首次使用要面对约 13 个功能块、20+ 个领域概念**。截图中的典型状态：用户只是想给主角记一下境界和功法，却先要划过大片空槽位（头饰 0/1、上衣 0/1、护腕 0/1……）和一整块预填的属性面板。

### 1.2 心智负担的三个具体来源

1. **空模块不是"空态"，是"待办感"**。装备栏 12 个部位全部显示"空"，用户不知道这些槽位是"必须填"还是"可以不管"，也不敢删——怕删了以后要用找不回来。
2. **概念前置，收益后置**。效果性质三档（被动/持续/释放）、两道计入闸门、属性映射的拓扑规则，都是为"精确记账"这个高级目标服务的；但用户在第一次打开时就被迫看见它们。
3. **默认配置替用户做了太多决定**。预填的 6 条基础属性、12 个部位、三套量纲，对"只想记境界和功法"的作者是噪声；对"想要全量记账"的作者又不够贴身——两头不讨好。

### 1.3 现有能力盘点（本次优化的地基）

好消息是：渐进式开放所需的底层能力**大部分已经存在**，本次主要是产品层重组，不是大动架构——

| 已有能力 | 落点 | 本次怎么用 |
|---|---|---|
| 模块启用/禁用/排序，按角色独立存储 | `ModuleManager` + `PackModuleState`（走草稿） | 分层默认值直接落在出厂布局 `DEFAULT_LAYOUTS` |
| 「恢复默认组合」 | `ModuleManager` | 升级为「恢复到所选开荒模板」 |
| 界面偏好即改即存 | config `novel_pack_ui` | 解锁进度、引导已读标记的存放处 |
| 模板行囊（一份填满的范例） | `buildTemplatePack()` / `seedTemplateBook()` | 扩展为多套开荒模板的内容来源 |
| 埋点 | `novel_usage_log` | 解锁时机的行为信号采集与效果验证 |

## 2. 优化目标与非目标

### 2.1 目标

1. **首次打开零压迫**：新用户默认只见 2 个高频模块（境界、技能/功法），可见功能块从 ~13 降到 ~3（含头部）。
2. **按需添加，而非被动承受**：其余模块一律由用户显式添加，且添加路径就近（在需要它的场景里出现，而不是藏在模块管理里）。
3. **渐进解锁有节奏**：随使用深度分三档逐步推荐开放，每次只推荐一个模块，绝不自动开启承载设定数据的模块。
4. **规则配置权交还用户**：默认属性组、默认部位方案、提示密度等都可自定义或清空。
5. **一键套用通用模板**：内置 4 套开荒模板，覆盖从「极简」到「数据流」的典型作者画像。

### 2.2 非目标（防止范围蔓延）

- **不做任何模块删减或合并**：10 个模块一个不少，只调"何时可见"。
- **不动汇总管线**：两道闸门、两趟计算、映射拓扑全部保持原样。
- **不做强制引导流**：不弹全屏 onboarding，不打断写作；所有引导都是非模态的一句话或一枚角标。
- **不迁移老用户布局**：已有角色已存布局（`PackModuleState` 走草稿）不受影响，新默认值只作用于新角色。
- **不做多角色**（REQ-036 维持 ➖）。

## 3. 模块分层与默认开放策略

### 3.1 三层划分

| 层 | 模块 | 定位 | 默认状态 |
|---|---|---|---|
| **L0 核心（默认开）** | 境界、技能栏（功法） | 任何题材的作者第一天都要用：境界联动 R25、功法记录 | ✅ 默认启用 |
| **L1 记账（常用）** | 物品栏、装备栏、状态效果、备注 | 开始"记东西"才需要 | ⬜ 默认关闭，就近添加 |
| **L2 规则（进阶）** | 人物属性、总属性汇总、属性映射、货币 | 想要"数值自洽"才需要，概念密度最高 | ⬜ 默认关闭，情境推荐 |

**总属性汇总特殊处理**：它不是配置负担（只读、无字段要填），而是收益面板。建议**不给它独立开关**，跟随规则自动出现/隐藏——只要有任何一个"加成来源模块"（属性/装备/技能指向属性的效果/状态/映射）处于启用状态且产生了计入项，汇总自动出现；一行计入项都没有时自动隐藏，不占版面。这样避免"用户开了装备栏却看不见汇总结果，以为没生效"的反向困惑。

### 3.2 一个必须先解决的依赖问题（关键决策点）

⚠️ **技能栏的效果编辑器要求"目标属性"从属性清单里选**——默认关闭属性模块后，用户在功法里加的第一条效果会没有属性可指。

两个方案：

- **方案 A（推荐）：效果暂记模式**。属性模块未启用时，效果编辑器的"目标属性"下拉给出「暂不指定属性（仅记录）」选项，效果以文本形式保留在功法条目上，不参与汇总；界面一句话提示"启用人物属性后，这条效果可以指定属性并计入总属性"。用户启用属性模块时，扫描所有「暂不指定」的效果，逐条引导补指（一次性非模态清单）。**优点**：默认层真正只有两个模块；**代价**：EffectEditor 增加一个空目标分支，启用属性时要做一次升级引导。
- **方案 B：属性模块以"隐藏底座"默认存在**。属性模块默认启用但不出现在面板上，仅作为效果的指向池。**缺点**：违背"所见即可编辑"，用户永远不知道属性在哪改；且 `ModuleManager` 里会出现一个状态说不清的模块。不推荐。

> 需求方确认点 ①：默认层是否接受方案 A 的「效果暂记」？

### 3.3 落地方式

- 出厂默认布局改两套：`DEFAULT_LAYOUTS_NEW`（L0 only）与 `DEFAULT_LAYOUTS_FULL`（现状全部），按「该角色是否已有布局记录」分流——**老角色零迁移**。
- 模块管理（`ModuleManager`）保留全部能力，入口文案改为「添加模块」，把"关闭"重新包装成"移出面板"（数据不删，降低用户移出时的心理门槛——这是纯文案差）。

## 4. 渐进式解锁与添加流程

### 4.1 原则：推荐，永不自动开启

行囊的一贯哲学是"工具不偷偷改设定"（过期不翻 `active`、超载不自动挂 Debuff）。解锁机制必须同源：**系统只做"提示 + 一键启用"，写数据的开关永远在用户手里**。

### 4.2 三档节奏与触发信号

| 档位 | 推荐内容 | 触发信号（满足任一，`novel_usage_log` 已可采集） | 呈现方式 |
|---|---|---|---|
| **第 1 步 · 记东西** | 物品栏、备注 | ① 正文选区右键「记入背包」（面板未启用物品栏时，改为"启用物品栏并记入"一步完成）；② 行囊打开 ≥ 3 次后仍无任何 L1 模块 | 就近转化：右键菜单直接一句话；否则在面板底部给一张非模态「＋ 添加模块」占位卡 |
| **第 2 步 · 装备与数值** | 装备栏 →（属性 → 汇总自动出现） | ① 技能效果出现 ≥ 2 条「暂不指定属性」；② 物品栏条目 ≥ 5 件；③ 累计保存 ≥ 5 次 | 占位卡轮换推荐 + 功法效果编辑器内的一句话引导 |
| **第 3 步 · 规则系统** | 属性映射、货币、状态效果、量纲 | ① 属性 ≥ 6 条；② 用户点开过部位管理或量纲管理；③ 保存 ≥ 15 次 | 仅出现在「规则设置中心」（见 §5.2）的推荐位，不打扰主面板 |

- 每个信号**只触发一次推荐**，用户忽略（点 ✕）后进 `novel_pack_ui` 的已读集合，同档位 7 天内不重复。
- 同屏最多出现 **1 个**推荐位；推荐文案必须说明"启用后你会得到什么"，而不是罗列功能名。
- **全空态兜底保留**：用户把所有模块移出后，面板仍显示"所有模块都移出了 + 恢复模板"（现有 REQ-021 行为，文案同步升级）。

### 4.3 添加流程（就近优先）

```
看到推荐位 / 占位卡「＋ 添加模块」
  → 点击 → 弹出轻量选择卡（每模块一行：图标 + 一句话 + 「启用」）
  → 启用 → 模块插入面板末尾（或推荐位置）+ toast「已添加，可在模块管理中调整顺序」
```

- 从「记入背包」「给效果指定属性」等场景进入的启用，**跳过选择卡直接启用对应模块**，然后继续完成用户原本想做的事（记入 / 补指属性）——添加永远不劫持用户的原任务。
- 移出模块：模块头部「⋯」菜单 →「移出面板」；若该模块已有数据，确认框写明"数据保留，重新添加即可找回"（`enabled: false` 不清数据，现架构天然支持）。

## 5. 用户配置权限范围（把规则的决定权交出去）

### 5.1 各模块的开放粒度

| 规则项 | 现状 | 本次开放到 |
|---|---|---|
| 默认属性组 | 预填 6 条（气血/灵力/神识/根骨/悟性/剑意） | 新建行囊时三选一：**空白 / 精简 4 条 / 保留现状 6 条**；已有的属性可整组清空（带确认） |
| 部位清单 | 固定播种 12 个部位 | 部位管理内提供三套预设方案：**极简 3 槽（武器/护甲/饰品）/ 标准 7 槽 / 全量 12 槽**，一键切换，已有穿戴物自动退回物品栏（复用 `shrinkSlotCapacity` 的既有语义） |
| 效果三档提示 | 「触发条件不计入总属性」二次确认恒开 | 提示保留（它是防静默失效的保险丝），但新手期的额外说明文案可关（进 `novel_pack_ui`） |
| 熟练度阈值 / 货币进制 / 自动进位 | 已完全自定义 | 不动，仅收纳入口 |
| 模块顺序 / 折叠 | 已支持 | 不动 |

### 5.2 规则设置中心（收纳，不新增）

现状里部位管理、量纲管理、属性模板分散在三个模块头部。建议在面板头部「⚙」下建一个**规则设置中心**抽屉，按 L1/L2 分组收纳这些管理器入口，并作为第 3 步解锁推荐的展示位。**只做收纳与入口重排，管理器本体零改动**。

## 6. 预设模板设计

### 6.1 四套开荒模板

| 模板 | 启用模块 | 预置内容 | 目标画像 |
|---|---|---|---|
| **空白开荒**（新用户默认） | 境界、技能 | 零预填；技能带一条示例效果（暂记模式示范） | "我就想随手记记" |
| **轻量记账** | ＋物品栏、备注 | 物品栏带 3 条示例物品（含数量/稀有度示范） | "我要记装备和宝物" |
| **标准玄幻** | ＋装备栏、人物属性（汇总自动出现） | 精简属性 4 条、标准 7 槽部位、1 件已穿戴示例装备 + 1 条被动 | 大多数玄幻作者的均衡点 |
| **数据流** | 全部 10 模块 | 等价于现状 + 模板行囊的完整范例（复用 `buildTemplatePack` 的覆盖面：三档性质、双槽戒指、熟练度缩放、链式映射） | "我要数值严格自洽" |

### 6.2 套用机制

- **入口**：模块管理「从模板开始」＋ 首次打开行囊时的首屏选择卡（非模态，可跳过）。
- **套用策略：只增不删**。模板只追加缺失的模块与内容；与已有数据冲突（如同名属性）时逐条列出让用户勾选，**绝不静默覆盖**。
- **幂等**：同一模板重复套用不产生重复数据（按模板 id 前缀去重，沿用 `tpl-` 前缀惯例）。
- **实现约束**：模板构建保持 `buildTemplatePack()` 的纯函数纪律（固定 id 前缀、无随机/时间、两次构建逐字段一致），四套模板各自过单测守卫（含"模板不自带映射环"这类既有断言）。

## 7. 预期的用户体验收益

| 维度 | 现状 | 目标 | 衡量方式 |
|---|---|---|---|
| 首次可见功能块 | ~13 块 / 需滚 3+ 屏 | ~3 块 / 1 屏 | 首屏渲染模块数（埋点） |
| 首次有效保存时长 | 用户需先理解属性/装备才敢动手 | 只需会写境界和功法即可完成第一次保存 | 打开面板 → 首次保存的间隔（`novel_usage_log`） |
| 概念首次接触数 | 20+ 领域概念一次性出现 | 按 L0→L2 分批，首次仅 ~5 个 | 文案评审 + 可用性测试 |
| 模块移出率（误用信号） | 无从产生（全开着） | 移出率 < 10%，且移出后 7 天回添率 > 50%（说明"移出"是选择而非放弃） | 埋点 |
| L2 模块最终渗透率 | 100% 展示但未知实际使用 | 属性/映射在 30 天活跃行囊用户中渗透 ≥ 40%（主动开启 = 真需求） | 埋点 |

**定性收益**：默认层"境界 + 功法"与 R25 联动（右侧要素栏设主角 → 行囊境界同步）是行囊最差异化、又零配置成本的能力，把它作为新用户的第一印象，比让 12 个空装备槽先入为主更能建立"这个工具懂网文"的认知。

## 8. 风险与开放问题

| # | 风险 / 问题 | 处置 |
|---|---|---|
| 1 | 「效果暂记」是新的中间态，存在"暂记后忘了补指"的流失点 | 补指引导挂在第 2 步解锁上；功法模块头部对暂记条目计数角标 |
| 2 | 推荐位本身成为新噪声 | 硬约束：同屏 ≤ 1 个、每信号只推荐一次、7 天冷却、可整体关闭（`novel_pack_ui` 加 `guideDismissed`） |
| 3 | 老用户看到新用户极简默认，产生"功能被砍"的误解 | 老角色布局不受影响；CHANGELOG 按 novel 版重构期的 `### Changed` 规范明示"新角色默认布局变化" |
| 4 | 汇总模块去独立开关改动 `PACK_MODULES` 登记面 | 涉及 `PACK_MODULES / MODULE_VIEWS / PACK_ZONE_OF / DEFAULT_LAYOUTS / moduleSummary / pack-dirty SPECS / pack-diff DIFF_GROUPS` 七处联动，需按 1.35.0 模块登记清单逐项过 |
| 5 | 四套模板的内容维护成本 | 模板构建保持纯函数 + 单测守卫；内容增量随版本走，不做用户自定义模板（明确不做，防蔓延） |

**需需求方确认**：
① §3.2 效果暂记模式（方案 A）是否接受；
② §5.1 默认属性组"新建时三选一"是否合适，还是一律空白；
③ §6.1 四套模板的分档与命名。

## 9. 建议落地顺序（供排期参考）

1. **P0 · 默认分层**：两套出厂布局 + 「效果暂记」+ 汇总跟随显隐（改动面最大，收益最直接）。
2. **P0 · 四套模板**：内容构建 + 套用机制（与 P0-1 同批验收「新用户全流程」）。
3. **P1 · 解锁推荐**：占位卡 + 三档信号 + 冷却机制（依赖埋点补 `pack_module_enable` 等事件）。
4. **P1 · 规则设置中心**：纯收纳重排，可独立上线。
