# CheckIn 图形素材主题化规范（Graphic Theming Spec）

> 配套文档：《novel 域视觉改造方案》`docs/novel-visual-polish-plan.md`。
> 本文回答的是那篇方案未覆盖的另一半空白：**图形 / 动画素材（SVG 图标、插画、Lottie 等）如何随四套主题切换**。
> 现状：项目已有一套管用的**图标主题化范式**（`fill="currentColor"` + `SvgIcon` 内联），但**尚未引入任何 Lottie / 动图资源**，也从未给「图形素材如何换肤」立过统一规则。
> 这正是破碎感的隐患点——趁现在零包袱，先立规矩再铺资源。

---

## 0. 一句话原则

> **图形素材的「主题化」只有两条正道：要么让它「跟着文字色走」（currentColor），要么让它「引用语义 token」（CSS 变量）。禁止把色值钉死在资源文件里，也禁止为每个主题复制一份资源。**

---

## 1. 图形素材分类与主题化策略

| 类型 | 示例 | 主题化策略 | 换肤方式 |
|------|------|-----------|---------|
| **A. 单色线形图标** | 行囊 / 小说设定 / 量纲 / 分类 | 跟随文字色 | `fill="currentColor"` + 内联 |
| **B. 多色图标 / 徽标** | 状态图标、打卡点、feature 标识 | 引用语义 token | `fill="var(--app-accent-*)"` |
| **C. 插画 / 空态图 / 引导图** | 空态插画、新手引导 | 双轨：浅/暗各一份，或单份中性 | 见 §3 |
| **D. 动态图形（Lottie / 动图 / 粒子）** | 加载动画、成就动效、空态动态 | 主题化 Lottie（见 §2） | 运行时换色 / 多主题资源 |

**核心铁律（对全部类型适用）：**

1. **能 currentColor 就用 currentColor**——单色图形没有理由写死色值。
2. **多色图形只允许引用 `var(--app-*)` 语义 token**，禁止硬编码 hex。
3. **禁止「一主题一资源」的复制粘贴换肤**（除非是 §3-C 那种必须分浅/暗的位图/插画，且只允许分「浅/暗」两套，不允许分「四套」）。

---

## 2. Lottie 主题化方案（本次重点，定死规则）

Lottie（bodymovin 导出的 `.json` 或 `.lottie`）的痛点在于：**色值写死在 JSON 的 shape fill/stroke 里，切换 `data-theme` 时不会自动变**。业界有四条路，本项目**只允许两条**，其余明确禁用：

### ✅ 方案 1（首选）：Lottie 内用 `currentColor` 占位 + 运行时替换

Lottie JSON 的 shape 里，`fill`/`stroke` 的颜色如果是纯色，可以表达为**占位色**（约定一个哨兵色，如纯黑 `#000000` 或纯白 `#ffffff`），渲染时由一层薄薄的 wrapper 把占位色替换成运行时的 CSS 变量值。

- **机制**：加载 JSON → 遍历 shape 的 `it` 数组 → 把所有 `c.k === [哨兵色]` 的 color 替换为目标色 → 交给播放器。
- **换肤时机**：监听 `data-theme` 变化（或复用 `ThemeProvider` 的变更回调）→ 重新替换 → 重渲染。
- **适用**：单色 / 双色的图形动画（加载圈、进度动效、图标微动效）。

### ✅ 方案 2：多主题资源，但**只分「浅 / 暗」两套**

对确实需要多色、无法用哨兵色干净替换的复杂 Lottie（如插画级动效），允许按**明暗二分**准备两套资源（`xxx.light.json` / `xxx.dark.json`），运行时按当前主题是浅色还是暗色切换。

- **关键约束**：**只分浅/暗两套，不做四套**。aurora / cream / mint 三套浅色主题共用同一份「light」资源；midnight 用「dark」资源。
- **理由**：四套主题的差异在**色相**（紫蓝 / 暖橘 / 薄荷 / 暗），而 Lottie 的插画级配色若强行四套，会产生 4 倍的资源维护成本与体积；浅色三套之间的色相差可以通过「资源里只保留中性 + 主色」来弱化，见 §4。

### ❌ 禁止的方案

- **禁止「四套主题各一份 Lottie」**：体积 4 倍、维护 4 倍、且极易出现「新主题上线漏补」的破碎感。
- **禁止在播放器外层套 `filter: hue-rotate()` 或 `CSS filter` 换肤**：会连背景、阴影、透明度一起被滤镜污染，色相偏移不可控，四主题下必然「发脏」。

## 3. 图形素材的「用色等级」约定（防破碎感的根本）

破碎感不是「颜色不同」，而是「同一类东西在不同地方用了不同策略」。所以给图形素材定三档用色纪律：

### 等级 L1 —— 纯文字色（currentColor）
单色图标、分割线、可交互图标的默认态。
- 规则：`fill/stroke = currentColor`，颜色由外层文字色决定。
- 主题切换：零成本，自动跟随。

### 等级 L2 —— 语义色 token（var(--app-*)）
多色图形里表达「主色 / 成功 / 警告 / 强调 / 弱底」的部分。
- 规则：只允许用现成的 `--app-primary` / `--app-success` / `--app-warning` / `--app-error` / `--app-accent-*` / 以及对应的 `-weak` 弱底。
- 主题切换：CSS 变量自动重映射，零成本。
- **禁止**：引入新的「图形专用」色值 token（例如自造一个 `--app-illust-sky`）——这会破坏语义 token 的单一事实源。图形要用颜色，只能从既有 token 里选。

### 等级 L3 —— 插画级多色（浅/暗二分）
空态插画、引导图、复杂 Lottie 中「需要多色渐变、无法归到单一语义」的部分。
- 规则：只允许「浅色一套 + 暗色一套」两套资源；浅色三主题共用浅色套。
- 配色要求：插画主色调应**尽量中性化 + 只点缀主色**，让它在 aurora / cream / mint 之间不违和（见 §4 调色板）。
- 主题切换：按 `data-theme` 是 light 还是 dark 切换资源。

> **一句话记忆：L1 跟文字、L2 跟语义、L3 跟明暗。除此三种，一律不许。**

## 4. 跨主题配色调色板约束（给设计/素材产出方）

当需要产出 L3（插画/Lottie）资源时，为了避免「同一套资源在紫蓝/暖橘/薄荷三套浅色主题里显得突兀」，素材配色必须遵守：

1. **主色点缀用中性可换色**：插画里唯一该出现高饱和「主题色」的位置，应优先用哨兵色 / 语义占位，运行时替换成 `--app-primary`（这样它在 aurora 是紫蓝、cream 是暖橘、mint 是薄荷，自动协调）。
2. **大面积底色只用中性灰阶**（黑/白/灰），不带冷暖倾向——这样它在三套浅色主题里都不脏。
3. **渐变慎用色相渐变**：优先「同色系明度渐变」或「透明→实色」，避免「红→蓝」这类跨色相渐变在切换主题时打架。
4. **暗色（midnight）资源必须降饱和 + 提亮度**：与主题体系里 `--app-accent-*` 暗色版的降饱和逻辑保持一致（参考 `themes.scss` 中 midnight 块对 accent 的处理）。

## 5. 技术实现要点（Lottie 换肤落地）

### 5.1 依赖选型
- 若只做「图标微动效 / 加载动效」：优先用 **CSS / SVG SMIL 动画** 或 **framer-motion**（项目已有依赖），**不要为几个小动效引入 Lottie 运行时**（lottie-web 约 300KB，lottie-player 也有体积）。
- 只有当出现**设计侧交付的复杂插画级动效**（bodymovin/AE 导出）时，才引入 `lottie-web` 或 `@lottiefiles/lottie-player`。

### 5.2 换肤封装（建议新增一个统一 wrapper）
新增 `src/shared/components/ThemeLottie`（或 `ThemedGraphic`），统一封装：
- 加载 Lottie JSON；
- 若资源是「哨兵色占位」型 → 遍历 shape 替换占位色为运行时 `getComputedStyle` 读到的 `--app-*` 值；
- 若资源是「浅/暗两套」型 → 按当前主题明暗选择资源；
- 监听主题切换 → 触发重新换肤。

**目的**：把「如何换肤」收口到一个组件里，未来所有 Lottie 都从这里走，避免每个使用处各写一套换肤逻辑（那才是破碎感的来源）。

### 5.3 主题变更的监听方式
- 项目主题由 `ThemeProvider` 在 `<html>` 上写 `data-theme`。
- Lottie wrapper 通过 `MutationObserver` 观察 `document.documentElement` 的 `data-theme` 属性，或复用现有主题 store 的订阅。
- 换肤是「替换颜色 → 重渲染」，**不要**在主题切换时重载整个 JSON（会闪帧）。

### 5.4 性能与内存
- Lottie 只在**可见 / 激活**时渲染；隐藏或离屏时 `pause` 或 `destroy`。
- 空态图 / 引导图这类「一次性」动效，播完即停（`autoplay` + 单次 `loop:false`），避免常驻 JS 动画空转（桌面应用里多个 Lottie 常驻循环会拉 CPU）。
- **尊重 `prefers-reduced-motion`**：用户开启「减少动态」时，Lottie 降级为**静态首帧图**（或直接不播、显示静态插画），这是与 motion 改造方案一致的红线。

### 5.5 可访问性
- 纯装饰性 Lottie 加 `aria-hidden`，不给辅助技术朗读。
- 若动效承载语义（如「保存中」「同步中」），必须同时有文字或 `aria-live` 提示，不能只靠动画。

## 6. 配套落点（与现有守卫的衔接）

| 项 | 落点 | 说明 |
|----|------|------|
| 语义色单一事实源 | 复用 `themes.scss` 现有 token | 图形**不新增**色值 token，只从 `--app-primary/--app-accent-*` 等既有 token 选 |
| 图形换肤 wrapper | 新增 `ThemeLottie` / `ThemedGraphic` 组件 | 收口换肤逻辑，未来 Lottie 一律走它 |
| 图标范式守卫 | 可选：新增 lint/测试，扫 `src/assets` 下 svg 是否含硬编码 fill（非 currentColor / 非 var()） | 防止新图标偷偷写死色值 |
| 明暗判断工具 | 复用主题 store 或 `data-theme` 判断 `midnight` 是否为 dark | 供 L3 资源选择 light/dark |

> **说明**：本节是「预设的落点」，实际在第一次引入 Lottie 时再落地代码；本文先把规则与约定钉死，避免「先随便写一个、后来越堆越多」。

## 7. 给未来的「破窗」清单（何时该敲警钟）

出现以下任一情况，说明破碎感已经在积累，必须停下来收敛：

1. 发现某个 SVG/Lottie 里有硬编码 hex 颜色（不是 currentColor / var()）。
2. 发现同一主题色在不同图形里用了**不同色值**（比如两处都用「主色」，一处 `#5b6cf9`、一处 `#5b6cfa`）。
3. 发现 Lottie 资源开始按「四套主题」复制。
4. 发现有人用 `filter: hue-rotate()` 给图形换肤。
5. 发现图形资源引入了既不在 token 里、也没有语义的新颜色。
6. 发现动效没接 `prefers-reduced-motion`、或隐藏状态还在空转。
