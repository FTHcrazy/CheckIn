## [2.36.4] - 2026-11-06

> 2.36.3 的浮层「钉住了」，但钉的过程里还有三处手感问题：开始滚动时抖一下、
> 点「下一个」偶尔原地不动、位置数字偶尔退回只报总数。

### Fixed

- **开始滚动的瞬间浮层会抖一下**：sticky 元素钉住之前还有个**静态位置**，它由
  祖先的内边距决定。纸面层 `.nv-editor__paper` 顶部留着 8px 内边距，卡片起点就
  比钉住位置低 8px —— 滚动到第 8px 之前，卡片一路往上滑（实测 top 18px → 10px），
  肉眼就是「刚滚一下浮层抖了一下」。把这 8px 留白挪进内容层
  （`.cm-content` 的 `padding-top`：8px → 16px），纸面顶部内边距归零，静态位置与
  钉住位置重合。实测（编译真实 SCSS + 无头 Chrome）滚动 0 / 4 / 20 / 300px 时
  卡片 top 恒为 58，右缘也不动。守卫 `find-panel-layout-guard` 增补
  「纸面顶部不许有内边距」。
- **点「下一个」偶现不跳转**：`findNext` 是从**选区末尾**往后找第一处命中。光标
  停在某一处命中**中间**（手点过正文、或从词里拖选）时，它找回来的就是这一处
  本身 —— 屏幕纹丝不动，只能再点一次才走。改为按面板自己的命中表算下标：
  「当前这一处」取光标所在的那一处，跳转取它的下一处，并保证目标与当前选区不同
  （零长度命中 `^` / `a*` 也会沿同一方向再挪一格，不会原地打转）。
- **命中被浮层压住，看着像没跳**：默认的「最小滚动」只要命中在视口矩形内就一像素
  不滚，而视口顶上那一条正好被卡片盖着。新增 `findPanelScroll`（`scrollHandler`）
  接管落点：命中放进「卡片下沿 ~ 视口下沿」这条可见带里才罢休，已经在带里则一像素
  不动（保留就近滚动的手感）。
- **「第几个」偶尔退回只报总数**：原先要求「主选区正好等于某处命中」才报位置，
  手点一下正文就退回「7 处」，看着像位置没更新。改为永远跟着光标报 `n / 总数`：
  光标在命中里报这一处，不在命中里报会跳过去的那一处（VS Code 同款口径）。

## [2.36.3] - 2026-11-06

> 2.36.2 的新查找卡片只浮到一半：它贴着「整篇文档的顶端」，正文一滚就跟着走。

### Fixed

- **查找浮层会被正文滚走**：卡片容器写的是 `position: absolute`，而绝对定位的
  参照物是最近的**定位祖先** —— CodeMirror 给 `.cm-editor` 上了
  `position: relative !important`，于是卡片钉在整篇文档的顶端，而不是编辑区
  视口的顶端。点搜索结果跳转（滚动 `.nv-editor__scroll`）后，浮层随正文一起滚出
  视野（实测滚动 600px，浮层正好上移 600px）。
  改为还原 CodeMirror 的 `position: sticky`（参照「最近的滚动祖先」=
  `.nv-editor__scroll`），再用**零高度容器**（`height: 0` + `overflow: visible`）
  把卡片抽离排版：sticky 仍在普通流里，不收高度会重新把正文顶下去一行。
  横向落点也从「纸面栏右缘」挪到**编辑区视口右缘**（VS Code / Typora 的位置），
  用容器查询单位补回纸面栏居中留出的空白。
  实测（编译真实 SCSS + 无头 Chrome）：滚动 600px 后浮层仍在视口顶部（上移 0），
  700 / 1000 / 1400 三种窗口宽度下与右缘距离一致，且不产生横向滚动条；
  卡片外的空白仍把点击透给正文。守卫 `find-panel-layout-guard` 钉住
  「容器必须 sticky、必须零高度、卡片绝对定位到这条线上」。
- **跳到命中时不再被浮层压住**：`findNext` / `findPrevious` 走的是「最小滚动」，
  往回找时命中正好落在视口顶部，会藏在新浮层底下。补一条 `scrollMargins`
  （只在面板开着时生效，高度按卡片当时量到的报），跳转时视口顶部自动让出这一段。

## [2.36.2] - 2026-11-06

> 两处「用起来别扭」的收口：书架列表视图的「新建作品」条比书卡行矮一截；
> 编辑器里的查找替换还是 CodeMirror 出厂面板（一排英文原生控件、压住正文）。

### Fixed

- **书架列表视图的「新建作品」条比书籍行矮 8px**：网格里每行只有一个元素，
  `align-items: stretch` 没有同伴可拉伸，那一行的 `height: 100%` 退化成内容高度
  （26px 加号 + 一行字）。行高改为只在 `.bs-page__grid--list` 声明一次
  （`--bs-row-height: 68px` = 封面 50 + 内边距 16 + 描边 2），书卡与虚线卡都
  只引用它、不各算一份；守卫 `shelf-card-height-guard` 钉住「只有一个出处」。
  实测（编译真实 SCSS + 无头 Chrome 量几何）三行均为 68.0px。

### Changed

- **编辑器查找替换面板重做**（`EditorPane/find-panel.ts` + 自定义 `createPanel`），
  对齐成熟编辑器（VS Code / Typora）的交互：
  - 面板改成**浮在正文右上角的卡片**，不占排版 —— 开关不再把正文往下压一行；
  - 查找框右侧实时显示「第几个 / 共几处」（无结果显示红字，正则写坏显示
    「表达式无效」），比原来的纯输入框多一层「到底找没找到」的确定感；
  - 三个选项从英文复选框改成 `Aa` / `ab|` / `.*` 三枚互斥开关（中文 tooltip），
    上下箭头与关闭按钮常驻；
  - 替换行默认收起：Ctrl+F 只查、Ctrl+H 连替换一起开（面板开着时是就地切换，
    不会把焦点弹回正文）；Enter 下一个、Shift+Enter 上一个、Esc 关闭；
  - 「替换」按钮补了一次跳转：CodeMirror 的 `replaceNext` 在选区不是命中时
    只做选中、不改正文，照直调会让人觉得按钮失灵。
  - 命中高亮换成主题的琥珀色（原来是出厂黄 / 青），与敏感词的红、标注层的彩色区分。
- 帮助中心的「查找替换」条目按新面板重写（命中计数、三个开关、快捷键）。

## [2.36.1] - 2026-11-06

> 一批界面缺陷与文案校正：书架卡片错位、摘要确认框与生成面板同时出现、
> 排版偏好的分段控件没有铺满、帮助中心若干说明停留在旧行为，以及界面里
> 残留的研发视角标注（需求编号 / IPC / 已上线 等）。

### Fixed

- **书架「新建作品」虚线卡与书卡底边错位**：网格从 `align-items: start` 改为
  拉伸，两类卡都 `height: 100%`（书卡封面 `flex: none`、信息区 `flex: 1` 吸收
  行高余量）。书卡高度随列宽（封面 5:4）变化，虚线卡用的是固定 `min-height`，
  各按各的高度落位就会错开几个像素。
- **生成 AI 摘要时，确认框后面已经浮着「正在生成摘要…」面板**：加载态改到
  「用户按下开始生成」之后才置起（授权弹窗同理，点头后才开面板）；授权失败 /
  章节已被删除 / 换作品等「发不出去」的早退路径会把面板收掉，不再留一个
  永远转圈的浮层。守卫 `useNovelPage-ai-confirm-guard` 同步改为钉「面板不得早于
  确认框出现」，并补了授权路径的反向断言。
- **「排版与偏好」→「字数口径」的切换开关没有铺满剩余宽度**：分段控件补
  `block`（两档等分整列），与同页「序号数字」同一范式。
- **帮助中心与实现不符的说明**：
  - 删除章节 / 卷已改为回收站软删除（30 天可恢复），原文仍写「不可恢复」；
  - 新建作品是两步（书名 → 题材可跳过），原文写「只填一个书名」；
  - 导入支持 TXT / DOCX，顶栏 tooltip 原写「导入 TXT 书籍」；
  - 补上回收站、数据安全（全量备份 / 恢复）、排版与偏好、阅读模式、字数口径、
    敏感词检测；工具卡已是六张（含人物关系网络、架空地图）；
  - 用量与效果页没有「成本估算」，改为实际的调用分布；快捷键补 Ctrl+H、Alt+W。
- **移除界面里的研发视角标注**：工具卡的「已上线」徽标与「规划中 · R27/R28」
  需求编号（改为不显示 / 「还没上线」）、「AC 自动机」改「整本扫描」；诊断页的
  「记录 IPC 调用」「DEBUG 级」（改「记录操作细节」，级别只留中文）；
  「可回传给开发者排查」改「反馈问题时可以一并提供」；三处 AI 面板的
  「没给标准 JSON，已按文本兜底解析」改「返回不太规整，已尽量从文字里提取」；
  行囊「导出草稿 / 保存」的写库措辞、起名收藏「按作品持久化」、「草稿已持久化」、
  标注层「整体降级」都换成用户能懂的说法；要素详情「基础字段」改「基础信息」、
  行囊「量纲 JSON」标题改「导出 / 导入」、敏感词模板标题去掉 JSON 字段名。

## [2.36.0] - 2026-11-06

> 地图 **观感批次 D 收口**：序 5「区块按层级静态衰减」（P2-2，按 §9.5 勘误口径）
> + 序 6「手工落位 AABB 避让」（P2-3）。至此 render-analysis §9.2 的执行序 1~6
> 全部闭环，观感修补三件（P1-4 / P2-2 / P2-3）全部完成。

### Changed

- **区块填充/边界引入静态层次系数 `REGION_LEVEL_FILL_SCALE`**（`regions.ts`，
  按 level 索引 `[1, 0.75, 0.58, 0.45]`，单调递减、与视口无关）。渲染落点
  （主图 `MapCanvas/index.tsx` + 子图 `submapRender.ts`）改走
  `regionFillAlphaOf(level)` / `regionBorderAlphaOf(level)`：
  - **为什么不乘 `levelAlphas`**：那是缩放驱动的 LOD 权重（帽函数 Σα≡1，已写进
    第 i 级容器的 alpha），再乘就是双重衰减 —— 当前活跃层级反而被压淡，
    「线比面还淡」换个方向复发（设计文档原方案已被 §9.5 勘误否决）；
  - **边界与填充共用同一张表**：两者必须同比例衰减，任何一层都不出现
    "线比面还淡"或"面比线还重"；调边界比例改 `REGION_BORDER_ALPHA`，
    调层次落差改这张表，没有第二个旋钮；
  - 只开 1 级时全部落在 level 0 = 系数 1，观感与 2.35.0 前逐字节一致；
    越界 / 非有限 level 回落 1（朝"不衰减"兜底，区块偶尔偏重远比整层消失可恢复）。
- **手工落位 AABB 避让（P2-3）**（`coords.ts` 新增 `ELEMENT_PLACE_PAD = 30` +
  `isCenterCovered`，`useMapEditor.placeSprite` 接线，`index.tsx` 提示）：
  - 拦的是**落位瞬间**"新素材中心落进已有素材命中盒（`hitTestElement` 同构：
    底部锚点 + width×scale）+ 30 世界单位呼吸边"的落点 —— 不拦就会出现
    "聚落被压在山体正中间，看得见但选不到"；
  - **只拦新建，不拦移动**：`moveElementBy` 路径不设防 —— 拦截若作用于拖拽，
    用户就永远无法把压住的素材拖开解围（这是"合法重叠"的逃生门，不是漏洞）；
  - 与命中测试同一条可见性门槛（`ELEMENT_PICK_MIN_WEIGHT`）与尺寸口径
    （`elementSizeFactor`）：看不见的素材不拦路；
  - 被拦时"待放素材"保持选中（不清 `pendingSpriteId`），页面提示
    「落点与已有素材重叠：换个位置，或先把压住的素材拖开」—— 比吞掉点击
    友好，比自动挤开克制；
  - 粘贴 / 复制 / 一键成图不在此列：粘贴落位贴近源素材是既有交互语义，
    生成器有自己的碰撞体系，本条只管"从素材面板点选后落笔"这一条路径。
- **验收**（守卫全绿）：① 系数表单调递减 + 首项 1 + 全落 (0,1] + 覆盖全部层级，
  填充/边界浓度比逐级恒等（`regions.test.ts` 4 条，含源码型守卫钉住两个渲染
  落点都走助手函数）；② 聚落中心被山压住 → 落位被拦、文档零变化；呼吸边外
  正常落位；移动既有素材进另一素材中心不被拦（解围路通）；未登记 spriteId
  不参与避让（`coords.test.ts` 4 条 + `useMapEditor.test.tsx` 4 条）；
  MapWindow 全量回归通过；tsc / eslint 干净。
