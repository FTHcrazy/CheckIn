## [2.40.0] - 2026-11-07

> 区块层第三轮：**砍掉"大陆/洲"、"飞线"退场、一键成图对齐参考面板**。
> 三件事都来自同一轮用户反馈（截图 + 五条要求）。

### Changed

- **层级从四级砍到三级：国家 → 郡 → 城**（`regions.ts` 的 `REGION_LEVELS`，默认数量
  20 / 60 / 160）。用户原话「去掉洲这个概念，感觉跟大陆重合了，最多支持三级」。原因
  不是"层级太多"，是**语义重叠**：一块陆地上"大陆"恒 1 个、下面挂 12 个洲，整图视角
  主导层级是"洲"，而"洲"与"大陆"在画面上都是一大片色块，读到的只是"国内的大区域"。
  `REGION_MAX_LEVELS` 由 `REGION_LEVELS.length` 派生，因此最大层级自动变成 3。
- **`level0` 不再"每岛 1 块"**（`useMapEditor.buildRegions`）：旧口径是"一块陆地恰好
  1 个大陆"，砍掉大陆/洲之后 `level0` 变成**国家**，"每岛 1 个国家"恰恰是错的。改为
  各级统一按 `Math.round(count × 面积份额)` 分摊、`Math.max(1, …)` 兜底。结果：整图
  适配视角（0.8）下主导层级 = **国家，20 块**，与参考实现的 `countries ≤ 20` 同量级。
- **区块描边丢弃"跳线"**（`MapCanvas` + `regions.isRegionJump`）：用户截图里那束
  "近乎平行、扇形散开"的细长直线 = 多边形自交时的长跳接。区块 display 多边形由
  「每条边切一段宿主折线」拼成，Voronoi 单元退化时参数窗口外推会让**首尾跳接**，
  描边把每次跳接画成一根横穿整块地的笔划。实测真实文档 223 块中 **57 个多边形自交**，
  最长边 **106** 世界单位，而该级边长中位数只有 3.4、p99 只有 16。现在按「该级边长方
  中位数 × 10（下限 30）」判跳线并**不描该段**。**为什么不修几何**：重排顶点会破坏
  「父子/兄弟逐点重合」这条铁律，而自交多边形的**填充**在 non-zero 环绕规则下基本自洽，
  只有描边暴露问题 —— 在渲染期过滤是影响面最小的切口。
- **补上"收口弦"修复**（`regions.repairClosingSeam`）：闭合边的首尾跳接会在陆地上留
  一根 10~14 单位的裸弦。沿较短方向绕行、并给长度上限（`BAY_DETOUR_RATIO = 3`，含首尾
  两跳）—— 远岸绕行一定超，真正的湾岸不会，避免重蹈 2.37.0「绕远岸越修越糟」。实测
  越岸点 1562 → 1537、最大越出 6.0 → 4.7、收口弦越岸 49 → 18。
- **一键成图面板对齐逆向目标**（`MapGeneratorModal` + `generator.ts`）：新增三组控制，
  语义与措辞照参考面板（架空大陆自动生成器）：
  · 要素大小 正常 / 较小 / 最小（全局素材倍率 1 / 0.82 / 0.66）；
  · 生成内容 草地 / 森林 / 沙漠 / 浅海 / 两极冰雪 / 城镇 / 遗迹（按地形组勾选，
    默认全开）；
  · 山体、河流 各有 正常 / 多 / 少 / 无（分族密度，倍率 1 / 1.9 / 0.45 / 0）。
  三者都只改**配方**（`terrainMix` 与全局体量倍率）：内容关掉后腾出的份额归一化分给
  其它族，总数仍由丰度档决定 —— 关"两极冰雪"不会让整张图变稀。
- **层级链条提示改为从 schema 取名**（`MapEditorPage` 的状态栏）：原来写死
  「大陆 → 洲 → 国家 → 郡」，砍成三级后会变成"教用户一个不存在的层级"。现在跟着
  `regionSchemaOf(doc)` 走，改层数 / 改名都不会留过时文案。

### 兼容与代价（显式承认）

- **老文档仍是四级**，照常渲染、照常编辑：`REGION_LEVEL_FILL_SCALE` 保留第 4 项
  （缺项会回落 1，反而比郡还重）；`elementSizeFactor` 只认**级别序号**，与档位叫什么
  无关；区块名上限 `REGION_NAME_MAX_LEVEL = 2` 在三级下恰好覆盖（国家/郡/城），在四级
  下仍是"第 3 层（郡）不出名"。
- **一键成图的默认产物与 2.39.0 逐实例相同**：`resolveGeneratorTuning({})` 全开 + 正常，
  要素大小倍率 = 1；新增测试直接比对「不传 tuning」与「显式传缺省 tuning」的 `placements`
  深度相等。老调用方 / 老测试不改也能拿到同一张图。
- **LOD 常量一个没动**（`LOD_BLOCK_PX` / `LOD_BAND_OCTAVES` / `LOD_ZOOM_RANGE`）。
  2.39.0 那条「要压到 ≤20 需改 `LOD_BLOCK_PX`」的结论**被本轮实测推翻**：同屏可辨识
  块数 ≈ 块数 × 视口占比，峰值由**最细一级的数量**封顶，`LOD_BLOCK_PX` 只决定"在哪个
  缩放碰到峰值"。1024² 画布实测（四级 `[1,12,48,160]`）：360 → 峰值 84.6 块、430 → 60、
  500 → 46、650 → 26。真正压数量的是层级结构与 `count`，详见 `regions.ts` 的
  `REGION_LEVELS` 注释。

### 验测

- `regions.test.ts`：默认 schema 改为逐项断言三级（`toHaveLength(3)` / `[0] === 国家` /
  `[2].count === 160`）；「全图视角主导层级」改为**国家 20 块**；「同级颜色多样性」改为
  国家一级 20 块用 ≥8 色；系数表断言放宽为"表长 ≥ `REGION_MAX_LEVELS`"。
- `region-land-audit.test.ts`：守卫 3 整段重写为「level0（国家）铺满陆地、顶层不再是
  '一陆一块'」—— 逐 seed 断言每个岛的 level0 数量 = schema 的国家数，并用 60×60 网格
  采样断言 level0 并集覆盖率 > 0.97。
- `index.coords.test.tsx`：层级指示用例按三级自然缩放 `[0.786, 1.362, 2.223]` / 交界
  `[1.035, 1.740]` 重写（80% 国家 → 97% 交界 → 228% 城 → 47% 下限）；素材层级用例改为
  「城」并在城级因子 1/4 下重算命中区。
- `generator.test.ts` 新增 7 条：缺省 tuning 与不传 tuning 逐实例相等 / 关森林后总数不变
  /「山体：无」「河流：无」该族一条不剩 / 多 vs 少的占比对照 / 全不勾只出陆地 /
  要素大小中位比值 ≈ 0.66 / `resolveTerrainMix` 归一后合计 = 总数。
- `index.generate.test.tsx` 新增 1 条：面板必须含「要素大小 / 生成内容 / 山体 / 河流」
  与七项生成内容（防止控制被删而无人发现）。
- `tsc --noEmit -p tsconfig.app.json` 零错误；`src/windows/MapWindow` 全量 **771 条通过**。

### 已知差距（一键成图 vs 逆向目标）

- **大陆形状**（正常 / 多陆地 / 多海洋 / 南北大陆 / 东西大陆 / 星月 / 狭长 / 盘古 /
  饼干 / 三大洲 / 类地球 / 零散）与**大陆底色**尚未接：前者需要 `land.ts` 的布局参数
  （主轴朝向、岛屿排布、破碎度），后者属渲染层配色，都不在"配方层"。本次只对齐了
  能落在配方与体量上的三组，形状/底色单列 Next。
- 参考面板还有「大陆边线」「道路」「国家」三项：前两项是渲染层能力（海岸烘焙 / 折线层），
  「国家」对应本项目的「划分区块」开关，语义已存在但位置不同。
