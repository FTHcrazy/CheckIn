# Changelog · 2.17.x

## [2.17.2] - 2026-11-01

### Added

- **地图编辑器：区块尺度与素材尺寸的纯函数层**（`src/windows/MapWindow/pages/MapEditorPage/`）。
  - `lod.ts` 新增 `polygonLongEdge`（轴对齐包围盒长边）、`finestBlockLongEdge`（按层级取低分位）、
    `elementSizeFactor`（按层级的世界尺寸乘数）、`zoomLimitsForBlocks`（由实际块大小反推缩放上下限）；
  - `coords.ts` 新增 `wheelZoomFactor`（把 `deltaY` 折算成缩放倍率）；
  - 四个函数都是"参数进、结果出"的纯函数，各自有同目录单测（`lod.test.ts` / 新增 `coords.test.ts`），
    覆盖 `level = null`、层级越界、块长边退化值、画布 0×0、层级数 1/2/4 等边界。
  - 外部输入一律先做有限性校验：`doc.regions` 的多边形顶点、`scales`、`fitScale`、`canvas`、`absMax`
    里混进 `NaN` / `Infinity` / 负数时，`zoomLimitsFor` 会先过滤脏 `scales` 再取首尾，
    `polygonLongEdge` 只按有效顶点计算 —— 避免缩放上限被污染成 `NaN`（表现为滚轮失灵、画面消失）。
  - 影响范围：仅地图窗口，无新依赖、无数据表、无 IPC 通道。

### Changed

- **地图编辑器：缩放上限改为「让最小的郡铺满画布」反推**（`zoomLimitsForBlocks`）。
  - 旧公式是 `最细一级自然缩放 × 4`，实测只有 **8.89 倍**，而让一个郡的长边铺满 900px 短边需要
    10~34 倍 —— 用户"放不到能看清一个郡"的程度。
  - 新上限 = `画布短边 × 1.15 ÷ 最细一级块长边的 p05`，实测 6 个种子（1024×900 画布）为
    **18.6~20.8 倍**；此时 **95%~99% 的郡都能把长边铺满画布短边**。
  - 三条护栏：①不得小于旧公式（层级调成 2 级时 3.97 > 旧 2.44，无回归）；②块长边地板 8 世界单位 +
    上限硬顶 `ZOOM_ABS_MAX = 40`（防退化碎块把上限炸到几百倍）；③画布未量出时退回旧公式 ——
    `width` / `height` **各自**都必须是有限正数，只有一边量出来（如 `Infinity × 900`）也按"没量出来"处理。
  - 下限语义不变（仍与"整图适配"取小者），"适应窗口"照旧能缩回整张图。
- **地图编辑器：素材世界尺寸随归属层级每级减半**（`elementSizeFactor`：level 0/1/2/3 → 1 / 0.5 / 0.25 / 0.125）。
  - 根因：素材基准宽是 80~160，而一个郡的长边只有 70~90 —— 素材比它所属的区块还大；素材与区块同在
    一个容器下同倍缩放，所以**放大多少倍都不改变这个比例**，只放开缩放上限照样塞不进几个要素。
  - 现在「素材宽 : 该级块长边」跨级稳定（山（大）在四级分别是 32% / 27% / 27% / **23%**；郡级的包围盒
    长边 81~88、高 35~37，山（大）郡级只有 20×11.6 —— 横向摆得下 4 个、纵向 3 层，留 20% 边距后约
    3×2 = 6 个不重叠）。
  - `level` 为 `null` 的素材（生成区块之前放置的）乘数恒为 1，**老文档观感逐位不变**；`el.scale` 语义与
    持久化结构未动（乘数只在渲染/命中出口乘一次，不做数据迁移）。
  - 选中框、精灵尺寸、命中测试三处用同一个乘数，命中区与视觉尺寸一致（新增用例：郡级素材点中心能选中、
    点外接矩形外 1px 不能选中）。
- **地图编辑器：滚轮步长随 `deltaY` 缩放**（`coords.wheelZoomFactor`，`WHEEL_NOTCH_PX = 50`，单事件
  最多 6 档、最小 1 档 = 1.1 倍）。上限抬高后从适配缩放滚到上限由 **27 格降到 18 格**；工具栏缩放按钮
  仍是精确 1.1 倍/次，小 `deltaY`（触控板慢推）被钳到 1 档，微调精度不变。
- **已知限制补记**：深缩放（>3 倍）时海面与纸纹会发糊 —— 根因是 1024 源图 + 静态层缓存倍率封顶
  `STATIC_CACHE_MAX_RES = 3`，属源分辨率决定；文档已写进 `docs/prd/prd-map-render/architecture.md` §9
  **L-7**，并明确禁止"把 viewport 加进烘焙依赖"或"抬高缓存上限"这两种反模式。

## [2.17.1] - 2026-10-30

### Fixed

- **「由高到低」的阶梯里，AI 排的等级插到了最上面**：`批量追加` 与 `单条插入` 的落点
  都按 **rank 升序**解释，而界面给的是**显示行序**；`desc`（由高到低）下 `sortLevels`
  会把展示数组反转，两者正好相反 —— 于是「接着末端往下」的等级浮到视觉顶部。
  - 修法：抽出 `toRankIndex(total, displayIndex, carryDir)` 做唯一换算，渲染层
    `insertLevel` 与主进程 `rankAt` 共用；末尾追加在 `desc` 下改为「现有整体上移、
    新条目占住低端」，并**整块反转条目顺序**（传入顺序 = 从现有末端往外的显示顺序）。
  - 空阶梯不反转：那时整块就是全部内容，rank 升序映射到 desc 展示正好「强在上、弱在下」。
  - 本地乐观更新（`useNovelData`）同步同一口径，避免刷新前后跳位。
- **AI 生成的等级说明不落库**：`批量追加` 的 `note` 原先硬编码空串，候选里看得见
  的「这一级能做什么」，加进阶梯后全变成「—」。现在 `note` 随条目一路带到 SQL。
- **AI 生成的等级缺小层**：`批量追加` 的 `subLevels` 原先默认 1，而单条新增是回落到
  **分类默认**（每阶小层数 / 小层命名）。两者现在同口径，AI 加的阶也能自带小层。
  弹窗里补一句提示说清「新阶继承分类的小层设置」。
- **全局设定左栏双击改名后输入框关不掉**：提交路径绕过了 `view.commitRename`
  （唯一会清 `renamingId` 的函数），直接 patch 分类，于是改名态永远留着 —— 输入框
  既不消失，点空白也只会再提交一次。改为提交走 `commitRename`，回车 / 失焦 / Esc
  三条路径现在都能正常退出。
- **一开弹窗窗口就变方**：antd 的 Modal / Drawer 挂 `body` portal，落在 `.window-shell`
  之外，不被圆角裁剪；遮罩是 `inset: 0` 的矩形，把靠透明像素画出来的四角填成实色。
  给 `.ant-modal-mask` / `.ant-drawer-mask` 同一个半径（`--window-shell-radius`，
  跟最大化状态走），全局设定与 novel 窗口同时生效。

### Changed

- 等级 AI 弹窗里「整理整套」的禁用说明改写：落点已修，问题不再是「顺序相反」，
  而是「整套只能接在末尾，顶点会落到最下面」。

## [2.17.0] - 2026-10-30

### Changed

- **一致性校对改在 Web Worker 里跑（R-AI-10a 性能）**：几千章的书不再占着主线程扫。
  - **问题**：原先 `useConsistencyStore` 是「每 8 章一批 + `requestIdleCallback` 让出」，
    让出只是把**一次**大卡顿摊薄成**几千次**小卡顿 —— 扫描期间敲字与输入法仍会掉帧，
    而校对是纯函数（不碰 DOM、不碰 IPC），本来没有任何必须留在主线程的理由。
  - **做法**：新增 `workers/consistency.worker.ts`（`start` 建索引 → 逐批 `chapters` →
    `finish` 出结果）与 `store/consistency-runner.ts`（编排 + 降级）。每批 50 章，
    **收到上一批的 `progress` 才投下一批**，形成背压：worker 没消化完，主线程不会继续灌。
    分批而非一次投全书，是为了让结构化克隆的峰值只有一批（一次投几十 MB 正文等于让
    渲染进程瞬间多背一份内存）。
  - **降级不降级功能**：无 `Worker`（jsdom / 极老内核）、构造抛错（打包后脚本加载失败）、
    线程中途崩溃三种情况，都退回主线程分片并**从头重扫**，只降速度。降级是静默的
    （控制台一条 warn），作者不需要知道校对跑在哪条线程。
  - 取消改为 `terminate()`：取消了就不该在后台继续扫。
  - 与 `import.worker.ts`（书籍导入）同一套形态，未新增任何约定或依赖。

### 说明

- 一致性扫描**结果与判据完全没变**，这次只换了执行线程；`consistency.test.ts` 一行未动。
- 打包已验证：`vite build` 产出独立 `consistency.worker-*.js`（6.2 KB），`app://` 协议
  已带 `standard + secure` 权限，生产环境同样可起 Worker。
- **边界确定**：base 窗口（checkin 域）的业务不接入 AI，R-AI-16b 及「备忘摘要 /
  待办拆解」两个方向不立项，`ai.db` 门控维持 `EDITION !== "lite"`。2.16.0 的
  记账分类建议属纯本地规则（不 import `shared/ai`），不受此边界影响。
